# 数据与模型审计

本次审计使用本地 `envs/mirroropd/bin/python`，设置 `CUDA_VISIBLE_DEVICES=''`，读取用户指定的原始 Parquet 和本地模型目录。逐行使用 student 的原生聊天模板，开启 `add_generation_prompt=True`，统计训练实际输入的 token 长度。完整文件路径、SHA-256、Arrow schema、模型配置和分位数保存在同目录 `data-model-audit.json`。

## 输入规模与长度

| 数据集        | 样本数 | 中位数 |    p90 |    p95 |    p99 | 最大值 |
| ------------- | -----: | -----: | -----: | -----: | -----: | -----: |
| DAPO train    |  17917 |     86 |    157 |    194 |    325 |   1493 |
| MATH-500 test |    500 |     55 | 146.10 | 206.10 | 347.06 |    796 |
| AMC23 test    |     40 |     83 | 139.10 | 194.30 | 219.61 |    220 |
| AIME25 test   |     30 |    103 | 226.20 | 237.35 | 254.23 |    258 |

2048 token 的 prompt 上限覆盖四个文件的全部输入。训练最大输入为 1493 token；将 prompt 上限设成 1024 会过滤或截断部分原始问题。response 长度的选择需要生成实验提供证据，本次输入统计只能确定 prompt 预算。

四个文件都有 `prompt`、`data_source`、`ability`、`reward_model` 和 `extra_info` 五列。每条记录只有一条 user 消息，奖励风格均为 `rule`。DAPO 的 `extra_info.split` 全部为 `train`，其余三个文件全部为 `test`。现有 `training/audit_gsm8k_setting.py` 对单 user 消息和 split 的检查适用于这些输入。

## 模型与模板

DeepSeek-R1-Distill-Qwen-1.5B 与 JustRL-DeepSeek-1.5B 的 token 到 ID 映射完全一致，聊天模板完全一致。二者 tokenizer 的 BOS ID 为 151646，EOS 和 PAD ID 都为 151643。模板在 user 问题后加入 assistant 标记和 `<think>`，训练和独立评测应保留这个原生前缀。

二者均为 Qwen2ForCausalLM，28 层、hidden size 1536、12 个 attention heads、2 个 key/value heads，配置词表为 151936。模型配置中的位置上限为 131072，tokenizer 中的 `model_max_length` 为 16384。两项是不同来源的配置值；本次四卡实验采用不超过 16384 的显式上下文预算即可满足二者。模型配置中的 BOS 为 151643，与 tokenizer 的 BOS 配置不同，因此 prompt 序列应由原生 tokenizer 模板产生。

## 数学奖励兼容性

MD-OPD 的 `opd_mixed_verify.reward_func` 对这四个数学 data source 都路由到 `ttrl_mathverify.reward_func`。有 boxed 答案时，它调用 `ttrl_math.compute_score(fast=False)`；没有 boxed 答案时，它用 Math-Verify 判定输出最后 2000 个字符。结果含 `score`、`format_score`、`acc`、`extracted_gt` 和 `pred`，正确性得分为 0 或 1。

MirrorOPD 的 `training/math_reward.py` 已实现同一调用入口。TA-OPD 后端原有默认数学奖励与上述规则不同，原先还缺少 `ttrl_mathverify.py`、`_timeout.py` 和 `ttrl_math/`。推荐使用 MD-OPD 这些模块的精确副本，并核对 SHA-256；后端已有的 `math_verify.py` 与 MD-OPD 同文件字节完全相同。完整混合领域路由会引入代码、指令遵循和工具调用奖励依赖，本次数学实验直接使用现有 math wrapper 即可。

`_timeout.py` 是必要依赖：它处理奖励在线程中运行时 SIGALRM 无法设置的问题。数学模块还依赖 `latex2sympy2_extended`、`sympy`、`math_verify`、`pylatexenc` 和后端的 `verl.utils.py_functional.timeout_limit`。

## 原始数据的训练测试重叠

按完整 user 消息的精确内容比对，DAPO train 与 MATH-500 test 重叠 2 条，与 AMC23 test 重叠 5 条，与 AIME25 test 重叠 0 条。AMC23 的 5 条重叠占测试集的 12.5%。这些是用户指定数据的原始属性，审计未修改数据。

原始测试集的整体指标仍可用于同一配置下的前后对比，但 AMC23 指标包含训练中可出现的问题。正式报告应披露重叠数量，并另记排除重叠问题后的准确率。重叠样本的训练和测试 index 已写入 JSON，能够复现这个辅助统计。
