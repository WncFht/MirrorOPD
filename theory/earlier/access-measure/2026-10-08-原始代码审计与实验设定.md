# MirrorOPD 原始代码审计与实验设定

## 结论先行

当前实验脚本可以作为动力学原型，但不能把它的四个方法名直接解释成论文算法。`PMD-part` 已经使用了逐 token 的精确 log-partition；`PMD-mean` 和 `BPO` 仍然是从有限条 rollout 估计中心量的版本；`MDPO` 是固定 anchor rollout 上的 KL surrogate 的一阶采样估计。三者都需要在日志中明确“精确目标”与“采样估计”之间的差别。

One-Shot-OPD 的默认算法也不是 BPO 或 PMD。它让当前学生生成响应，再由冻结教师对学生实际采样到的 token 计算

$$
r_t=\log p_T(a_t\mid s_t)-\log p_\mu(a_t\mid s_t),\qquad a_t\sim\mu(\cdot\mid s_t),
$$

并把这个 dense token reward 直接交给 policy-gradient 的 advantage estimator。其 recipe 中 `USE_KL=False`，默认 KL coefficient 为 $0$；因此“teacher log-ratio reward”和“额外的 actor KL regularizer”是两个独立开关。`LOG_PROB_TOP_K` 才会把 sampled-token reward 换成 top-$K$ 候选上的加权信号，`METRIC_TOP_K` 只做观测。

## KL 在四个目标中的位置

### OPD 的 sampled log-ratio

在 One-Shot-OPD 的默认路径中，学生 rollout 的分布是 $\mu$，所以

$$
\mathbb E_{a\sim\mu}[r_t\mid s_t]
=\mathbb E_\mu[\log p_T-\log\mu]
=-\operatorname{KL}(\mu\Vert p_T).
$$

这里每个样本只需要教师和学生在已采样 token 上的 log-prob，不需要枚举词表。它是 $-\operatorname{KL}(\mu\Vert p_T)$ 的 Monte Carlo 样本，而不是整个 categorical KL 的精确值。若要报告 KL，至少应按 token mask 做样本均值，并给出 batch 方差或置信区间。

One-Shot-OPD 的源码把该量写成 `-(student_log_probs - teacher_log_probs)`。这与额外的 `use_kl_loss` 不同；后者调用 `kl_penalty`，在默认 recipe 中关闭。源码还明确说明 top-$K$ 截断后两边的概率质量不再为一，因而 top-$K$ divergence 可能为负，不能把它当成完整 KL。

### PMD-part

若 anchor 是 $\mu$，序列奖励为 $R(y)$，PMD 的精确解是

$$
\pi^+(y)=\frac{\mu(y)\exp(R(y)/\tau)}{Z},\qquad
Z=\mathbb E_{y\sim\mu}[\exp(R(y)/\tau)].
$$

逐步回归使用

$$
c(y)=R(y)-\tau\log Z-\tau\log\frac{\pi_\theta(y)}{\mu(y)}.
$$

因此它需要 $\log Z$。在离散小动作空间中 $Z$ 可以精确求和；语言模型中若奖励是 token-additive 且只考虑一步 token，代码可以对整个 vocabulary 做 `logsumexp`。当前脚本的 `log_partition` 正是

$$
\log Z_t=\operatorname{LSE}_a\big((1-\eta)\log\mu(a\mid s_t)+\eta\log p_T(a\mid s_t)\big),
$$

对应 $R_t=\log p_T-\log\mu$、$\tau=1/\eta$ 的精确 token partition。若改成只在采样 token 上平均，就会退化成 noisy partition estimator，不能再称作 exact PMD-part。

### PMD-mean

PMD-mean 用 anchor 下的软优势中心。用 sampled rollout 时，代码中的

$$
\widehat b=\frac{1}{N}\sum_i r_i
$$

只是 $\mathbb E_\mu[r]$ 的 batch 估计；它不是逐状态 soft value，除非同一个状态有足够多的独立动作样本，并且中心是按状态分组计算。跨 prompt、跨时间位置做一个总均值会把不同状态的 $Z(s)$ 混在一起，因而不能用于 PMD-mean 的逐状态定理。当前脚本保留它作为“sampled PMD-mean baseline”，实验解释必须使用这个名字。

### BPO

BPO 的逐状态目标为

$$
\pi^+(a\mid s)=\frac{\mu(a\mid s)e^{\eta A^\mu(s,a)}}{Z_\mu(s)},
\qquad
Z_\mu(s)=\mathbb E_{a\sim\mu}[e^{\eta A^\mu(s,a)}].
$$

其轨迹残差不是单纯的 $\eta A-\log(\pi/\mu)$，而是

$$
\delta(y)=\eta(R(y)-V^\mu(x))
-\sum_t\left[\log\frac{\pi(a_t\mid s_t)}{\mu(a_t\mid s_t)}
+\operatorname{KL}(\mu(\cdot\mid s_t)\Vert\pi(\cdot\mid s_t))\right].
$$

所以，答案是：**若要实现论文里的 exact BPO，确实需要估计或计算一个 action-independent KL center。** 对每个状态，

$$
\operatorname{KL}(\mu\Vert\pi)
=\mathbb E_{a\sim\mu}\left[\log\frac{\mu(a\mid s)}{\pi(a\mid s)}\right].
$$

词表可枚举时可以精确计算；只拿 rollout token 时只能用 Monte Carlo。当前脚本用整批 token 的 `masked_mean(eta * reward - ratio_log)` 代替这个中心，它既不是逐状态 KL，也没有按 BPO 的轨迹回归残差组织。因此它只能标成 `sampled BPO center`，不能宣称实现了 BPO exact。后续实验应同时保留两个版本：

1. `bpo_exact_vocab`：在每个状态对 vocabulary 计算 $\operatorname{KL}(\mu\Vert\pi_\theta)$，并用逐状态中心构造残差；
2. `bpo_mc`：从 anchor 采样估计该 KL，并记录估计方差、每个状态的样本数和有效 token 数。

## 与 One-Shot-OPD 源码的逐项对照

| 项目           | One-Shot-OPD 原始实现                                              | 当前 MirrorOPD 原型                 | 结论                               |
| -------------- | ------------------------------------------------------------------ | ----------------------------------- | ---------------------------------- |
| rollout        | 学生当前策略生成，通常每个 prompt 一条响应                         | 每个 outer step 固定 anchor 生成    | outer hard sync 是额外设计         |
| teacher signal | 已采样 token 的 $\log p_T-\log p_\mu$                              | 同时保存 anchor/teacher log-prob    | sampled OPD 一致                   |
| extra actor KL | 默认关闭，recipe 中 coefficient $0$                                | 没有单独加 actor KL                 | 不应把 reward 当 regularizer       |
| top-$K$        | 可选；`student_p`/`teacher_p`/`none` 加权                          | 未实现原始 top-$K$ candidate reward | 不能直接比较 top-$K$ 结果          |
| inner epochs   | PPO/actor 更新受 on-policy 约束；top-$K$ reward 模式要求一个 epoch | 任意 inner steps 重用固定 rollout   | 多轮 inner 会产生 off-policy drift |
| teacher        | 一个 frozen teacher，FSDP forward                                  | 一个 frozen HF teacher              | 结构一致，系统规模不同             |
| KL 方向        | sampled reward 的期望为 $-KL(\mu\Vert T)$                          | 诊断 `log_student-log_teacher`      | 需明确写成 forward KL 方向         |

原始 recipe 的默认设置是 batch 64、mini-batch 64、每 prompt 一条响应、训练温度 1、AdamW 学习率 $10^{-6}$、KL coefficient 0。该设定与当前小模型的 $2\times10^{-5}$ 学习率和多轮 inner loop 不可直接类比；当前参数是为了 CPU/GPU 小实验快速观察动力学，而不是复现论文数字。

## 模型选择

实验默认已改为 `EleutherAI/pythia-14m` 学生与 `EleutherAI/pythia-70m-deduped` 教师。选择依据如下：

| 候选              | 优点                                                                 | 问题                                                                                     | 用途                                  |
| ----------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------- |
| Pythia-14M / 70M  | 同一 GPT-NeoX 架构、同一 tokenizer、参数差距足够大；14M 反向更新便宜 | 14M 语言质量弱，teacher signal 可能受分布差影响                                          | 主实验，先验证 outer/inner/eta 动力学 |
| Pythia-31M / 160M | teacher 更强，仍是同一家族                                           | 下载和显存增加；对小规模重复 outer 变慢                                                  | 主实验后的规模对照                    |
| Pythia-70M / 160M | 现有缓存，信号稳定                                                   | 学生已较大，无法回答“小模型快速迭代”问题                                                 | 旧结果的可复核基线                    |
| GPT-2 / SmolLM2   | 社区使用广或有现成 checkpoint                                        | GPT-2 与 SmolLM2 不能跨 tokenizer 配对；SmolLM2-135M/360M 可以同系列配对，作为新架构对照 | 不作为第一阶段                        |

Pythia-14M 和 70M 都使用 GPT-NeoX causal LM 与同一 Pythia tokenizer；因此词表级 `logsumexp`、sampled log-ratio 和 teacher/student token 对齐都可以直接比较。14M/70M 的总权重下载量远小于当前实验使用的 70M/160M，适合在 archbox 上做多 seed、多 eta 和多 inner-budget sweep。31M/160M 作为第二阶段校验 teacher capacity；不能用它替换第一阶段，否则会把“方法效果”和“模型规模效果”混在一起。

## 当前代码的修正边界

当前 `train_opd.py` 做了三件正确的事：每个 outer step 固定 anchor rollout；PMD-part 对 token vocabulary 计算 exact log-partition；MDPO 的 sampled coefficient 在乘以 current student log-prob 前停止梯度。仍需在后续实验中补上：

1. 逐状态的 BPO KL center，而不是全 batch center；
2. PMD-mean 的按状态软值估计，而不是全局均值；
3. inner step 增加 anchor-to-current 的 KL、importance ratio 和 rollout age 诊断；
4. 对 One-Shot-OPD 的 top-$K$ reward 单独实现 candidate-set、weight mode 和 on-policy epoch 限制。

在这些项完成前，`short2` 结果只能作为数值稳定性 smoke test。它们可以说明 corrected PMD-part 没有 NaN、旧版 MDPO 的错误符号已修复，但不能说明四种算法性能排序或收敛定理已经在 LLM 上成立。
