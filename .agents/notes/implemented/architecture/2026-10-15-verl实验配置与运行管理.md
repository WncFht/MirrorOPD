# Agent Note: verl 实验配置与运行管理

Status: implemented

## 问题

MirrorOPD 已有严格 Job、模型与数据 profile、固定后端编译器和完成审计。运行器实际执行 TA-OPD 的固定 verl 分支；它没有替换 verl 的分布式训练循环。此前实验名称、本地目录和 W&B ID 分开指定，suite 的算法共享显示名称；优化器和 checkpoint 的部分原生参数没有公开，重复调参需要手工复制命令。

该问题是[单仓交付与固定后端](2026-10-12-单仓交付与固定后端.md)决策的后续配置管理问题，不取代原有算法、后端和来源边界。目标是在原生执行之上补齐实验表达与执行身份，检验严格 Job 能否承载模型、数据、任务和参数组合，不另建训练框架。

## 调研方法与证据

调研固定六个仓库的源码版本，沿配置读取、调用点、产物和恢复分支核对。没有运行六框架的训练性能对比；模型规模、硬件和任务成绩不作为配置方案的选型依据。Miles 和 slime 的评测解析器另以两数据集执行轻量核验，确认单数据集覆盖优先于公共默认值及 CLI 回退。

TRL 的配置解析、数据组合和训练入口分别由 `trl/scripts/utils.py` 与 `trl/scripts/sft.py` 定义。[^trl] Miles 的 `scripts/run_qwen3_4b.py` 使用 run ID 派生产物目录，`EvalDatasetConfig` 支持逐数据集解码与判分；其 W&B 显式 run ID 使用 `resume=allow`，不代表训练状态自动恢复。[^miles] verl 的 `ppo_trainer.yaml` 组合组件，`ray_trainer.py` 执行模型与 dataloader checkpoint；默认路径派生自 project 和 experiment name。[^verl]

slime 的评测配置与公共 CLI 回退分离；straw 路径在模型和数据保存完成后发布联合提交记录。该能力有特定路径条件，不能泛化为所有后端的精确恢复。[^slime] Rethinking 的发布训练脚本主要使用 SwanLab，关闭训练内周期验证并配独立评测脚本；One-Shot 的公共 shell 配方复用任务默认值，也主要选择 SwanLab 或控制台。它们的底层日志能力不能直接称为发布配方的 W&B 管理方案。[^rethink] [^oneshot]

## 决策

以当前固定 verl 后端为实施基线、官方 verl 为演进参考，One-Shot 只提供任务配方组织经验。保留唯一 Job 默认值、严格校验、源码冻结、逐更新指标及逐题完成审计。任务 profile 组合 recipe、模型、数据和独立评测 profile；显式 CLI 选择覆盖任务默认值。

一个持久化 execution identity 连接本地事件、W&B 名称和 ID；W&B group 表示实验批次。显式输出目录保持可用，省略时自动产生唯一目录。suite 的各算法有独立执行 ID 和可辨名称，批次 group 一致。

原生 Adam/AdamW、betas、eps、constant/cosine 与 warmup 通过类型化字段进入现有 compiler；checkpoint 公开保存内容与最近保留数量。固定 worker 每个 outer 仅推进一次调度器，因此 warmup 与衰减单位明确为 outer。

小型 study 先展开并校验全部组合，再顺序复用现有 runner 与 GPU 预约。记录所有成功、失败和待运行项；失败重试读取冻结的 Job，创建新目录并保留来源。配置身份仍是完整 Job 的内容哈希，不宣称跨机器路径无关。

完整中断恢复继续关闭。新增保存参数不能证明冻结缓存、随机数、数据游标和观测游标可以恢复。后续只从已完成更新且同步完成的 outer 边界验证恢复；独立最终 test、多评测协议和 best checkpoint 是另外的接口变化，不能把公共评测 profile 误称为这些能力。

## 考虑过的替代方案

1. 全面采用 One-Shot 的 shell 配方：接近论文复现入口，但会将现有严格字段、输入身份与源代码冻结退回环境变量和执行顺序约定，且不能替代 MDPO/BPO 的冻结缓存语义。
2. 直接开放所有 Hydra 参数：减少映射代码，但会绕过完整动作采样、teacher/reference、inner 更新和全局归约约束。新增参数仍经 Job 与编译器审核。
3. 引入独立通用调参平台：当前首先缺少的是单任务身份与冻结配置的批量展开，新增服务与第二套生命周期会增加维护成本。搜索算法以后可以作为 Job 生产者接入。

## 验证与边界

实现归属为 [Job 与原生参数](../../../../src/mirroropd/runtime/config.py)、[profile 组合](../../../../src/mirroropd/runtime/profiles.py)、[执行身份](../../../../src/mirroropd/runtime/experiments.py)、[study](../../../../src/mirroropd/runtime/study.py)、[现有控制进程](../../../../src/mirroropd/runtime/control.py)及[后端编译器](../../../../src/mirroropd/integrations/verl/compiler.py)。操作入口见[实验管理](../../../../docs/实验管理.md)。

[实验管理测试](../../../../tests/runtime/test_experiments.py)覆盖 profile 优先级、未知字段、非法组合、重复归一化、执行身份、suite、失败隔离、停止及冻结 Job 重试。[原生配置测试](../../../../tests/integrations/test_experiment_config.py)编译固定后端的真实 YAML，执行 Adam/AdamW 和 cosine 调度，核对 checkpoint 内容与保留策略。[离线 W&B 测试](../../../../tests/runtime/test_offline_tracking.py)用实际 SDK 核对 ID、name、group、完整配置和可迁移文件。[审计测试](../../../../tests/runtime/test_lifecycle.py)验证初始请求与执行身份被修改时拒绝完成。

独立 worktree 的 `make test` 共 387 项通过。四任务、微型模型与 JSONL 输入的 prepare-only 验证全部到达 prepared，完成配置、输入、来源和原生 YAML 链路，不使用 GPU；它不证明新增参数的 GPU 训练行为。详细运行证据保存在忽略的运行目录，不把工作过程另存为成品报告。

## 后果

当前 GPU 0–7 均有在用任务。配置编译和 CPU 控制流验证不能替代新配置的 GPU 容量与执行验证。第三方 checkpoint 的保存、导出和完整续训是不同能力；文档必须分别陈述。
