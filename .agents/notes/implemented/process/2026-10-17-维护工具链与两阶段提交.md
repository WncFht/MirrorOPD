# Agent Note: 维护工具链与两阶段提交

Status: implemented

## 问题

单阶段 pre-commit 在保护未暂存改动期间再格式化 index，会破坏部分暂存补丁的恢复条件。旧检查仅覆盖 Markdown/YAML 文字，未覆盖代码字符串、隐藏脚本与 preview 资源；大型研究证据也使通用临时目录和全仓扫描不适合直接照搬。

## 决策

采用固定 agent-maintenance 来源的 formatter、严格扫描器、语言分派、锁文件、预览资源与行为反例，保留 MirrorOPD 的实验报告规则和增强检查器。既有 .githooks 调用项目 adapter，先运行 manual git-format-staged，再运行 pre-commit 检查；文件大小、暂存伪代码和可信 index 契约继续保留。setup 保存所选维护 Python，commit/push 不依赖用户重新激活环境。

维护 Python 独立于 GPU 环境；项目 Make、hook 和 CI 复用同一检查图，产品数值验证保留独立 lane。理论、第三方、冻结历史和原始证据有明确边界；MPE 载荷在项目内固定来源，用自身生成、QuickJS 与浏览器测试验证。index 快照继续写项目磁盘目录，避免把研究材料放入受限 tmpfs。

## 考虑过的替代方案

- 直接安装上游默认 .git/hooks：会绕开已有 .githooks 的文件限制和伪代码入口，因此复用上游 formatter 实现并适配项目入口。
- 将 formatter 留在普通 pre-commit 阶段：真实部分暂存和失败恢复的契约不成立，必须在框架保护未暂存内容前完成。
- 把完整研究仓库纳入所有文字和格式扫描：会改写冻结证据或第三方载荷；保留原始字节，用链接、哈希和所属专项测试核验。
- 依赖兄弟 agent-maintenance 的运行时文件：独立 checkout 无法工作，因此复制规则、工具与 preview 资源并记录固定来源。

## 后果

维护链能拦住早期文件/批次失败、空扫描、管道失败和暂存错误，真实提交与本地 bare push 反例覆盖环境和恢复语义。浏览器依赖增加本地与 CI 准备成本；preview 测试不代替 VS Code 或 PDF 的视觉验收。远端工作流和分支保护仍由托管平台执行，文件存在不能证明已运行或启用保护。
