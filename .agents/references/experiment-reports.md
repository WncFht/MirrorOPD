# 实验报告维护

适用于有可追溯输入、配置与结果的研究报告。项目的路径、命名与特例由局部 AGENTS 维护；本文件说明写作与更新方法，不授权启动实验或扩大预算。

## 问题、协议与证据

实验前在工作记录中明确命题、成功与否决条件、规模、预算及可变选择。报告按研究问题组织，不以执行日期或会话轮次堆叠。已有同一问题的报告优先更新；新模型、目标、测度或评测协议的实质变化需明确分组，无法共同解释时另写报告。

可引用结果至少绑定以下信息：

- 数据版本、split、题目或轨迹身份、筛选/排除规则、实际样本数及重叠检查范围。
- 模型与 tokenizer 版本或内容哈希、模板、温度、采样、长度及终止/截断规则。
- 目标、估计器、支持集、随机性来源、停止梯度、更新/同步、精度、种子与重复次数。
- 实际执行源码与未提交差异、解析配置、依赖环境、输入输出、命令或固定脚本来源。
- 指标定义、单位、归约权重、统计参照、不确定性单位和图表的数值/生成来源。

来源缺失就写明缺失，不用目录名、commit 或近邻实验补造。旧入口退役时说明固定源码恢复和外部依赖；指向压缩包成员的 URL fragment 只作定位，不当作直接可执行命令。

## 结论与更新

区分观测事实、解释假设与因果证据。标量估计误差不自动决定参数梯度方差，相关 token 数不替代独立种子，测试最高点不替代预定终点。CPU、canary、完整训练和正式 benchmark 分别标注，实验状态使用完成、失败、停止、取消或尚未执行，并给证据截止点。

新增结果写入对应条件与结论。旧解释被推翻时直接改正，保留必要的原判断、纠正依据及负结果；缺少 checkpoint 或逐题输出时不补造事后检验。停止与取消的条件退出执行计划，保留影响结论的覆盖缺口。

合并前列出独有命题、配置、结果、失败原因和复现依赖，逐项确定去向。合并后删除重复定义和被替代文章，修复正文、图表、代码说明及理论来源的入链。来源映射和审阅流水放工作记录，成品只保留理解结论所需的来源关系。

## 正文与产物

正文可采用[实验报告骨架](../templates/experiment-report.md)，按问题调整章节。原始记录、统计和图表进入项目约定的证据目录；大缓存、checkpoint、运行流水和资源交接留运行目录。正文引用证据，不复制每条日志。

核对表格与实际数据、图片路径、计数和单位；存在重算程序时优先复算汇总。展示为当前操作的命令按写法执行；GPU 或外部输入不可用时明确未重跑。链接、格式、测试通过都不等于科学结论成立，不以模式匹配器自动判定文字是否有价值。
