# 基础 on-policy OPD 训练记录

## 决策与算法

按用户要求停止 `gsm8k-smollm2-mdpo-o50-bounded-scratch`，保留原运行目录与日志，不再等待其完成，不将主动停止记作成功退出。后续从原始 SmolLM2-360M-Instruct 学生开始，由 SmolLM2-1.7B-Instruct 教师蒸馏，不继承被停止的 MDPO 参数。

生产分支使用已有 `mirror_opd_onpolicy`。每轮用当前学生生成 B=64 条轨迹，然后对全 batch 做一次全局 token 平均的梯度累积更新，J=1、micro-batch=1，随后同步 rollout 权重。没有 token IS 权重、PPO 包装或额外 KL regularizer；`use_kl_loss=false`、`use_kl_in_reward=false`、`use_task_rewards=false`。KL baseline 采用 K=16 的 Tail-aware 估计，而不是完整词表 KL，必须保留这个近似差异。

每个 sampled token 的奖励与 score surrogate 为

$$
r(s,a)=\log\pi_T(a\mid s)-\log\pi_\theta(a\mid s),\qquad
\ell(s,a)=-\operatorname{sg}\left[r(s,a)+\widehat{D}_{\mathrm{KL}}(\pi_\theta\Vert\pi_T)(s)\right]\log\pi_\theta(a\mid s).
$$

其中 KL baseline 合并学生 Top-16 之外的概率质量为一个尾部类别。这个 action-independent baseline 在精确 on-policy 测度下不改变期望 score 梯度；有限样本方差依赖其估计误差。vLLM 生成与训练前向有小量数值差异，监控 rollout probability difference，不宣称两种后端逐 token 概率严格相等。该分支不使用 eta，配置中的 eta=1 只满足共享接口，不产生正则项。

## 固定设置与检查

入口为 `training/run_gsm8k_opd_onpolicy.sh`，配置为 `training/configs/gsm8k-opd-onpolicy.json`。actor 参数 FP32、前向 BF16、lr=3e-7、clip=2、生成预算 2048、prompt 预算 512、context2560，使用完整 7473 题 GSM8K train 与 1319 题 test。100 outer 对应 100 次 optimizer update；每 5 outer 全量 greedy test，含初始和最终评测。关闭 checkpoint 与生成文本保存。

启动先执行 2 outer canary，只限制 train=128、test=16，其他训练设置相同。canary 退出 0，完成 2 个 inner、2 次同步和初始/最终评测；两次 student center 均 0，teacher center 分别 0.32913、0.32956，pre-clip grad norm 分别 1.53148、1.86183。短样本只验证计算与资源链路，不证明蒸馏性能。

`training/followup_gsm8k_opd.sh` 检查退出码、记录数、J=1、有限指标、同步 center、importance ratio 与测试完整性后自动启动 100 outer。长程运行名为 `gsm8k-smollm2-opd-onpolicy-o100-j1`，systemd unit 为 `mirroropd-gsm8k-opd-o100.service`；已实际启动并通过模板、词表与数据审计。修复后的 W&B logger 已部署，inner 横轴是更新前已完成的 optimizer update 数，step0 的 center 在首个 inner 上传；评测横轴独立为 0、5、10 等。

本次未改生产损失内核，只增加 baseline 设置、入口和顺序启动脚本。已有 OPD 数学/上游接口测试与 shellcheck 通过。当前长程仍在运行，最终效果由完整 test 曲线与退出状态确定。
