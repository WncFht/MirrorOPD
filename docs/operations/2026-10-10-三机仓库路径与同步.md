# 三机仓库路径与同步

## 目录与版本约定

三台机器统一使用 `~/src/MD-OPD` 和 `~/src/mirroropd`。archbox 是后续开发与训练执行位置，源码通过 Git 提交和推送保存，训练日志、checkpoint、环境和大型数据继续留在 archbox，后续实验无需把这些运行产物同步回 Mac。

| 机器    | MD-OPD                          | MirrorOPD                          |
| ------- | ------------------------------- | ---------------------------------- |
| fht-mba | `/Users/fanghaotian/src/MD-OPD` | `/Users/fanghaotian/src/mirroropd` |
| meituan | `/Users/fanghaotian/src/MD-OPD` | `/Users/fanghaotian/src/mirroropd` |
| archbox | `/home/fanghaotian/src/MD-OPD`  | `/home/fanghaotian/src/mirroropd`  |

MirrorOPD 的远端为 `https://github.com/WncFht/MirrorOPD.git`，默认分支为 `main`。本机现有 HTTPS OAuth 凭据没有 workflow 写入范围，首次发布使用同一仓库的 SSH push URL；读取地址保留 HTTPS。MD-OPD 的个人远端为 `git@github.com:WncFht/MD-OPD.git`，当前训练开发分支为 `mopd-m1`，三机目标版本为 `f043a754c3d0992b4cab7dff93c80d362bc1d65a`。`main` 的个人文档提交也已推送至 `a23bd8c6f0b142a8bc2bfbc2ff962474acdc7aae`。

meituan 的原仓库实际位于 `~/Desktop/src/One-Shot-OPD`。此次将该原仓库整体迁至 `~/src/MD-OPD`，在原仓库切换至最新 `mopd-m1`；没有留下另一个 Oneshotopd 工作区。`origin` 指向个人 MD-OPD，原始 Thinking-Space 远端保留为 `upstream`。

## 保留的机器本地状态

meituan 的原有两份修改笔记和一份新增笔记保持原样：`docs/2026-09-13-implemented-opd-dynamics-derivation.md`、`docs/2026-09-13-opd-essence-literature-and-derivations.md`、`docs/2026-09-13-opd-unified-view.md`。它们尚未提交，三机相同的是 Git 版本，不能把三台工作区描述为字节完全相同。

archbox 的 `~/src/mirroropd` 原来是无 `.git` 的文件副本，同时用于正在运行的 OPD 实验。此次在相同目录接入正式 Git 历史，保持 `runs/`、数据、环境和本地额外文件。同步前确认 `src/` 中发布版本的文件与现有对应文件内容一致；覆盖更新的其他文件备份在 `~/.cache/mirroropd-sync-backup-20261010`。既有未跟踪的旧布局文件仍保留，应在当前训练结束后核对调用者再决定归档范围。

本机 MirrorOPD 的书稿及实验笔记存在其他会话正在进行的修订。本次发布保留这些未完成工作，仅提交补丁恢复修正、路径说明和代码审查。发布提交与本机整个工作区快照具有不同范围。

## archbox 的运行边界

`~/src/mirroropd` 是第一方源码和实验入口；`~/src/mirroropd-taopd` 继续保存已经验证的 TA-OPD/verl 训练环境及运行依赖。当前 Mirror launcher 默认使用后者的 `.venv` 和 `verl`，通过 `PYTHONPATH=~/src/mirroropd/src:~/src/mirroropd-taopd/verl` 加载生产核心。这个目录是训练后端，不能因统一两个仓库名字而移走正在使用的环境。

`~/src/MD-OPD` 已同步训练开发代码，并存在可导入 torch、Ray、Transformers、vLLM、Hydra 和 OmegaConf 的 `.venv`。本次没有启动新的 GPU 任务。仓库同步与 Mirror 算法接入是两个阶段：MD-OPD 尚未实现 `mirror_*` modes，具体方案见 [接入代码审查](2026-10-10-MirrorOPD接入MD-OPD代码审查.md)。

后续在 archbox 直接执行以下版本检查，再选择相应入口。

```bash
cd ~/src/mirroropd
git status --short
git rev-parse HEAD
git remote -v

cd ~/src/MD-OPD
git status --short
git branch --show-current
git rev-parse HEAD
```

MirrorOPD 已有训练入口仍为 `training/run_configured_training.sh` 及 GSM8K/Pythia wrapper；MD-OPD 已有入口为 `recipe/opd.sh`、`recipe/mopd*.sh`。模型、数据、GPU 数量和 batch 参数按真实环境配置，不能将集群默认配置直接当作 archbox 单张 12 GB GPU 的可运行配置。

## 可恢复 checkout

TA-OPD 集成补丁现已完整包含相对 manifest 原始基线的训练接线。发布验证在干净的 `62669afb5101bfdf57dc5ddf81e78f000c5ce2fc` 上执行 `git apply --check`、实际重放，然后将 `verl/verl` 与本机既有实现逐文件比较，结果一致。新 checkout 的 `make upstream` 因此无需依赖本机不可获取的中间集成提交。

本次验证包括隔离工作区的 `make check`、补丁重放、三组 CPU Mirror 语义与链路测试、三机 Git 版本和 archbox 核心导入。没有将这些检查记为新的 GPU canary 或正式 benchmark。
