## 原提案与核验记录

### 决策与现有方案的关系

保留 MirrorOPD 作为唯一产品仓库。将完整数据准备、数学判分、评测和训练编排收进本仓库，维护一份固定版本的生产 backend。算法继续在第一方纯 tensor 内核中实现，分布式执行仍复用 verl。MD-OPD、TA-OPD、ResOPD、LSPD、KLPO 等保留为来源、兼容性基线和研究对照，按能力迁入经过审阅的组件。

本决策延续[六仓库统一架构](2026-10-10-六仓库统一OPD架构方案.md)的核心：概率角色、采样测度、支持集、梯度程序和 reduction 分开。它调整此前[MD-OPD 接入方案](2026-10-10-OPD统一抽象与MD-OPD接入方案.md)的双仓库交付方式。旧方案让 MD-OPD 承载 backend 与编排；单仓自包含要求将这些交付职责纳入 MirrorOPD，并不要求重写 Ray/FSDP/vLLM。

迁往 MD-OPD 重写会将已有 cache/loss、纯 CPU oracle、真实 outer-inner 验证、指标归约、逐题评测和图表证据再次接线。当前缺少的是独立交付和语义接口，不是一个新的 trainer。采用已有 MirrorOPD 生产链路作为起点，能先验证行为不变，再扩展算法。

本轮属于架构与数学核验：阅读了当前两仓源码及[上游 OPD/KLPO 审阅](2026-10-11-上游OPD与KLPO代码审阅.md)，运行了三动作 FP64 梯度枚举，修正了指标规范中对 MD-OPD 候选策略的错误状态描述。没有迁入 backend、修改训练 loss 或启动 GPU 训练。

### 自包含的具体边界

源码自包含要求一次普通 Git checkout 就具备第一方 pipeline 和选定 backend 源码；正常声明的软件依赖通过环境安装，模型与原始数据通过版本化下载或离线导入获得。PyTorch、vLLM、Ray 和 datasets 属于软件依赖，不必把它们的源码复制到项目里。

当前需要消除的邻仓约定如下。

| 实际入口                           | 当前依赖                                                     | 统一后的职责                                  |
| ---------------------------------- | ------------------------------------------------------------ | --------------------------------------------- |
| `training/prepare_math_backend.py` | 读取相邻 MD-OPD 的判分文件，再复制进 backend                 | 判分器在第一方可独立导入，verl 使用薄 wrapper |
| `training/math_reward.py`          | 从 verl namespace 导入数学判分                               | 调用第一方 evaluation API                     |
| `training/run_dapo_math_4gpu.sh`   | 父目录 `.bashrc`、`fht-mirror`、MD-OPD parquet、固定模型路径 | 一份显式配置驱动的公开入口                    |
| `upstream/TA-OPD`                  | 忽略 checkout 或本机软链，启动前应用补丁                     | 固定生产 backend 纳入源码交付                 |
| `pyproject.toml`                   | 没有训练 extras 和完整环境锁                                 | CPU / GPU backend / analysis 依赖分开锁定     |

`training/prepare_dapo_math.py` 已有固定源 revision 的 DAPO/MATH-500 构建，不需要从零实现。它目前明确不准备 AMC/AIME，且 parquet schema 与旧 MD-OPD 输入仍须逐字段核对。MD-OPD `data/prep/` 有 AMC23/AIME25 builder、明确 PyArrow schema 和 DAPO 去重素材；部分下载使用 `Revision=master`，缓存只检查非空，迁入后必须补 source revision 与 checksum。

数据准备应支持 `download` 和 `import-local` 两条输入路线，随后共用校验和转换。manifest 记录源版本、原始 SHA-256、转换版本、schema、题目 UID、行顺序、去重规则、训练测试重叠与输出 hash。分别维护“历史原始数据复现”和“去重后的新实验”，不通过改同一个默认路径静默替换训练集。

模型准备记录模型与 tokenizer revision、权重文件 hash、模板、EOS 和 action-space 变换。网络下载后的固定版本与已有本地模型导入都输出相同 manifest。单仓 pipeline 的目标是 `prepare → preflight → train → evaluate → analyze`，各阶段可以单独重跑，依赖和产物通过 manifest 连接。

### backend 与 patch 的维护方式

当前 TA-OPD 接入补丁有 1490 行，涉及 18 个框架文件，覆盖 trainer、agent loop、tracking、FSDP engine、worker、vLLM、padding 和评测配置。它已经是完整框架集成变更，继续把所有新能力追加在一个手工 diff 中，会让日常代码审阅、历史定位和升级冲突处理变得更难。

推荐将“固定 TA-OPD 基线加当前已核验补丁”的确切源码树放入 `third_party/verl/`，用 Git subtree 或明确来源的 vendored snapshot 管理。整个生产源码树正常入库；后续框架修改是按职责划分的普通提交。模型和数据仍放忽略的资源目录，backend 源码与其许可证属于交付内容。

submodule 只记录指针，需要额外获取源码；manifest 加 clone 也要求额外下载。它们可以做到自动准备，但无法满足严格的单 checkout 源码自包含。当前 patch 应保留为历史基线重放和升级差异材料，退出新版本日常启动的必经路径。

第一份受控 backend 应继承当前已验证执行链。官方 verl 的升级安排为另一项迁移：旧 backend 做兼容性参照，新 adapter 逐项对照 loss、梯度、mask、评分、同步与评测。算法统一、backend 升级、数据去重和评测协议改变分别进行，否则训练结果变化无法归因。

保留 MD-OPD 的多教师路由、回放和 EOS class 等实现作为后续能力来源。迁入前逐项验证其合同，避免整体复制第二套 trainer。当前 `scripts/bootstrap-upstream.sh` 对新 clone checkout 固定 revision，但对已有 checkout 主要检查 origin 和补丁可应用性；准备成功并不能独自证明已有 backend 的 HEAD 正确。过渡期应校验实际 HEAD、patch hash 与源树 hash。

迁入源码时保存原许可证、版权头和来源 commit，建立 third-party notices。当前 MirrorOPD 没有跟踪的 LICENSE/NOTICE 文件，这部分应纳入正式交付。传统 MDPO 继续采用论文数学和独立实现，不复制没有明确许可的源码。

### 统一抽象的最小组成

一次算法更新包含五个问题：优化什么目标、在哪个测度积分、拿到哪些概率证据、用什么程序生成梯度、怎样归约和记录。每个算法是一个具有这些完整声明的 recipe，不是给统一大函数填一组任意布尔开关。

沿用现有 `training/` 与 `integrations/verl/`，先增加 contracts、recipes、requirements 三类模块。使用小型不可变 dataclass、明确 tensor shape 和少量 registry；先不创建通用 trainer 基类或动态插件系统。真正复用后再拆目录。

| 对象                | 必须表达的信息                                                     | 禁止隐含的假设                                    |
| ------------------- | ------------------------------------------------------------------ | ------------------------------------------------- |
| `SequenceLayout`    | prediction position、action IDs、mask、序列分组和有效长度          | token 与 logit 下标默认相同                       |
| `DistributionSpec`  | student / behavior / anchor / teacher 身份、版本、温度、截断与 EOS | behavior、anchor、PPO old policy 永远相同         |
| `CandidateSet`      | 真实 IDs、valid mask、来源 membership、冻结边界与 hash             | Top-K rank 就是 token 身份                        |
| `FrozenEvidence`    | sampled LP、指定 IDs 的概率、固定 mass、teacher target             | 持久化缓存可以保存跨 update 的 live graph         |
| `LiveStudentScores` | 当前 action / head / tail / full expectation 的可微结果            | 已 detach 的日志值可以用于 live-center regression |
| `ObjectivePlan`     | objective、测度、gradient program、近似性质、reduction 和数值策略  | estimator 名字决定目标及梯度                      |
| `ScoreRequest`      | sampled / 指定 IDs / native Top-J / full reduction 等能力需求      | 每个算法都需要全部 logits 和全部诊断              |
| `UpdateWindowState` | outer、实际更新计数、冻结版本、同步和恢复边界                      | `outer × epochs` 等于 optimizer update 数         |

`FrozenEvidence` 与 `LiveStudentScores` 是评分合同中两个不同生命周期的部分。框架 TensorDict、Ray remote handle 和 worker 不进入数学公共 API；adapter 负责其运输和执行。

recipe 返回 `backward_surrogate`、明确命名的 objective/value 诊断、充分统计量及近似状态。返回结构允许 deterministic head 项、stochastic residual 项和 live-center correction，不能强制每个算法只有一个 sampled coefficient。

planner 从 recipe 和诊断配置编译请求，再检查 backend 能力。例如 MDPO 的 sampled gradient 只需 sampled student/anchor/teacher LP，head-tail center 仅是诊断；BPO 需要每 inner 的 student center；精确 live-center regression 需要 actor 计算图中的 anchor expectation；PMD-Part 需要冻结的 log-partition。没有任意 IDs scoring 的 teacher backend 不能静默把请求替换成 teacher-own Top-K。

#### 可组合轴与有效预设

| 配置轴           | 例子                                                                        | 数学职责               |
| ---------------- | --------------------------------------------------------------------------- | ---------------------- |
| objective        | reverse KL、Mirror-Mean、BPO、MDPO、response-PMD                            | 定义总体优化对象       |
| target/proposal  | current student、anchor、真实 behavior                                      | 定义积分与采样修正     |
| support selector | anchor head、teacher head、union、intersection                              | 定义候选身份           |
| integration      | full、raw head、conditional、head-tail、head+MC residual                    | 定义积分或改变后的目标 |
| gradient program | regression autograd、score surrogate、deterministic autograd、PPO surrogate | 定义计算图与停止梯度   |
| center/control   | exact、coarse、独立 MC、leave-one-out                                       | 定义近似误差与方差控制 |
| numerical policy | mass floor、ratio cap、log-ratio clip                                       | 定义实际数值与偏差     |
| reduction        | global token mean、sequence mean、response token sum                        | 定义样本权重           |

这些轴服务于消融，但不能开放所有笛卡尔积。先维护有限的有效 recipes，编译时拒绝不成立的组合。full vocabulary、raw partial、conditional 和 head-tail 都能输出一个标量，却有不同目标。直接把 prefix 上的 deterministic KL 标量 detach 后当同一个 sampled token 的 advantage，也不能继承原 KL 的 direct gradient。

建议配置形式如下；这是目标接口示例，当前 launcher 尚未支持。

```yaml
recipe: bpo
action_granularity: token
target_measure: anchor
proposal: anchor
gradient_program: score_surrogate
center:
    resolution: head_tail
    selector: anchor_top_j
    j: 16
reduction: global_token_mean
diagnostics:
    overlap_j: 32
    objective_probe: fixed_prefix
backend: pinned_verl_fsdp
```

切换 `gradient_program` 前，应确认新程序对该中心定义是否等价。把 `center.resolution` 从 exact 改为 head-tail 是算法近似消融；把 `diagnostics.overlap_j` 从 16 改为 32 只改变观察成本。这两个实验应明确分开。

### 统一 W&B 与数学指标

#### 当前实现

`training/metrics.py` 收集有效 token 的 count、sum、sum-square、min/max，跨 micro-batch 和 DP 合并后产生 mean/std/RMS 与 ESS。`training/tracking.py` 是展示适配层：本地保留原始字段，W&B 将其分类，并为 inner、rollout、aggregate 和 quality 绑定不同轴，显式设置 `step_sync=False`。

首 inner 的 `rollout_*` 与整轮汇总的 `aggregate_*` 已分开，避免同名字段在 outer=0 混入不同状态。当前 inner 轴由完整 rank-zero 更新记录的序号生成，比 `outer × epochs` 稳健；跨进程恢复仍缺持久化 optimizer 计数和上传去重合同。

首 inner snapshot 只覆盖第一个 optimizer mini-batch。当前正式数学设置中 rollout batch=mini-batch=64，因而覆盖本轮全部样本；更改 batch 划分后不能继续默认代表整个 rollout。inner 概率量来自更新前 forward，梯度范数来自该 backward 的裁剪前状态，应在事件字段中分别记录。

`teacher_center` 的数学含义随方法改变：Mirror 使用 anchor–teacher center，OPD 分支使用 current student–teacher baseline。`token_advantage` 又直接复制 `score_coefficient`。统一后按公式和方向命名，不能只对旧名称换一个更好看的 W&B 前缀。

#### 目标日志合同

算法和 scorer 返回普通 tensor 诊断与充分统计量；统一 reporter 产生本地 canonical event，再由 JSONL、W&B 与绘图 consumer 读取。算法代码不调用 W&B。

每条事件有 schema version、run/event ID、event type、outer/window、完成 optimizer updates、模型版本、batch/prefix 身份、measurement、单调运行时、评测 protocol ID。上传游标和去重身份持久化；W&B `_step` 只表示写入顺序。

推荐事件为初始化评测、outer-start probe、update-pre、update-post、outer-end、evaluation 和 resource-stage。post 概率量必须真正重新 forward；没有测到的量保留缺失状态，不能复制 pre 或填零。

指标 registry 记录公式、KL 方向、测度、支持集、exact/estimated/coarsened 状态、单位、统计分母和归约。显示名称可以变化，canonical 数学字段保持稳定。示例为：

```text
kl/anchor_to_student/head_tail/mean
kl/anchor_to_teacher/head_tail/mean
kl/student_to_teacher/full/mean
objective/bpo/residual_square/mean
gradient/score_coefficient/rms
optimization/backward_surrogate/mean
offpolicy/diagnostic_student_over_anchor/ess_fraction
support/student_teacher/intersection_fraction/mean
support/student_teacher/jaccard_macro
support/student_teacher/jaccard_pooled
```

这里的 objective 与 backward surrogate 分开。实际最小化程序为 $\operatorname{sg}(c)\log p$ 时，$c$ 是梯度下降系数；若展示上升形式的系数则使用 $-c$，并声明是否已经包含重要性权重。原始 reward、未加权 residual、proposal ratio 和最终加权系数各自记录。

资源轴分 end-to-end runtime、各训练阶段累计时间、evaluation 时间和准备时间。当前 `training_seconds` 累积 `timing_s/step`，不能解释为完整 pipeline 成本；应核对 timer 范围后迁移字段。设备级 `gpu.csv` 占用与 worker 的 allocated/reserved 也分开，增加 CPU/PSS、scoring payload 和同步峰值。

on-policy/off-policy 的 quality 同时支持已完成 outer、实际 optimizer updates、新生成 response tokens 和运行时间四种横轴。更新前概率指标绑定更新前状态，初始化 quality 的 updates=0。共同固定 prefix probe 的三对概率在相同位置比较；不同算法各自新生成的 prefix 则承认其样本测度不同。

### Top-J overlap 与优化支持集

用书稿记号 $\pi_{k,n}$、$\pi_k$、$\pi_T$ 表示当前 student、冻结 anchor 和 teacher。对同一个 prefix $s$，定义原生集合：

$$
H^S_{k,n}(s)=\operatorname{TopJ}(\pi_{k,n}),\qquad H^A_k(s)=\operatorname{TopJ}(\pi_k),\qquad H^T(s)=\operatorname{TopJ}(\pi_T).
$$

当前 `cache.py` 冻结 anchor 和 teacher 原生 IDs，`losses.py` 每 inner 重算 student 原生 IDs，`support.py` 比较三对集合。teacher 在 anchor IDs 上的概率和 teacher 原生 IDs 是不同字段。旧 `support_overlap` 对应 student-anchor，首 inner 时 student=anchor，所以 OPD 的旧曲线为 1 符合定义。

对等大小 J 的两个集合：

$$
I=\lvert H^L\cap H^R\rvert,\qquad C=\lvert H^L\cup H^R\rvert=2J-I,\qquad O=I/J,\qquad Jac=I/C.
$$

全局应同时保存 $M^{-1}\sum_i Jac_i$ 和 $\sum_iI_i/\sum_iC_i$，分别是 macro 和 pooled Jaccard。J=4，一个 prefix 完全相同、一个完全不重叠时，二者为 1/2 和 1/3。当前 J=0 的零比例是诊断关闭约定，展示为 disabled。未来不同两侧 J 还需保存各集合大小和双向 containment。

诊断 Top-J 与训练支持集的 K 应分开。当前诊断 J 仍取 `anchor_ids.shape[-1]`，实际上与训练缓存 K 绑定；独立 `overlap_j` 是下一步需求，并非已上线开关。

union/intersection 是训练 candidate selector 时，必须真的构建相应动作集合、去重并 transport IDs。当前 MD-OPD 的 only_tch 和 union 没有完整运输 teacher-only 候选，union mask 被截回 student 轴；union-intersection 也只保留 student-only 一侧。正确统一实现应对真实并集中的每个 ID 查询 current/behavior/teacher 概率，冻结需要重用的 ID 身份。归一化权重、raw mass 与 head-tail partition 分别声明。

### regression 与 policy gradient 的数学边界

#### 共同符号与当前生产形式

固定 $s\sim d_k$，使用旧书稿符号：

$$
U_{k,n}=\log\frac{\pi_{k,n}}{\pi_k},\quad r_k=\log\frac{\pi_T}{\pi_k},\quad \psi_{k,n}=\nabla_\theta\log\pi_{k,n},\quad \omega_{k,n}=e^{U_{k,n}},
$$

$$
\mathcal K^S_{k,n}=\operatorname{KL}(\pi_k\Vert\pi_{k,n}),\qquad \mathcal K^T_k=\operatorname{KL}(\pi_k\Vert\pi_T).
$$

完整期望下 $\mathbb E_{\pi_k}U=-\mathcal K^S$、$\mathbb E_{\pi_k}r=-\mathcal K^T$。当前生产缓存将两种 center 替换成 anchor head 加 aggregate tail 的 coarsened KL，公式中必须用帽子或 explicit resolution 区分。

当前 `training/losses.py` 统一返回 $\operatorname{sg}(c)\log\pi_{k,n}(a\mid s)$。它是 score surrogate，通过自动微分得到 $c\psi$；并非 PPO clipped loss，也不是以该 scalar 的数值定义真实 objective。

#### PMD-Mean 与 PMD-Part：逐样本梯度别名

Mean residual 定义为

$$
R^{\mathrm{Mean}}=U-\eta(r+\mathcal K^T),\qquad \ell_{\mathrm{reg}}=\tfrac12(R^{\mathrm{Mean}})^2.
$$

teacher target 在 outer 内冻结，因此

$$
\nabla R^{\mathrm{Mean}}=\psi,\qquad \nabla\ell_{\mathrm{reg}}=R^{\mathrm{Mean}}\psi=\nabla\left[\operatorname{sg}(R^{\mathrm{Mean}})\log\pi_{k,n}\right].
$$

相同 sampled actions、mask、reduction、冻结 target 和数值策略下，两种程序逐样本梯度相同。把 teacher center 换成同一个冻结近似也不破坏此计算图恒等式，只是改变共同 target。它适合作为统一实现的强回归用例；单独比较两者训练质量没有独立算法变量。

Part 将 residual 换成 $U-\eta r+\log Z_k$，只要 $\log Z_k$ 在 outer 冻结，同样成立。精确 $Z_k$ 与 head-tail/MC 近似是另外的消融。$\widehat Z$ 无偏不推出 $\log\widehat Z$ 无偏。

#### BPO：live-center 与 stopped-score 需要条件等价

定义

$$
R^{\mathrm{BPO}}=U+\mathcal K^S-\eta(r+\mathcal K^T),\qquad \bar\psi=\mathbb E_{\pi_k}\psi.
$$

精确 student center 保留反传，故

$$
\nabla\mathcal K^S=-\bar\psi,\qquad \nabla\frac{R^2}{2\eta}=\frac R\eta(\psi-\bar\psi).
$$

当前 stopped-score 单样本梯度为 $R\psi/\eta$。两者之差为

$$
g_{\mathrm{reg}}-g_{\mathrm{score}}=-\frac R\eta\bar\psi.
$$

精确 center 和 proposal=anchor 下 $\mathbb E_{\pi_k}R=0$，因此两者总体梯度相同。分类 logits 中 $\psi(a)=e_a-p$、$\bar\psi=q-p$，差值为 $R(p-q)/\eta$；单样本差异和有限 batch 方差仍存在。

近似中心设 $\widehat R=R+\delta_s-\eta\delta_t$，则

$$
\mathbb E_{\pi_k}\widehat R=\delta_s-\eta\delta_t.
$$

它通常不为零。若直接对 coarsened student KL 的平方 residual 自动微分，该 center 的导数也不等于 $-\bar\psi$。因此当前 head-tail BPO 的 live-center regression 与 stopped-score 是不同 recipe，不能用一个实现开关宣称等价。冻结 student center 后再做平方，则是另一个 stopped-center 程序，其梯度可以与 score surrogate 逐样本一致。

MD-OPD 的 `mopd_resid` 有 live anchor expectation，使用精确中心且额外 floor 权重为零时可以与 BPO 的上述总体关系对照；默认混合测度、近似 center 和 floor 另行审查。LSPD 的未中心化 log-prob regression 也应保留自己的目标名称。

#### MDPO：当前测度目标与 action IS

MDPO 的原始目标是

$$
\mathcal L_{\mathrm{MDPO}}=\mathbb E_{d_k,\pi_{k,n}}[U/\eta-r].
$$

同时微分概率和被积函数，得到

$$
\nabla\mathcal L=\mathbb E_{d_k,\pi_{k,n}}[((U+1)/\eta-r)\psi]=\mathbb E_{d_k,\pi_{k,n}}[(U/\eta-r)\psi].
$$

最后一步使用 current measure 的零均值 score。若动作来自冻结 anchor，正确 score 系数为

$$
c=\operatorname{sg}[\omega(U/\eta-r)].
$$

固定 prefix 的 full-vocabulary 原始目标 autograd 与正确 action-IS score 在总体上等价，单样本可以因所去掉的常数项不同。MDPO 没有通过随意平方 $U/\eta-r$ 自动获得同一个 regression objective。比较原始目标与采样梯度时，名称应是 deterministic objective versus stochastic gradient estimator。

如需为 MDPO 实现一个逐样本同梯度的平方程序，可以构造

$$
\ell_{\mathrm{local}}=\frac\eta2\operatorname{sg}(\omega)(U/\eta-r)^2,\qquad \nabla\ell_{\mathrm{local}}=\operatorname{sg}[\omega(U/\eta-r)]\psi.
$$

它命名为 weighted-square surrogate；冻结权重随着当前 student 重算，其 forward value 不是原 MDPO objective。它可以检验实现一致性，不能据两个不同显示值判断哪个更快收敛。

动作 IS 修正的是同一固定 prefix 上的 action 积分，不把 $d_k$ 换成当前 student 的轨迹访问测度。response-level PMD 和 KLPO sequence route 需要独立的轨迹分组、测度和归约，不能接到 token recipe 后只改 tensor 维度。

#### scalar KL estimator 的同值与不同梯度

令 $x=\log p(a)-\log t(a)$，已经采样的动作索引固定。直接回传三种标量得到

$$
\nabla k_1=\psi,\qquad \nabla k_2=x\psi,\qquad \nabla k_3=(1-t(a)/p(a))\psi,
$$

其中 $k_1=x$、$k_2=x^2/2$、$k_3=e^{-x}+x-1$。在 action proposal=current p 下，分别求期望为

$$
\mathbb E_p\nabla k_1=0,\qquad \mathbb E_p\nabla k_2=\nabla\operatorname{KL}(p\Vert t),\qquad \mathbb E_p\nabla k_3=\nabla\operatorname{KL}(t\Vert p).
$$

所以 value estimator 与 backward estimator 分开配置。MD-OPD helper 的 k3+ 已分离 forward/backward，但其 distillation registry 没注册 k3+；helper 存在不能当作完整 trainer 能力。冻结 proposal 不等于 current p 时，以上直接回传结论还需重新处理积分测度。

用 action-independent prefix 标量 $D(s)$ 作 plain score reward 时，$\mathbb E_{a\sim p}[D(s)\psi(a\mid s)]=0$。因此 deterministic Top-K KL 不能简单 detach 后变成同一个 token 的 PG advantage。MD-OPD `use_policy_gradient` 还包含 PPO ratio/clipping；统一实验需拆 gradient program、proposal correction 和 clipping，不能只切旧布尔开关。

KLPO 值得借鉴的是明确的 scorer/auxiliary-draw 合同和独立梯度内核。随机 center 与 score 相乘时，两个估计量的无偏性不保证乘积无偏；独立 draw 或合法 leave-one-out 是 recipe 的实际要求。KLPO 的 token/sequence、sampler、raw reward 和 reduction 保持独立定义。

### 实施顺序与验收

#### 第一步：封闭现有 pipeline

迁入完整数学 schema/builders/判分，替换 `.bashrc` 和相邻数据路径约定，增加固定 data/model manifests 与离线 import。先保留现有 backend 和 loss，不同时改变算法。验收是去掉相邻 MD-OPD 后，准备数据、判分和解析训练设置仍可运行，旧题目顺序与评分保持兼容。

#### 第二步：明确算法与日志合同

在现有函数外建立小契约，旧六个 production modes 作为 legacy parity recipes。先补 Mean regression/score alias、BPO exact live-center/score 对照和显式 head-tail 变体，再建立 capability planner。完整日志事件和实际 optimizer 计数持久化，与旧 metric aliases 并行迁移。

验收覆盖 token ID 交换、mask、EOS、temperature、冻结证据、target/proposal、DP/global reduction 和 estimator 独立性。unsupported 组合在启动前报错。数学 CPU tests 与 backend parity tests 分开：前者无需 third-party checkout，后者锁定其真实版本和导出符号。

#### 第三步：单个 backend 正式入库

固定当前可核验源码树，保存来源与许可证，框架变更按 hook/cache/validation/telemetry 拆分维护。新增算法只增加第一方 kernel、需求和预设；score backend 不具备能力时才扩展接缝。随后另设官方 verl 升级对照。

#### 第四步：分层消融

先验证数值和梯度，再做真实模型 canary，最后比较固定预算训练质量。建议实验组为：

1. Mean/Part 的 regression versus score：逐动作同梯度是验收条件。
2. BPO exact live-center versus score：总体等价与有限样本方差是两个比较维度。
3. BPO full versus head-tail versus 独立 MC center：比较 center/gradient bias、方差和评分成本。
4. reverse-KL sampled versus head+tail residual/control：目标保持一致时比较梯度估计量；coarse deterministic target 单列。
5. frozen anchor / teacher / union support：真实 ID 完整，K 与质量归一化分别控制。
6. inner=1/4/16，统一生成 token、更新数、teacher 评分与运行时预算，并使用相同评测协议。

inner 收敛看固定 probe 上的真实 objective/proxy、可解释 residual、梯度和参数变化。$\mathcal K^S$ 是离开 anchor 的距离，不能作为收敛目标；score coefficient 也可能在 stationary policy 下保留 action-independent 非零项。outer quality 与 inner objective 分别报告。

这一实施顺序保持现有实验作为可核验参照，同时使每个新算法具备明确数学目标、可替换估计量、独立执行需求和一致可观测性。
