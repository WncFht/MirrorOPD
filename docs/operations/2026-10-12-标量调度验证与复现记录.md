# 标量调度验证与复现记录

## 范围与入口

本次开发基于 MirrorOPD commit `5cd86d87e4125285667523c8b7bec3414f971de3`。用户已有的 WandB 指标文档修改保持未暂存。理论更新现有主稿的 `dyn_scalar_schedule.tex`，实验结论维护 [BPO 标量调度分析与验证](../experiments/2026-10-15-固定监督蒸馏动力学与BPO优化实验报告.md)，对应数据、配置、源码哈希和汇总保存在 `results/scalar-schedule/`。

实验只使用本机 GPU 0–3；GPU 4–7 的已有任务保持运行。运行环境为 workspace 的 `envs/opd`，使用 Torch 2.7.1+cu126 和 Transformers 4.57.6。生产损失、冻结缓存和 AdamW 直接复用；没有新建分布式 trainer。标量搜索内核位于 `src/mirroropd/training/scalar_schedule.py`，模型训练脚本位于 `experiments/toy/scalar_schedule_lm.py`。

## 运行与修正

先写实验判据，执行 690 条二次轨迹与 540 条分类轨迹。常数 lr 网格包含达到同一阈值的快速分支与终值较低的分支，结果按阈值与终值分别比较，避免只用保守默认 lr 作基线。

初步语言模型缓存使用 16 条 prompt，其中第 5、7、8 行有左侧 padding。rollout 与原缓存 forward 的 attention mask 处理不一致。这批初步结果已移到忽略目录 `runs/scalar-schedule/padded-preliminary/`，不进入正式表格、图或结论。保留其余 13 条无 padding prompt，416 个 prefix，重新运行全部关键条件。准备与训练脚本已统一传入 attention mask；固定输入 token IDs、mask、prompt 及排除行已版本化，恢复信息加入 `data-manifest.json`。

20 条正式 GPU 分支共享同一个修正后缓存，源码哈希一致。它们包含完整 BPO 与生产 sampled/Top-16 更新、FP32 与 BF16、常数 lr 网格、三点搜索、log loss 梯度缩放和相对收缩反馈。完整目标的主要常数与搜索分支跑 500 次 backward，其余消融跑 120 次。Toy forward 计数包含优化循环及终点评估，排除所有分支共同的初始化指标计算；语言模型计数还包含初始评估。

固定 IDs 的缓存重建已实际运行。重建与原始缓存的 q/teacher 分布平均 KL 分别为 $3.58\times10^{-11}$ 与 $1.09\times10^{-10}$；最大 logit 差分别为 0.00134 与 0.000724。GPU batch shape 与算子路径引起的浮点差异有单独记录，未把缓存重建描述为逐字节相同。正式比较始终使用同一原始缓存，校验值在输入压缩文件与每条运行 JSON 中保留。

原始大轨迹以 gzip 归档，解压后的 SHA-256 和压缩文件 SHA-256 记录在 `archive-manifest.json`。单个版本化文件均小于 20 MiB。临时缓存、初步结果、模型加载日志及训练 scratch 留在 `runs/scalar-schedule/`。
