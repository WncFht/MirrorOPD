## 上游实现与补丁

`upstream-manifest.json` 记录 MDPO、OpenKimi、One-Shot-OPD 与 TA-OPD 的原始 URL、基线提交和迁移时 HEAD。`experiments/upstream_patches/` 保存所有本地源码修改，包括 TA-OPD 的 MirrorOPD loss、缓存、trainer 路由和 rollout 权重版本检查，以及其他审计 checkout 的本地修改。

`make upstream` 获取 manifest 指定的基线并重放补丁。现有 checkout 不自动切换分支；若补丁已存在，则只核对并报告。来源 URL 不符或补丁冲突时停止，保留原文件。新机器重建时，TA-OPD 在原始基线提交上保留已应用的工作区补丁，因此其 HEAD 与迁移时包含本地提交的 HEAD 不同，源码修改以补丁为准。

上游 checkout 不进入本仓库 Git，许可证和原始历史由对应项目维护。正式训练入口继续调用 TA-OPD/verl 的 `main_ppo`，CPU 数学实现和小型 LM 实现承担验证用途。

## 数据和构建产物

两份完整 rollout 的 `prefix_mk.csv` 与一份 `prefix_metrics.jsonl` 采用确定性 gzip 压缩，压缩包进入 Git，原文件留在本地并忽略。`data-manifest.json` 保存原文件大小和 SHA-256。`make data` 恢复缺失文件并核对内容；已有文件若与记录不同则停止，不覆盖修改。其余图、CSV 汇总和 metadata 保持版本化。

训练日志、checkpoint、scratch、Python cache 和 LaTeX 中间文件不进入 Git。当前 ElegantBook PDF 与早期 PDF 保留。主书用 `make book` 编译，图像加载路径已经改为新布局。

## 工具链与验证入口

`make bootstrap` 安装 npm 锁文件依赖，连接本地 agent 与 MPE 预览环境，安装 pre-commit 并恢复数据。提交检查包括 Markdown、YAML 注释宽度、Python Ruff、Shell、TOML、GitHub Actions、secret 检查与 20 MiB 文件守卫。格式化作用于暂存内容；上游 checkout 和运行数据不参与第一方代码格式化。

`make test` 验证数学恒等式、outer/inner 更新、上游 loss、trainer cache 路由和小型 causal-LM。`make check` 检查工具链，CI 同时运行静态检查和 CPU 数学/上游集成验证。主书编译、压缩数据恢复和上游补丁重放另有独立入口，便于区分失败来源。
