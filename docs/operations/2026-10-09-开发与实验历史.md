### 2026-10-09：FlashAttention 与 dtype 兼容性修复

FP32 控制实验最初在 FlashAttention kernel 处失败，原因是 FSDP forward 的参数 dtype 为 FP32，而 FlashAttention 只接受 FP16/BF16。修复写入上游补丁：`FSDPEngine` 检测实际 mixed-precision parameter dtype；当它为 FP32 且 attention implementation 为 FlashAttention 或未显式设置时，自动选择 PyTorch SDPA，并发出可检索的 warning。BF16 主路径不改变，仍使用 FlashAttention。vLLM rollout 始终保持独立的推理 attention 栈。

修复后的 `dtype-smoke4`（BF16、vLLM、FlashAttention）和 `fp32-smoke3`（FP32、vLLM、SDPA）均以退出码 0 完成 1 step。FP32 smoke 的 FSDP actor allocated 峰值约 2.37 GiB；rollout 与 actor 的 log-prob 仍存在已知 vLLM/HF 数值差异，记录为 `rollout_corr/kl=0.0865`，不能将其误判为训练损失。

新增 `training/run_mdpo_calibration_matrix.sh`，在 archbox 上按 resource、inner、eta 三阶段顺序运行 MDPO 校准。矩阵默认禁用 checkpoint，并通过 `WANDB_RUN_GROUP` 将资源、inner 动力学和 eta 消融分组；每个 run 独立落盘完整配置、JSONL、GPU CSV 和 W&B 记录。正式批量执行从该入口开始，结果逐批回填 [训练预算校准与消融计划](../experiments/2026-10-09-训练预算校准与消融计划.md)。

### 2026-10-09：One-Shot-OPD 指标对齐与模型配对调整

核对 One-Shot-OPD 的 `opd_trainer_mixin.py` 和 `fsdp_teacher_worker.py`：其 dense teacher token reward 直接进入 `token_reward_direct` advantage estimator，并记录 `opd/top_k_overlap_ratio`。这个 overlap 是学生候选 token 落在教师候选集中的比例；论文中的 state coverage 是跨训练 prefix 的覆盖率，不能当作同一个量。MirrorOPD 增加 `mirror_token_advantage`、`mirror_support_overlap` 和正值 `mirror_action_nll`。support overlap 比较冻结 rollout anchor Top-K 与当前 inner student Top-K，始终 stop-gradient，只作候选集漂移诊断。

重新明确指标解释：`distillation_losses` 是 policy-gradient surrogate，不是 KL；其负值来自 `coefficient * log pi_theta(a|s)` 的最小化符号，不能用绝对值评价算法。固定 prefix 的 full-vocab `KL(teacher||student)` 是主蒸馏指标，`KL(student||teacher)`、真实续写 NLL、entropy 是安全性与分布质量指标，ESS、importance ratio、advantage RMS、pre-clip grad norm、clip scale 和 parameter update norm 是优化诊断指标。

主模型 pair 调整为同 tokenizer 的 `HuggingFaceTB/SmolLM2-135M` student / `HuggingFaceTB/SmolLM2-360M` teacher（约 134.5M/361.8M 参数，Apache-2.0，教师小于 1B）。Pythia-14M/70M 继续作为最快回归 pair；Qwen3-1.7B/4B 退出主消融，因为教师规模超出约束。SmolLM2 pair 尚未开始正式训练，先完成 tokenizer、full-vocab KL 与 vLLM/HF log-prob 一致性 smoke。

## 2026-10-09：主机内存失败定位与修复验证

run26duxpth 在 actor 到 vLLM 同步时触发 Ray 主机内存保护：节点 30.17 GB/31.05 GB，actor/teacher 共用 worker RSS17.88 GB。不是 CUDA 显存 OOM，也不能将缺少 outer 日志解释成 W&B 上传失败。新增阶段级 host-memory.jsonl，记录 RSS、系统可用内存、pinned allocator 统计及清理前后差值，保持 Ray 原有 95% 保护阈值。

同样 B=64、J=16、response=2048 的诊断发现普通 gc/malloc_trim 只释放约 5 MB；单独释放空闲 pinned 缓存仍然失败，节点 30.05 GB/31.05 GB。PyTorch 2.8 FSDP1 开启 CPUOffload 后，在第一次 forward 初始化时为每个 flat parameter 预分配同形 CPU 梯度缓冲，即使该 engine 是 forward_only。SmolLM2-1.7B teacher 的这组缓冲共 3422752768 bytes，纯推理不执行 backward。

最初仅对 forward_only engine 在 eval 结束后释放_cpu_grad，actor 不走此分支；CUDA 同步后回收空闲 pinned 块，再释放普通 CPU 分配器缓存。实际 worker RSS 在 teacher 阶段从 16986791936 降到 10261553152 bytes，训练 offload 后降到 9297457152 bytes。但这一组仍然失败：teacher 首次 forward 的峰值已触发 Ray 杀 worker，后面的同步才暴露异常。因此将 FSDP lazy initialization 和梯度缓冲释放提前到 teacher forward 之前，避免仅在峰值过后清理。保留模型参数、优化器状态、global token 累积梯度和全部算法超参数。修复使用固定 PyTorch 2.8 内部接口，新增测试验证 actor 保护、参数保留及重复执行；完整跨 outer 运行是否成功由后续退出码记录。

PyTorch 源码证据：[CPUOffload 梯度预分配](https://github.com/pytorch/pytorch/blob/v2.8.0/torch/distributed/fsdp/_flat_param.py#L1222)、[pinned 空闲块释放](https://github.com/pytorch/pytorch/blob/v2.8.0/aten/src/ATen/core/CachingHostAllocator.h#L316)。allocator 的 allocated/reserved 统计在本版本出现 allocated 大于 reserved 等不一致，结论以实际 RSS 变化及释放张量字节数为准。
