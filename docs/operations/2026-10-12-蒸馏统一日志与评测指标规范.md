# MD-OPD 与 MirrorOPD 统一日志与评测指标规范

状态：拟定规范，供两库合并时实施；当前正式训练仍使用原有日志。本文设计不改变已运行实验的目标与评测协议。

## 设计目标与已核实的差异

统一日志首先固定被测数学对象、参数时点与聚合权重，再统一 W&B 展示。相同字段名只有在三个条件相同时才允许直接叠加。生产原始记录保留来源字段，转换层输出版本化规范字段，并保存来源到规范字段的映射。

MD-OPD 的 `verl/verl/utils/tracking.py` 直接将 `data` 与训练 `global_steps` 交给 W&B，没有 MirrorOPD 的独立 inner 轴。MirrorOPD 的 `src/mirroropd/training/tracking.py` 已将 inner 更新和 outer 分轴，但 outer 字段中仍混有本轮更新前 rollout 量与更新后 evaluation 量。后者不能由一个 `outer_step` 完整描述。

MD-OPD 的 `opd_trainer_mixin.py:218–290` 中 `opd/adv_*` 测量的是教师与当前学生的 sampled-action log-prob 差，学生来自 `current_student_log_probs`，缺失时回退 `old_log_probs`。该量是蒸馏 reward，经过算法中心化、importance weighting、优势估计器后的实际优化 advantage 未必等于它。MirrorOPD 的 `mirror_token_advantage` 则与下降 score coefficient 完全相同，两库现有 `advantage` 名称的数学对象不同。

MD-OPD 在 Top-k reward 模式下 `opd/token_reward_mean` 会对候选轴求和，再除以有效 response token 数。其 `opd/adv_*` 仍来自真实 sampled action。两者不得统一为同一个 `reward_mean`。

## 与两版书稿一致的符号

旧书使用 $\pi_k,\pi_{k,n},\pi_T$；当前书使用 $q_k,p_{k,n},t$，三组对象逐项相同。本文展示沿用旧书，规范字段使用无歧义的对象名。

$$
q_k=\pi_k,\qquad p_{k,n}=\pi_{k,n},\qquad t=\pi_T.
$$

| 符号                            | 定义                                                 | 规范字段根                       | 解释                                                |
| ------------------------------- | ---------------------------------------------------- | -------------------------------- | --------------------------------------------------- |
| $U_{k,n}$                       | $\log(\pi_{k,n}/\pi_k)$                              | `signal/U_student_anchor`        | 当前学生相对本轮冻结锚点的 sampled-action log-ratio |
| $r_k$                           | $\log(\pi_T/\pi_k)$                                  | `signal/r_teacher_anchor`        | 冻结 teacher reward                                 |
| $r^{\mathrm{cur}}_{k,n}$        | $\log(\pi_T/\pi_{k,n})=r_k-U_{k,n}$                  | `signal/r_teacher_student`       | 当前 teacher reward                                 |
| $\omega_{k,n}$                  | $\pi_{k,n}/\pi_k=e^U$                                | `ratio/omega_student_anchor`     | 与锚点的条件动作比率                                |
| $w_{k,n}$                       | $\pi_{k,n}/\beta_k$                                  | `ratio/w_student_behavior`       | 一般行为策略 $\beta_k$ 下的动作 IS 权重             |
| $\rho$                          | $\pi_{k+1}=(1-\rho)\pi_k+\rho\pi_{k,N}$              | `setting/sync_rho`               | 书中的概率空间同步系数，hard sync 为1               |
| $\mathcal K_k^T=K_{qT,k}$       | $\operatorname{KL}(\pi_k\Vert\pi_T)$                 | `kl/anchor_teacher`              | 冻结 teacher center                                 |
| $\mathcal K_{k,n}^S=K_{qp,k,n}$ | $\operatorname{KL}(\pi_k\Vert\pi_{k,n})$             | `kl/anchor_student`              | student center，方向从锚点出发                      |
| $K_{pT,k,n}$                    | $\operatorname{KL}(\pi_{k,n}\Vert\pi_T)$             | `kl/student_teacher`             | 当前 OPD baseline 的中心                            |
| $c^{\mathrm{score}}$            | $g=\mathbb E[c^{\mathrm{score}}\nabla\log\pi_{k,n}]$ | `optimization/score_coefficient` | 参数下降所用 score 系数                             |
| $A^{\mathrm{score}}$            | $A^{\mathrm{score}}=-c^{\mathrm{score}}$             | `optimization/ascent_advantage`  | 同一更新写成策略上升时的 advantage                  |

旧书第一章的无下标 $\rho$ 表示同步；第二章 Token-IS 节还用 $\rho_{k,n}$ 表示教师与当前学生 log-ratio。统一规范将后者写成 $r^{\mathrm{cur}}_{k,n}$，与 $r_k-U_{k,n}$ 对应，保留 $\rho$ 的同步含义。PPO 的概率比率使用 $w$ 或 $\omega$，避免同一个字母再增加第三种含义。参数 EMA 的系数另记 `setting/parameter_ema_decay`，不得伪装为概率混合的 $\rho$。

旧书还用 $c_{k,n}=p/\operatorname{sg}(p)$ 表示 K4 的 score surrogate。为避免与下降系数冲突，本文一律写 $c^{\mathrm{score}}$；如需记录 K4 的量，使用 `estimator/k4_score_multiplier`，公式仍写 $p/\operatorname{sg}(p)$。

$N$ 表示 inner 更新数，$J$ 表示 Top-k 大小，$R$ 表示每题评测生成数，$M_k$ 表示本轮有效训练 token 总数。配置及图例禁止共用 `k` 或 `j` 表示这些不同对象。

## 系数与 advantage 的统一定义

令 $b_{pT}(s)$ 为当前学生到教师的动作无关 baseline，各方法的下降系数为

$$
\begin{aligned}
c^{\mathrm{OPD}}&=-(r^{\mathrm{cur}}+b_{pT}),&&a\sim\pi_{k,n},\\
c^{\mathrm{TokenIS}}&=-w(r^{\mathrm{cur}}+b_{pT}),&&a\sim\beta_k,\\
c^{\mathrm{MDPO}}&=\omega(U/\eta-r_k),&&a\sim\pi_k,\\
c^{\mathrm{BPO}}&=(U+\mathcal K^S)/\eta-r_k-\mathcal K^T,&&a\sim\pi_k.
\end{aligned}
$$

每个系数在承载解析梯度的 score surrogate 中整体停止梯度。$A^{\mathrm{score}}=-c^{\mathrm{score}}$ 是同一更新的另一符号写法，不是新增梯度分支。若算法先得到未加IS的 reward advantage，再乘比率，应另存 `optimization/preweight_advantage`，禁止将其与加权后的 $A^{\mathrm{score}}$ 混合。

BPO 的原始目标按冻结锚点积分，因此系数没有乘 $\omega$。仍然记录 $\omega$ 与其 ESS 来诊断策略离开锚点的程度，但必须同时记录 `setting/applies_action_is=false`。MDPO 与行为分布相同于锚点的 Token-IS OPD 则为true。

## 支持集重叠的对象与统计

记录 `support/student_anchor/top_j_overlap` 和 `support/student_teacher/top_j_overlap` 两个不同字段，分别为 $\lvert\mathrm{Top}_J(p)\cap\mathrm{Top}_J(q)\rvert/J$ 与 $\lvert\mathrm{Top}_J(p)\cap\mathrm{Top}_J(t)\rvert/J$。每个 token 的集合重叠与概率质量分开报告；MD-OPD 现有 rank 平均不能作为全 token 平均。两库统一传 overlap_sum 和 valid_token_count，跨 DP 汇总后再除。Top-$J$ 与 Jaccard 的关系为 $O/(2-O)$，全局均值的非线性转换不等于逐 token Jaccard 均值，故不能直接转换已汇总历史 scalar。

## KL 精度与聚合权重

每个 KL 字段需要精度后缀，例如 `kl/anchor_teacher/full`、`kl/anchor_teacher/tail_aware_j16`、`kl/anchor_teacher/sampled_action`。Tail-aware 聚合分布保留锚点选出的头部 $\mathcal H_k$，把其他动作归到尾部桶：

$$
K^{\mathrm{TA}}_{qT}=\sum_{a\in\mathcal H_k}q_a\log(q_a/t_a)+q_{\mathcal T}\log(q_{\mathcal T}/t_{\mathcal T}).
$$

完整 KL 与该诊断的差为

$$
K_{qT}-K^{\mathrm{TA}}_{qT}=q_{\mathcal T}\operatorname{KL}(q(\cdot\mid\mathcal T)\Vert t(\cdot\mid\mathcal T))\ge0.
$$

只保留名字 `teacher_center` 无法交代 KL 方向、参考策略与精度。MDPO/BPO 对应 `anchor_teacher`，OPD 的当前baseline对应 `student_teacher`。统一后分别保存；在 $n=0$ 两者数值一致时，也保持两个不同数学名称。

训练 token 字段的平均为 $\sum_{i,t}z_{i,t}/M_k$，以有效 token occurrence 等权。数学 task score 以题目/回答等权，不乘回答长度。评测数据集平均先对每题的生成聚合，再对题平均；不同数据集分别展示，若给总570题成绩必须另存总正确数与总题数。

每个 token 字段合并原始充分统计量 `count,sum,sum_sq,min,max`，再计算 mean/std/RMS。数据并行sum如被框架平均，count/sum须恢复rank规模，ESS用同一恢复规则。分位数需要全局样本或可合并分位数草图；局部p95的平均不是全局p95。

MD-OPD 的 `ce_minus_entropy_proxy` 是 teacher NLL在实际动作上取均值减学生完整条件entropy均值。行为动作并非当前学生时，它不是当前完整 KL。迁移时保留 `diagnostic/teacher_nll_minus_student_entropy_proxy`，不改名为 `kl/student_teacher/full`。

MDPO 的 $\overline{c^{\mathrm{score}}}$ 等于固定 batch 上 IS 形式镜像原目标的数值估计：$\widehat L_{\mathrm{MDPO,IS}}=\widehat{\mathbb E}_q[\omega(U/\eta-r_k)]$。它与 $\overline{c\log p}$ 的 score surrogate 数值不同。规范应另存 `objective/mdpo/is_value`，并注明训练/holdout batch；同一标量在语义上可以与系数 mean 相等，但不能据此把 OPD/BPO 的系数 mean 统一解释为目标值。

## 事件、参数版本与 W&B 轴

本地JSONL采用event记录。每条记录包含 `schema_version,event_id,event_type,measurement,outer_index,inner_index,updates_completed,actor_version,anchor_version,behavior_version,batch_id,prefix_set_id`。数据初始化、rollout完成、inner更新前、inner更新后、hard-sync后与evaluation分别为独立事件，避免合并成一个模糊的outer行。

| 事件                 | $k,n$          | `updates_completed` | 参数/数据时点                           |
| -------------------- | -------------- | ------------------- | --------------------------------------- |
| `initial_evaluation` | $k=0$，无inner | 0                   | 初始权重，测试数据                      |
| `rollout_snapshot`   | $k$，$n=0$     | 当前真实计数        | 新rollout及冻结anchor，更新前           |
| `inner_pre_update`   | $k,n$          | 当前真实计数        | 即将执行该次optimizer，旧书 $\pi_{k,n}$ |
| `inner_post_update`  | $k,n$          | pre计数加1          | 本次optimizer已完成，旧书 $\pi_{k,n+1}$ |
| `outer_post_sync`    | 已完成outer数  | 真实计数            | rollout副本已同步                       |
| `evaluation`         | 已完成outer数  | 真实计数            | 明确checkpoint及测试协议                |

`updates_completed` 从实际optimizer计数器增加，不能用 `outer*N+n` 替代，后者在变N、提前停止、resume和多mini-batch时会失真。无值字段用JSON null，在W&B省略；不得用0把不存在的初始训练指标补成初始点。

`outer_index=k` 始终表示正在处理的轮索引；`axes/outers_completed` 表示已完成全部 inner 和同步的轮数。第 k 轮 `inner_pre_update` 时已生成 k+1 次 rollout，而完整 outer 只完成 k 次。这两个计数必须分别维护。

规范轴为 `axes/rollouts_completed`、`axes/updates_completed`、`axes/generated_tokens_total`、`axes/training_elapsed_s`、`axes/run_elapsed_s`。前四个支持公平训练比较，最后一个包含评测、checkpoint与等待，反映总成本。一次评测记录携带全部轴，让用户切换x轴而不重新拼历史。

W&B的隐式history step仅作单调事件编号。`define_metric`应为规范指标绑定默认轴：inner默认 `axes/updates_completed`，rollout snapshot默认 `axes/rollouts_completed`，质量默认 `axes/rollouts_completed`，同时固定提供优化次数、训练时间和端到端时间三个对比面板。W&B面板可切换其余轴。每次 log 同一个 payload 显式携带对应轴值，并设置 `step_sync=false`，避免先前事件的横轴继承到新事件。rollout 指标、inner 指标、inner aggregate 和 evaluation 使用独立字段根，禁止两种事件写同名标量。

内层动力学用本地 $(k,n)$ 热图和选定outer折线；不要把每outer重置的 $n$ 作为整个run的全局W&B step。按outer比较时只取指定snapshot，例如每轮 $n=0$；内层末态必须真实补测 $n=N$，下一轮 $n=0$ 的新batch不能替代。

## mean@R、pass@R 与重复 greedy

MD-OPD `_validate` 按 `val_kwargs.n` 重复测试batch，通过uid将同题生成聚合；`process_validation_metrics` 输出mean、std、pass、best和majority。令题目 $i$ 的第 $j$ 次生成正确标记为 $z_{ij}\in\{0,1\}$，题数为 $D$，每题 $R$ 次独立随机生成。

$$
\operatorname{mean@}R=\frac1D\sum_{i=1}^D\frac1R\sum_{j=1}^Rz_{ij}.
$$

它估计固定解码分布的一次生成成功率；增大R提高估计精度，不将任务改为“至少一次答对”。至少一次成功为

$$
\operatorname{pass@}R=\frac1D\sum_{i=1}^D\mathbf1\{\sum_jz_{ij}>0\}.
$$

若总共采样R次而报告 $h\le R$ 次机会的pass率，令 $C_i=\sum_jz_{ij}$，代码的估计器为

$$
\widehat{\operatorname{pass@}h}=\frac1D\sum_i\left[1-\frac{\binom{R-C_i}{h}}{\binom Rh}\right].
$$

当 $h=R$ 时退化为至少一次答对的指示量；$h=1$ 等于mean@R。独立同分布随机采样和二元correctness是其概率解释条件。任意连续reward的 `best@R` 与pass率不同。MD-OPD现有工具会对每个数值变量统计等于1的次数，规范层仅对二元correctness输出 `pass@h`。

Greedy重复R次属于可复现性检查。理想确定性推理下各次输出相同，mean@R与greedy accuracy相同，不能把R次结果解释为独立随机采样带来的pass@R能力。若重复结果不同，应报告 `evaluation/repeat_greedy/disagreement_rate`、正确数范围、逐题输出hash及运行版本，调查batch shape、分布式推理、数值精度与实现确定性。

现有 MirrorOPD 的完整性核验需由固定 570 条响应改为同时验证 570 个唯一题目、每题 R 次响应、总计 570R 条生成；必须按 UID 统计，防止漏题或重复题被总数掩盖。记录多次生成不只修改 val_kwargs.n，还涉及独立验证 max_tokens、do_sample、评分输入、上传字段和逐题文件。

评测metadata必须记录 `do_sample,temperature,top_p,top_k,R,response_budget,context_budget,seed,template_hash,checkpoint_hash,scorer_version,dataset_hash`。规范名称建议 `quality/math500/sample_t0p7/mean_at_16`、`quality/math500/sample_t0p7/pass_at_16`、`quality/math500/greedy/accuracy`，并保留正确生成数/总生成数、每题正确次数与 generated token 数。不同预算/解码必须使用不同 protocol_id，禁止同一个质量系列在运行中改变协议。

## ESS 的边界与内层收敛判据

对有效token比率 $w_j$，

$$
\operatorname{ESS}=(\sum_jw_j)^2/\sum_jw_j^2,\qquad
f_{\mathrm{ESS}}=\operatorname{ESS}/M_k=1/(1+\operatorname{CV}(w)^2).
$$

高ESS描述权重集中度，既不校正当前前缀分布，也不证明任务性能改善或内层优化完成。同一回答的token相关，使ESS不能充当独立统计样本数。BPO的ESS只作锚点漂移诊断；比率应用到梯度与否另由 `applies_action_is` 表达。

不能要求MDPO的coefficient趋零。在精确Gibbs解处 $U^*=\eta r_k-\log Z_k$，其系数为

$$
c^{\mathrm{MDPO},*}=-\omega^*\log Z_k/\eta.
$$

该系数一般非零，但总体梯度为

$$
\mathbb E_q[c^{\mathrm{MDPO},*}\psi^*]
=-\log Z_k\,\mathbb E_{p^*}\psi^*/\eta=0.
$$

因此coefficient RMS、surrogate loss与ESS均不能单独作为收敛阈值。完整中心且逐前缀可表达的BPO可在Gibbs解使残差归零；共享网络投影误差、Tail-aware中心与有限batch仍会使经验量非零。

建议新增 `convergence/full_batch_gradient_norm`、`convergence/full_vocab_objective`、`convergence/full_vocab_objective_improvement`、`convergence/parameter_update_relative_norm`、`convergence/fixed_prefix_holdout_gradient_norm`。全batch梯度必须是跨所有micro-batch与DP rank累积后、clip之前的真实梯度范数；同时记录clip比例与Adam实际参数更新，避免小裁剪后更新被误认为小原始梯度。

MDPO完整目标为 $\mathbb E_{d_k}[\operatorname{KL}(p\Vert q)/\eta-\mathbb E_p r_k]$；理想gap为 $\mathbb E_{d_k}\operatorname{KL}(p\Vert\pi_k^*)/\eta$。固定前缀集上按完整词表测量，记录evaluation-only开销。BPO使用 $\mathbb E_{d_k,q}R^2/(2\eta)$ 和完整中心误差。实际early-stop使用多次objective改善低于预设阈值并同时梯度或实际更新下降，在独立holdout前缀/action上复核，不以重复batch训练loss单独决定。

## 迁移建议与可恢复范围

1. 首先增加规范适配层，所有现有原始字段及事件留存。对已有JSONL使用显式方法、测量时点、epoch数与来源映射转换，不能仅按字符串rename。
2. 将 `mirror_token_advantage` 历史字段映射为 `score_coefficient`，生成新的 `ascent_advantage` 时mean/min/max须取负并交换min/max，std/RMS保持不变。MD-OPD `opd/adv_*` 映射为teacher-current log-ratio统计，只有验证其实际策略梯度消费路径后才输出优化advantage。
3. 将 `teacher_center` 按算法拆成anchor_teacher或student_teacher，明确Tail-aware与支持选取方式。将sampled_reward拆成frozen/current两字段，可由 $r^{cur}=r_k-U$ 恢复相同时点的线性mean，RMS/std需要协方差或逐token数据，不能从两组边际moment直接恢复。
4. 训练完成数从optimizer事件恢复并验证连续性。现有固定B=mini时可通过 $kN+n$ 验证，但恢复字段必须标记来源为derived；变N或缺记录时使用实际计数。
5. 原始moment无法恢复分位数、逐题配对、最后一次更新后ESS及完整词表KL。这些字段在历史run标记缺失，从新run开始采集；不补造数值。
6. 资源事件使用wall-time计时并分列rollout、anchor、teacher、actor、sync、evaluation、checkpoint；GPU峰值按device与阶段记录allocated/reserved/NVML-used，说明统计范围，禁止把不同范围混成同一峰值。

新增固定 full-logit probe 可记录镜像方程残差 $\Delta=U-\eta r_k+\log Z_k$，其中 $Z_k=\sum_a q_a^{1-\eta}t_a^\eta$。精确 Gibbs 解处 $\Delta=0$，比要求 MDPO 的实际下降系数归零更接近目标条件。该诊断需在同一 prefix 上拥有 q/t 的完整共同支持 logits；当前 Top-J cache 不足以恢复完整 logZ，不能将跨 prefix 的全局系数均值充当条件 baseline。记录字段为 `residual/mirror_equation/full_probe/rms`，与真实梯度和 holdout objective 联合使用。

实现验证覆盖重复启动/resume、动态N、多个mini-batch、变长micro-batch、DP不等长、EOS与预算终止，以及mean@R/pass@h/重复greedy。日志正确性校验以原始充分统计量和真实optimizer事件为基准，避免只检查图像是否平滑。

## 精度、支持与资源元数据

模型精度按角色单独记录 `parameter_storage_dtype`、`forward_dtype`、`gradient_reduce_dtype`、`buffer_dtype`、`logprob_normalization_dtype` 与 `optimizer_state_dtype`，不能用一个 bf16 字段覆盖全部阶段。冻结 teacher 的 reduce dtype 是配置元数据，不代表发生了梯度通信。

共同 action 支持用 tokenizer hash、有效 action ID 范围、output head 列数和支持外概率质量记录。HF actor、teacher 与 vLLM 都在相同 action 支持上归一化；仅将 Top-k 调大不修复不同归一化分母。MD-OPD 当前源码中的支持差异应在统一实现前用真实模型 probe 核实并处理。

每次 optimizer 记录裁剪前梯度范数、裁剪阈值、裁剪 scale、实际更新范数及参数相对更新；inner 计时由 worker 单调时钟记录，上传时间只作传输诊断。显存分别保存 actor allocator 高水位、每阶段重置后的 allocator 峰值与设备 NVML 已用内存；CPU 记录整机与进程组 PSS，禁止把整机 used RAM 标成 actor RAM。
