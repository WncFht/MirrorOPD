# 实验目录组织与训练代码导航

## 目录边界

当前实验采用代码、输入记录、结果和文档分别维护的布局。`experiments/` 只存可执行实验程序；程序以命令行参数接收输入路径与输出路径。`src/mirroropd/` 保存 PMD、BPO、MDPO 的数学参考内核，供测试和 toy 程序复用。它不承担 Ray、FSDP 或 vLLM 的调度。

| 目录                    | 文件归属                                              |
| ----------------------- | ----------------------------------------------------- |
| `experiments/rollout/`  | GSM8K rollout 与早期 M32 探查程序                     |
| `experiments/scoring/`  | 对已有轨迹计算 Top-k mass、student/teacher KL         |
| `experiments/analysis/` | 合成分布下的 EMA/Top-k 估计量分析程序                 |
| `experiments/plotting/` | 读取记录或统计表并输出图表的程序                      |
| `experiments/toy/`      | 固定 history 的有限步优化实验                         |
| `tests/`                | 可重复的正确性和集成验证                              |
| `training/`             | 正式训练和 GPU canary 启动脚本                        |
| `data/`                 | 每个 prefix 或 prompt 的观测记录及压缩归档            |
| `results/`              | 各实验的 bias、variance、RMSE 等汇总表、图和 metadata |
| `docs/experiments/`     | 对应的说明、报告、审计和结论                          |
| `patches/`              | 固定上游版本上的源码改动                              |
| `runs/`                 | 忽略的本机运行日志、PDF 检查与构建输出                |

`results/` 按实验名保持对应目录，便于将图、统计表与生成参数一起核对。`data/qwen3_gsm8k_mk/` 按模型分别保存 prefix 和 prompt 记录；大文件通过 gzip 与 `data-manifest.json` 恢复并校验。已忽略的日志和检查图片也已移入 `runs/`，没有删除。

早期工程保存在 `docs/earlier/`，维持其历史上下文与独立构建关系。当前实验的持续开发入口使用以上目录。迁移前对 119 个文件逐一记录 SHA-256，移动后先核对内容，再更新代码导入、文档链接和命令路径。

## 实验输入与输出

完整实验分为 rollout、scoring 与 plotting。rollout 输入数据集 prompt，生成轨迹；scoring 在轨迹的每个 prefix 上计算模型分布统计；plotting 从观测记录或汇总表生成图和统计摘要。用于标量 KL 的 Monte Carlo 方差和优化梯度验证仍由各自的脚本与测试分别处理。

从仓库根执行以下命令。具体模型和量化参数由对应脚本的 `--help` 查看；GPU 环境仍在 archbox。

```bash
make data
make test
PYTHONPATH=src uv run --with torch --with numpy python experiments/toy/toy_token_inner.py
uv run --with pandas --with matplotlib python experiments/plotting/plot_mk_distributions.py \
  --one data/qwen3_gsm8k_mk/1p7b \
  --four data/qwen3_gsm8k_mk/4b \
  --output results/qwen3_gsm8k_mk
uv run --with pandas --with matplotlib python experiments/plotting/plot_teacher_kl_distribution.py \
  --input data/qwen3_gsm8k_kt --output results/qwen3_gsm8k_kt/plots
```

`toy_token_inner.py` 默认将结果写到仓库的 `results/toy/toy_token_inner.csv`，不写入程序目录。合成分布分析程序的输出参数应指定 `results/ema_topk_reproduction/` 或其 `k_analysis/`。GPU rollout 与 scoring 新运行时应将逐 prefix/prompt 的记录写入 `data/`；同次运行的 metadata 与记录一起保留，以便追溯生成参数。现有版本化 metadata 保留在对应 `results/` 中。

早期 M32 探查程序同时负责 rollout 和绘图；它的一次新运行使用 `runs/` 作为输出目录，确认后将原始记录归入 `data/`，图与汇总归入 `results/`。现有数据已按上述用途分开。

## 训练实现的调用链

正式 GPU 训练的本机入口是 `training/run_upstream_mirror_training.sh`。它设置模型、LoRA、inner epoch、rollout、token budget 和 Mirror loss 参数，然后执行上游 `verl.trainer.main_ppo`。`training/run_upstream_mirror_canary.sh` 准备验证数据并调用相同入口。

| 文件                                                            | 职责                                                                                |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `upstream/TA-OPD/verl/verl/trainer/main_ppo.py`                 | Ray 训练任务与模型 worker 初始化                                                    |
| `upstream/TA-OPD/verl/verl/trainer/ppo/ray_trainer.py`          | outer rollout、冻结锚点和 teacher 缓存、actor 更新及 rollout 权重版本核对           |
| `upstream/TA-OPD/verl/verl/trainer/distillation/losses.py`      | 将 Mirror 模式路由到对应 loss 实现                                                  |
| `upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py` | Top-k/tail 缓存、teacher center、inner student center、PMD-mean/BPO/MDPO token loss |
| `patches/ta-opd-mirror-token-loss.patch`                        | 上述上游修改的版本化、可重放保存形式                                                |

最先阅读 `compute_mirror_opd_token_loss`，它展示三种 inner 模式的系数和 surrogate。随后阅读 `build_mirror_anchor_cache` 与 `complete_mirror_teacher_cache`，查看 outer 冻结字段；再阅读 `compute_mirror_opd_from_cache`，查看当前 student logits 如何参与 inner 重算。最后沿 `ray_trainer.py` 的缓存创建和 actor 更新调用核对完整训练顺序。

本地上游 checkout 由 `upstream-manifest.json` 与 `make upstream` 获取和重建，Git 忽略。提交训练改动时更新 `patches/`，并运行上游语义、wiring 和 causal-LM 测试。`src/mirroropd/` 的参考实现用于核对公式和有限步动力学；正式 GPU loss 以 TA-OPD/verl 实现为准。

archbox 已验证训练工作目录仍是 `~/src/mirroropd-taopd`，源码包位于该目录的 `verl/verl/`，虚拟环境为 `.venv/`。启动脚本默认调用该运行目录，迁移本机代码目录没有改变远端 checkpoint、环境或日志。
