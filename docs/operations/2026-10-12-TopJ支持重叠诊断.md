# Top-J 支持重叠诊断

## 三组比较对象

沿用旧书符号，$\pi_k$ 是本轮冻结anchor，$\pi_{k,n}$ 是inner更新前student，$\pi_T$ 是teacher。令它们在同一个prefix $s$ 的原生Top-J集合分别为 $H_k(s)$、$H_{k,n}(s)$ 和 $H_T(s)$。本次实现令 $J$ 等于配置 `distillation_loss.topk`；将集合大小与inner次数区分，本文把inner次数记作 $N_{\mathrm{inner}}$。

对任意一对集合 $H_A,H_B$ 定义

$$
I_{AB}(s)=\lvert H_A(s)\cap H_B(s)\rvert,\qquad U_{AB}(s)=\lvert H_A(s)\cup H_B(s)\rvert=2J-I_{AB}(s),
$$

$$
O_{AB}(s)=\frac{I_{AB}(s)}{J},\qquad \mathcal J_{AB}(s)=\frac{I_{AB}(s)}{U_{AB}(s)}.
$$

三个比较对象分别是student–teacher、student–anchor和anchor–teacher。student–teacher是主要教师对齐诊断，student–anchor测量本轮更新的集合漂移，anchor–teacher给出本轮开始时的教师对齐状态。首inner满足student=anchor，因此student–anchor为1，student–teacher等于anchor–teacher。后两者初始化无需等于1。

## 字段名称与统计协议

每对集合分别记录以下四个逐token字段，`PAIR`取 `student_teacher`、`student_anchor`、`anchor_teacher`：

| 内核字段                                    | 定义              |
| ------------------------------------------- | ----------------- |
| `mirror_overlap_PAIR_intersection_count`    | $I_{AB}$          |
| `mirror_overlap_PAIR_union_count`           | $U_{AB}$          |
| `mirror_overlap_PAIR_intersection_fraction` | $O_{AB}$          |
| `mirror_overlap_PAIR_jaccard`               | $\mathcal J_{AB}$ |

`token_moments` 先汇总有效response token的充分统计量，`finalize_token_moments` 再做跨micro、跨DP统计。新字段因此与现有teacher center使用同一有效token测度。JSONL前缀自动变成 `mirror/overlap_PAIR_STAT/{mean,std,rms,min,max}`；W&B均值等映射到 `06_support_mass/{inner,outer}_overlap_PAIR_STAT/...`，极值仍遵循现有 `90_detail_extrema` 分类。

旧字段 `mirror_support_overlap` 保留，逐项等于 `mirror_overlap_student_anchor_intersection_fraction`。它保证现有报表读取兼容，同时新增名称明确区分三种比较对象。旧缓存若缺 `mirror_teacher_topk_ids`，只产生可定义的student–anchor新字段，缺失teacher字段保持缺失；不写出虚假的零重叠。

J=0是完整关闭Top-J支持诊断的边界配置。本实现把两种count和两种fraction都记0；此时fraction是工程约定值。J等于完整词表大小时，三个集合均为完整词表，intersection_count=union_count=J，两种fraction均1。

Top-J成员选择沿用现有 `torch.topk`。并列logits处的成员采用该算子的原生选择，集合比较忽略返回顺序。不同设备或执行版本对边界并列项可选择不同成员，因此重复实验应固定计算环境；这些字段不能把浮点近并列造成的成员变化解释成概率质量发生大幅变化。

## 缓存和部署契约

教师在outer起点对同一prefix做一次前向。`complete_mirror_teacher_cache` 除原有anchor选出token的teacher logprob外，新增教师自己的Top-J token IDs，字段为 `mirror_teacher_topk_ids`、dtype为int64、形状为prefix维度加J。无效prefix位置置0。teacher IDs与teacher centers一样冻结，所有inner复用；student的原生Top-J每次inner前向重新计算。

第一方 `integrations/verl/fsdp.py` 在teacher scoring阶段返回该缓存，在loss阶段读取。仓库上游补丁更新trainer的teacher输出字段列表与padding/no-padding传输列表，让新增int64缓存完整走过实际worker链路。算法loss、已有centers、IS与reward公式保持相同，新增字段全部无梯度。

缓存额外空间为 $8NJ$ 字节，其中N是本轮有效及传输prefix位置数。若N=400000、J=16，未计张量封装的全局新增ID存储约48.8MiB；四DP均分后每rank约12.2MiB。实际padding布局还可能保存无效位置，应以运行时tensor大小核实。teacher新增一次原生Top-J计算，三对交集各需要J×J布尔比较；没有新增teacher前向。

本次只在独立worktree准备源码与补丁，没有同步到正在训练的backend。部署需一起同步第一方cache/loss/adapter与更新后的TA-OPD patch；仅同步第一方代码不能使旧trainer转发新的teacher字段。

## 与 MD-OPD 的策略选择区分

MD-OPD `top_k_strategy=intersection/union/only_stu` 选择训练候选支持及其权重；其 `top_k_overlap_ratio` 是student与teacher原生Top-K的intersection/K。这两个概念互相独立。MirrorOPD本次新增的union_count与Jaccard属于观测量，不选择loss支持，不开启union/intersection训练策略。

例如两个四元素集合交集含两个token，intersection_fraction=0.5，union_count=6，Jaccard=1/3。把loss支持选成它们的并集不会使原生集合overlap自动变1；统计比较对象仍是两个原生集合。

## 验证

`tests/test_topk_overlap.py` 覆盖三对集合、已知交集与并集、集合排列不变性、并列logits、J=0与J=完整词表、变长response mask、无效prefix置零、全token加权归约、teacher缓存冻结以及新旧诊断对loss/gradient不变性。

`tests/test_upstream_mirror_wiring.py` 在重放新补丁的隔离backend上执行真实trainer方法及padding函数，核对teacher Top-J IDs形状、dtype与无效位置。CPU模型链路和训练统计回归同时核对更新后的cache/loss契约。GPU分布式吞吐与显存影响需要后续canary测量。
