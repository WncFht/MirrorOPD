# 六仓库统一 OPD 架构方案

## 结论与阅读入口

统一的对象是固定状态上的概率积分、梯度程序和执行需求，不是仓库里的 `OPD`、`MOPD`、`Top-K` 名称。生产核心采用框架无关的数据契约、有限 objective recipes、独立数学 oracle 和版本化 backend adapter。保留 token-level、response-level、连续控制三个不同优化对象；共享概率与执行原语，不强行共享 loss。

本方案扩展 [MD-OPD 接入方案](2026-10-10-OPD统一抽象与MD-OPD接入方案.md)，以六个上游的固定 commit、对应论文和本地 [理论主稿](../book/2026-10-08-固定测度Token级MirrorOPD.tex) 为依据。深入审查分别见 [TA-OPD 与 OPD](review/2026-10-10-TAOPD与OPD审查.md)、[verl 与 One-Shot](review/2026-10-10-verl与OneShot审查.md)、[OpenKimi 与 MDPO](review/2026-10-10-OpenKimi与MDPO审查.md)。显存、部署、可观测性和开源维护见 [工程方案](review/2026-10-10-统一OPD工程与开源维护.md)。本次不修改生产训练算法。

### 共同的数学坐标

固定 prefix/state 测度为 $d$，当前 student 为 $p$、真实 behavior 为 $b$、冻结 center/anchor 为 $q$、teacher 为 $t$。目标 action 积分测度为 $\nu$，实际 proposal 为 $\rho$。即使某个 recipe 声明 $b=q=\rho$，系统仍保留角色和版本，以验证这种等同性。

本地书稿的核心统一形式是

$$
\widehat I=I_\nu(a)+\frac{\nu(A)}{\rho(A)}\left[f(A)-a(A)\right],\qquad A\sim\rho.
$$

$f$ 可以是 scalar KL、reverse-KL score、forward-KL score 或 Mirror residual score；$a$ 是已知精确积分的控制函数。支持条件作用于非零随机残差，不要求 deterministic head 已覆盖的区域仍可抽样。GPU 实现通过 scalar surrogate 表达梯度，不构造参数维度的 score vector。

### 必须保留的 recipe 家族

1. **完整 KL 与 scalar estimator。** reverse/forward 分别定义；K1/K2/K3/K4/K3++ 的 forward value 与 backward 配对分别保存。clipping 激活后重新核对偏差。
2. **确定性支持目标。** raw head、conditional support、head+tail coarse KL，以及 head I-divergence 分别命名；它们一般不等于 full KL。
3. **sampled teacher-gap PG。** 固定 rollout、冻结 reward、current/old ratio、rollout correction、PPO clipping 分别记录；不能宣称它完整微分了随参数变化的 trajectory visitation measure。
4. **candidate teacher-gap PG。** 冻结 IDs、每候选 reward 与 ratio/clip；候选权重归一化不等于 conditional-KL 目标。
5. **Mirror token Part/Mean/BPO/MDPO。** anchor 与 current 测度分别选择，center 和 log-partition 有不同职责；完整/近似 center 是显式算法变体。
6. **MOPD residual 与 weighted SFT。** live-center square、GRPO complement ratio/cap/gate/floor 不能合并。名字 `MOPD` 不保证属于同一数学家族。
7. **HETS/ResOPD/SC-TA。** deterministic head 加随机 residual；控制项的向量结构和 stop-gradient 定义不同。
8. **response PMD 与连续控制 MDPO。** 前者先合并 response log-ratio 再平方，后者依赖 state occupancy、continuous policy 和 critic。仅复用生命周期与低层概率操作。

## 等价、条件等价与刻意不等价

MDPO token objective为 $\mathrm{KL}(p\Vert q)/\eta-E_p\log(t/q)$；eta=1 精确化为 $\mathrm{KL}(p\Vert t)$，应与 `opd_is_no_baseline` 建立逐动作 gradient alias。eta趋于无穷是 frozen teacher-gap reward；仅初始 $p=q$ 时方向与 ordinary reverse-KL OPD 一致。本地书稿对 infinity 的概括与 production endpoint tests 需据完整公式对齐。

精确 center、action proposal=q、floor=0 时，MOPD residual square 与 BPO 的总体目标/期望梯度相差 $2\eta$。它们逐动作 gradient 相差 $2R(p-q)$，有限 batch 方差不同；旧 proposal 与近似 center破坏总体等价。这是共用 residual definition、保留两种 gradient recipe 的理由。

K2 和 stopped K4 在 current action measure、无 clipping 时有相同逐动作 backward；其 forward 数值不同。K3++ 也可具有相同 backward，但实现的 clamp 和 backend registry需另外验证。direct k3 的期望方向是 forward KL，不等于 reverse KL。不能按同一 scalar value catalog推导同一训练算法。

raw head、conditional、coarse partition 的差异不是实现细节。分区链式分解给出 coarse KL 是 full KL 下界，但其 gradient error 不保证随 K 单调。conditional目标忽略支持外的相对形状；raw head则保留完整 normalizer 并可以为负。teacher Top-K raw FKL 的非负 clamp还会改变梯度。

OpenKimi的 $(\sum_t u_t-A)^2$ 与本仓库 $\sum_t(u_t-a_t)^2$ 不等价。trajectory correction需要完整 response proposal ratio；token ratio 的算术平均不能替代概率乘积。loss后除长度、ratio本身取均值、prompt-group filtering也各自改变权重或目标。

## 统一 API 与代码边界

采用六个小协议：`SequenceLayout`、`DistributionSpec`、`CandidateSet`、`ScoreRequest/ScoreBundle`、`ObjectivePlan`、`UpdateWindowState`。详细字段沿用接入方案，新增以下轴：

- `action_granularity=token|response|continuous` 与相应 grouping/state measure；
- `support_aggregation=raw|conditional|coarse|i_divergence|full`；
- `gradient_program` 单独描述 deterministic/stochastic surrogate、live/stopped coefficient；
- `approximation_status=exact|biased_target|unbiased_estimator|legacy_update`；
- `ReductionSpec`区分 candidate、token、sequence、prompt和DP全局权重；
- `NumericalPolicy`声明normalizer精度、tail floor、函数clip、ratio cap及监控；
- `BudgetSpec`记录生成、训练、teacher评分、optimizer update和wall-time预算。

不为这些字段各造一个抽象类。第一方首先在既有 `training/`内建立 contracts、recipes 和 requirements三类职责，复用 cache/loss/metrics；`integrations/verl/`持有layout、callback、TP/SP、worker与sync适配。框架TensorDict不进入数学公共API。

MirrorOPD维护唯一数学核心、纯tensor生产kernel与独立oracle。MD-OPD承载现有定制backend与训练编排；长期基于固定官方verl engine形成薄adapter，减少fork维护面。TA/OPD/OpenKimi作为锁定来源和legacy parity，不把六套trainer复制成一个大仓库。无需新增第三个公共core仓库。

## 实际缺口与优先修复

| 问题                                         | 影响                            | 接入前处理                                                    |
| -------------------------------------------- | ------------------------------- | ------------------------------------------------------------- |
| OneShot/本地MD teacher-only和union未完整接线 | 配置名与实际支持集不同          | CandidateSet与producer parity；参考OPD的真实IDs路径但逐项核对 |
| current Top-K重选与old槽位配对               | 多inner时ratio对应不同token     | 冻结IDs，actor只gather                                        |
| raw partial FKL clamp                        | 负值处梯度消失                  | legacy兼容保留，新目标独立命名                                |
| teacher prompt LP固定温度1                   | 不能任意温度准确center          | capability门禁或FSDP指定IDs backend                           |
| TA backend mode dispatch不完整               | 模式在Megatron可被当FKL         | 按backend注册受支持recipe，禁止silent fallback                |
| live center与detached evidence混用           | residual反传改变                | actor-forward gradient ownership                              |
| sequence/token/reduction混用                 | 理论测度和实际batch权重不同     | 独立oracle与global sum/count                                  |
| window状态缺少完整恢复                       | stale cache/anchor与actor不一致 | 首版boundary resume，exact另做                                |

每个差异留legacy recipe和golden evidence，不把修复静默混入原benchmark。论文配置与README/launcher不一致时，保存实际resolved config并分别标注复现目标。

## 已运行实验与证据范围

[分区梯度实验设计](../experiments/2026-10-10-统一OPD分区梯度实验设计.md) 在运行前规定了问题、规模与判定。程序为 [audit_partition_gradients.py](../../experiments/analysis/audit_partition_gradients.py)，结果为 [完整枚举记录](../../results/analysis/2026-10-10-partition-gradient-audit.json)。四种词表3/17/128/2048、每种64 case、current/stale proposal、合法嵌套K，共2688行。

HETS/ResOPD/SC-TA在正确importance correction下的gradient最大坐标误差为 $3.78\times10^{-15}$。小词表独立autograd误差为 $3.55\times10^{-15}$；显式score矩阵与O(V)二阶矩实现的scaled误差为 $1.14\times10^{-12}$。完整head autograd与stopped tail错配的偏差满足head-mass gradient恒等式。

coarse KL标量没有单调性违例。梯度反例发生在V=128的case11：K从4到32，gradient bias norm从0.231067增加到0.710327。完整student/teacher分布保存于结果，支持独立复现。

832个current proposal、非空非full支持案例中，ResOPD的variance trace不高于HETS有805个，SC-TA有811个。控制项通常有收益但不保证对所有分布更优；不能把一个paper实验结论提升成无条件variance定理。此计数是synthetic固定prefix统计，不是训练效果排名。

之前的 [KL与MOPD/BPO审查](../../results/analysis/2026-10-10-opd-unification-audit.json) 已验证proposal correction、partial clamp和exact/coarse center差异。各上游审查另核对真实函数与pipeline。本轮不在已有训练占用的archbox GPU竞争运行，资源现场与后续独占性能计划见工程方案。数学枚举不能证明真实模型teacher payload、TP collectives或训练质量。

## 实施与验收顺序

1. **发布语义规格与oracle。** recipes目标、value/backward、measure、support、reduction和numerical policy成表；建立刻意等价/不等价测试。
2. **抽取小契约，不改legacy行为。** 两套teacher、existingMirror cache/loss、responsePMD通过adapter保持golden parity。
3. **修正评分与生命周期。** frozen IDs、chosen-IDquery、版本检查、完整mask/global reduction、明确outer-boundary恢复。
4. **接入tokenMirror与KL家族。** full/coarse、Mean/BPO/MDPO与HETS/ResOPD/SC-TA按独立recipe实施，针对不同算法只请求所需评分。
5. **优化内存与分布式。** 数值/梯度parity后做chunk/tiled/query复用；真实SP/TP、多teacher、EOS与replay分别验证。
6. **开源稳定版本。** package可CPU导入、独立extras与锁定backend、license/notices、patch replay CI、schema迁移、部署manifest和可复现benchmark。

首版scope限制是实现分期，不缩小最终架构能力。最终验收仍要求多KL与OPD可接入、论文/代码差异可解释、数值与系统pipeline可复现、资源与训练指标可观察、升级边界明确。

每个新recipe的最低交付是数学定义与假设、纯tensorkernel、独立value/gradientoracle、proposal/support/layout/reduction边界测试、真实backend contract、GPUcanary和固定预算配置。性能优化先证明相同gradient，再比较显存、主存、payload、latency与tokens/s；训练比较同时报告生成token、optimizer updates与walltime。
