# W&B 指标与保存策略

## 展示层与原始记录

原始 inner/outer JSONL 保持既有字段；W&B 的重命名只在上传时执行。核心映射维护在 src/mirroropd/training/tracking.py，verl 的 Tracking 仅调用这个适配器。模型训练、loss 和梯度不受展示规则影响。

[分组工作区](https://wandb.ai/wncfht/mirror-opd-pythia?nw=1wdmd1gnvqm)使用手工选定的面板，关闭自动生成。按以下顺序展示：

| 顺序 | 分组 | 默认展示 |
| --- | --- | --- |
| 01 | Quality | full-vocab 双向 KL、真实续写 NLL，置顶 |
| 02 | Off-policy | ESS fraction、最大 ratio、log-ratio RMS，置顶 |
| 03 | Optimization | clipping 前 gradient norm、score coefficient RMS |
| 04 | KL centers | Tail-aware student/teacher center 均值 |
| 05 | Entropy | student entropy |
| 06 | Support mass | anchor/student head 与 tail mass |
| 07 | Reward | sampled reward 均值与标准差 |
| 08 | Rollout | response 长度、截断率、有效 token |
| 09 | Resources | actor 耗时、outer 耗时、显存 |
| 90 | Detail extrema | residual/reward/center 的 min/max |

前四组展开，后六组折叠；前两组 pinned。全部原始统计仍然上传，但首屏展示有限数量的主要曲线。框架内部辅助量放在 99_framework，坐标放在 00_axes，不为它们自动创建面板。旧 run 的旧字段保留，新工作区只展示新分组字段。

outer 曲线使用 00_axes/outer_step，inner 曲线使用 00_axes/inner_update，独立评价使用 00_axes/evaluation_outer。它们不混用 SDK 的内部 Step。每次 inner 上传同时保留 outer 索引与本轮 inner 索引，便于对齐 hard sync。

run group 用 WANDB_RUN_GROUP 区分 budget-calibration、eta-scan 和正式对照系列；method、eta、topk 存在配置与 summary 中，用于过滤条件。已将首个预算探测的 run group 设为 budget-calibration，并加上 mdpo、k16、inner-budget、single-seed 标签。

训练入口会保存 wandb-run.json（entity/project/id/url，无凭据）。训练正常结束后，publish_wandb_diagnostics.py 将逐 inner JSONL 上传到同一 run；网络失败保留本地日志和退出状态，可以单独重试。外层仍使用原生 verl tracking 实时上传。后续离线评价完成后可再次运行 publisher；重复上传会增加 history 行，因此每次上传应注明时间并避免无目的重复。

## 保存的实际配置

旧 Pythia 配置每 8 outer 保存一份，最多保留 4 份，内容包括 model、optimizer、extra 和 hf_model。实测一组 4 checkpoint 约 873 MiB；这些权重用于旧报告的独立 full-vocab checkpoint 评价，具有审计价值。

从本次修订起，两条训练入口默认 trainer.save_freq=-1，禁止周期保存，也不触发训练末尾保存。设置 trainer.resume_mode=disable。原版 trainer 的保存分支整体要求 save_freq>0，已经核对源码。

显式启用保存时，默认 actor.checkpoint.save_contents=[model]，max_actor_ckpt_to_keep=1：只保存一份模型，不保存 optimizer/extra/HF 重复导出。这种 model-only 权重用于独立评价，不是完整可恢复训练的快照。需要恢复训练时，应显式重新启用完整状态，而不是用 model-only checkpoint 冒充断点恢复。

普通显存、吞吐、学习率稳定性探测无需持久 checkpoint。完整的独立评价当前通过 score_pythia_mdpo.sh 加载权重；不开保存时该程序会明确报错，不会只评价初始模型后声称完成最终评价。要同时获得独立模型评价与零持久 checkpoint，需要后续接入训练中 live-model evaluator，或者显式保存临时 model-only 权重、评价后核验再删除。当前实现没有把该能力伪装为已完成。

配置、模型/data revision、来源 hash、inner/outer JSONL、GPU CSV、rollout 和统计图仍保留；关闭 checkpoint 不能变成丢弃实验证据。已有历史 checkpoint 尚未删除。

## 维护入口

调整显示顺序或面板时执行 training/configure_wandb_workspace.py，并传入现有 --url，原地维护同一工作区。工具依赖远端安装的官方 wandb-workspaces==0.4.13。展示变更需要重新读取保存的 workspace，核对 section 顺序、展开与 pinned 状态。
