# W&B 指标与保存策略

## 展示层与原始记录

原始 inner/outer JSONL 保持既有字段；W&B 的重命名只在上传时执行。核心映射维护在 src/mirroropd/training/tracking.py，verl 的 Tracking 仅调用这个适配器。模型训练、loss 和梯度不受展示规则影响。

[分组工作区](https://wandb.ai/wncfht/mirror-opd-pythia?nw=1wdmd1gnvqm)使用手工选定的面板，关闭自动生成。按以下顺序展示：

| 顺序 | 分组           | 默认展示                                         |
| ---- | -------------- | ------------------------------------------------ |
| 01   | Quality        | full-vocab 双向 KL、真实续写 NLL，置顶           |
| 02   | Off-policy     | ESS fraction、最大 ratio、log-ratio RMS，置顶    |
| 03   | Optimization   | clipping 前 gradient norm、score coefficient RMS |
| 04   | KL centers     | Tail-aware student/teacher center 均值           |
| 05   | Entropy        | student entropy                                  |
| 06   | Support mass   | anchor/student head 与 tail mass                 |
| 07   | Reward         | sampled reward 均值与标准差                      |
| 08   | Rollout        | response 长度、截断率、有效 token                |
| 09   | Resources      | actor 耗时、outer 耗时、显存                     |
| 90   | Detail extrema | residual/reward/center 的 min/max                |

前四组展开，后六组折叠；前两组 pinned。全部原始统计仍然上传，但首屏展示有限数量的主要曲线。框架内部辅助量放在 99_framework，坐标放在 00_axes，不为它们自动创建面板。旧 run 的旧字段保留，新工作区只展示新分组字段。

outer 曲线使用 00_axes/outer_step，inner 曲线使用 00_axes/inner_update，独立评价使用 00_axes/evaluation_outer。它们不混用 SDK 的内部 Step。每次 inner 上传同时保留 outer 索引与本轮 inner 索引，便于对齐 hard sync。

run group 用 WANDB_RUN_GROUP 区分 budget-calibration、eta-scan 和正式对照系列；method、eta、topk 存在配置与 summary 中，用于过滤条件。已将首个预算探测的 run group 设为 budget-calibration，并加上 mdpo、k16、inner-budget、single-seed 标签。

训练入口会保存 wandb-run.json（entity/project/id/url，无凭据）。现在 inner 指标在每个 outer 的 actor 更新返回后，由 driver 直接写入已经初始化的同一个 W&B run；Ray worker 只负责写 append-only JSONL，不初始化 W&B，也不会产生重复 run。W&B SDK 的内部 step 由适配器统一递增，图表坐标仍分别使用 outer_step 和 inner_update，因此 inner/outer 都能在训练过程中实时出现。

`publish_wandb_diagnostics.py` 保留为中断训练或网络故障后的恢复工具。补传前读取服务端 history，只追加尚未出现的 inner 索引和 outer 点；测试指标仍使用 evaluation_outer。它读取 `exit-code.txt`，以实际退出码结束 W&B run，失败恢复不能把训练标成成功。正常结束的训练不执行恢复。上传失败时，inner/outer JSONL 和 `wandb-run.json` 支持重新补传。

## 保存的实际配置

旧 Pythia 配置每 8 outer 保存一份，最多保留 4 份，内容包括 model、optimizer、extra 和 hf_model。实测一组 4 checkpoint 约 873 MiB；这些权重用于旧报告的独立 full-vocab checkpoint 评价，具有审计价值。

从本次修订起，两条训练入口默认 trainer.save_freq=-1，禁止周期保存，也不触发训练末尾保存。设置 trainer.resume_mode=disable。原版 trainer 的保存分支整体要求 save_freq>0，已经核对源码。

当前训练配置另设 actor.checkpoint.save_contents=[]，并关闭 rollout 和 validation 文本落盘。显式启用 checkpoint 时，必须同时指定保存频率和保存内容；只保存 model 的权重可用于独立评价，但不是完整可恢复训练的快照。

GSM8K 入口已经接入训练中的 live-model evaluator。每 5 outer 完成 actor 更新后，trainer 将最新权重同步给 vLLM，再对固定 test 进行 greedy 生成；训练前和最后一个 outer 也进行评价。这个过程直接使用驻留模型，不生成临时 checkpoint。accuracy、答案格式、response 长度、EOS 比例和预算耗尽比例上传到 01_quality，横轴为 evaluation_outer。完整设置和验证结果见 [GSM8K 训练与周期评测](2026-10-09-GSM8K训练与周期评测.md)。

历史 Pythia 的独立 full-vocab KL 评价仍由 score_pythia_mdpo.sh 加载权重；它与 GSM8K live-model accuracy 是不同的评价。关闭 checkpoint 时，旧脚本会明确报错。

配置、模型/data revision、来源 hash、inner/outer JSONL、GPU CSV 和统计图仍保留。已有历史 checkpoint 尚未删除。

## 维护入口

调整显示顺序或面板时执行 training/configure_wandb_workspace.py，并传入现有 --url，原地维护同一工作区。工具依赖远端安装的官方 wandb-workspaces==0.4.13。展示变更需要重新读取保存的 workspace，核对 section 顺序、展开与 pinned 状态。

GSM8K 使用 `--project mirror-opd-gsm8k --quality gsm8k`。对应 [GSM8K 工作区](https://wandb.ai/wncfht/mirror-opd-gsm8k?nw=jg1sqm7q48n) 的首组显示 accuracy 与生成诊断，后续组保留 off-policy、优化、KL center 等训练曲线。

## 失败恢复的历史step与显示横轴

W&B `_step`是单个run的SDK历史计数，不等于outer或inner更新数。失败恢复从服务器已有历史的最大step继续，禁止人为加入百万偏移；当前修复同时核对run.step与scan_history的_step。已存在的百万step保留为原始上传历史，不删除或重复写入。训练曲线应使用自定义显示轴：inner使用`00_axes/inner_update`，outer使用`00_axes/outer_step`，测试使用`00_axes/evaluation_outer`。

修正后的保存视图为 [GSM8K诊断workspace](https://wandb.ai/wncfht/mirror-opd-gsm8k?nw=jg1sqm7q48n)。`nw=nwuser...`是个人视图，Workspace API不能更新；它的默认Step选择不会被保存视图自动覆盖。26duxpth只有outer0评测及16次inner，随后RAM失败，上传记录完整而训练未完成。
