## 总览

六个仓库可以分成三种实现形态。

| 形态                         | 仓库                                | 核心抽象                                                                                                              |
| ---------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| veRL distillation 插件       | TA-OPD、ResOPD                      | rollout 产生 student token；teacher 返回 top-k/采样 token；logits processor 计算逐 token surrogate；actor 再聚合 loss |
| veRL reward/advantage 扩展   | One-Shot-OPD、Rethinking-OPD 主 OPD | FSDP teacher 产生 log-ratio reward；冻结 advantage 后进入 sampled/candidate PPO loss                                  |
| 独立 loss 与 actor objective | LSPD、KLPO                          | LSPD 在 actor 中直接回归 teacher log-prob；KLPO 用历史 sampler、raw reward 和 score correction 构造 surrogate         |

共性 pipeline 是：`prompt -> student rollout -> response mask/log-prob -> teacher signal -> token/sequence objective -> actor update -> sync rollout weights`。关键差异在 teacher 信号的支持集、梯度估计方式和 rollout 是否严格 on-policy。

## TA-OPD

### 入口与 pipeline

启动入口是 [`train.sh:95`](../../upstream/TA-OPD/train.sh:95)。它调用 `verl.trainer.main_ppo`，关闭 reward 中的 KL（[`train.sh:98-99`](../../upstream/TA-OPD/train.sh:98)），用 vLLM 生成 `n=4` 条 response（[`train.sh:124-130`](../../upstream/TA-OPD/train.sh:124)），再开启 distillation、选择 teacher 和 loss mode（[`train.sh:136-147`](../../upstream/TA-OPD/train.sh:136)）。默认同时关闭 `use_task_rewards` 和 `use_policy_gradient`，所以 trainer 使用 PPO 生命周期，但训练梯度直接来自 distillation objective，并不再套一层 PPO ratio surrogate。`distillation_loss` 的 PG/direct 分支见 [`losses.py:342-374`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:342)。

完整调用链是：trainer 创建 teacher manager 并向 rollout manager 传入 client（[`ray_trainer.py:956-996`](../../upstream/TA-OPD/verl/verl/trainer/ppo/ray_trainer.py:956)）→ student generation（[`ray_trainer.py:1542`](../../upstream/TA-OPD/verl/verl/trainer/ppo/ray_trainer.py:1542)）→ agent loop 对完整 student 序列查询 teacher 并回填 top-k/sample score（[`agent_loop.py:920-944`](../../upstream/TA-OPD/verl/verl/experimental/agent_loop/agent_loop.py:920)）→ actor loss 两阶段处理 → update actor（[`ray_trainer.py:1730`](../../upstream/TA-OPD/verl/verl/trainer/ppo/ray_trainer.py:1730)）→ 同步 rollout weights（[`ray_trainer.py:1760`](../../upstream/TA-OPD/verl/verl/trainer/ppo/ray_trainer.py:1760)）。teacher 请求用 `prompt_logprobs=K` 和 `max_tokens=1` 评分已有序列，teacher score 与下一个 token 对齐；并非拿 teacher 新生成的 response 当训练标签（[`teacher_manager.py:30-42`](../../upstream/TA-OPD/verl/verl/experimental/teacher_loop/teacher_manager.py:30)、[`teacher_manager.py:211-212`](../../upstream/TA-OPD/verl/verl/experimental/teacher_loop/teacher_manager.py:211)）。

loss 的总调度位于 [`verl/verl/trainer/distillation/losses.py:172-239`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:172)。`compute_topk_loss` 按 strategy 选择 FSDP/VeOmni 或 Megatron 实现，并按 `loss_mode` 分派 `reverse_kl_topk`、`taopd_reverse_kl_topk`、`normalized_reverse_kl_topk`、`sample_corrected_ta_opd` 等算法。`distillation_ppo_loss` 明确区分两次调用：student logits 非空时，在 logits processor 阶段得到逐 token distillation loss；否则在 actor policy-loss 阶段把它与 PPO/任务项合并（[`losses.py:242-277`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:242)）。

TA-OPD 的注册抽象是 `DistillationLossSettings` + registry。每个 loss 声明是否需要 top-k、是否需要 sampled log-prob，注册后由名称查找函数（[`losses.py:84-155`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:84)）。这使算法选择成为 Hydra 配置，而不是修改 trainer 主循环。

### 数学与数据抽象

TA-OPD 的命名算法是 `compute_taopd_reverse_kl_topk`，核心在 [`fsdp/losses.py:557-627`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:557)。令 $S=\operatorname{TopK}(q)$，$p_B=1-\sum_{v\in S}p_v$、$q_B=1-\sum_{v\in S}q_v$，它计算

$$
L_{\mathrm{TA}}=\sum_{v\in S}p_v\log\frac{p_v}{q_v}+p_B\log\frac{p_B}{q_B}.
$$

student 用 full vocabulary `logsumexp` 归一化，在 teacher head id 上 gather，再用 `log1mexp(logsumexp(head_logp))` 得到 tail log-mass，最后把 tail 当作第 $K+1$ 个类别。head 保留原始概率，tail 保留全部剩余质量。这个 coarsened reverse KL 省去了 tail 内部各 token 的区别；完整 reverse KL 满足

$$
D_{\mathrm{KL}}(p\Vert q)=L_{\mathrm{TA}}+p_BD_{\mathrm{KL}}(p(\cdot\mid B)\Vert q(\cdot\mid B)).
$$

实现的 `log1mexp` 先将输入 clamp 到不超过 `-1e-6`，因此 tail 接近零的边界是数值稳定近似，不是所有输入上的 literal exact arithmetic（[`fsdp/losses.py:477-489`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:477)）。

sample-corrected 变体正是针对后一项的条件 log-ratio 引入 sampled action correction；因此应区分 TA 的 deterministic coarsened KL 和 SC-TA 的 score-gradient surrogate。

TA-OPD 的默认 teacher payload 是每个 prefix 的 teacher top-k ids/log-probs；FSDP loss 接收 `(student_logits, teacher_topk_log_probs, teacher_topk_ids)`（[`fsdp/losses.py:118-130`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:118)）。`sample_corrected_ta_opd` 将 teacher top-k 之外的实际 rollout token 作为 tail 样本，并用 `exp(student_logp_y - behavior_logp_y)` 作为 off-policy importance ratio；无 behavior log-prob 时用 `exp(student_logp_y - student_logp_y.detach())`，其 forward 值为 1、梯度保留 action score（[`fsdp/losses.py:60-115`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:60)）。

当前 checkout 还接入了 MirrorOPD cache 路径：`mirror_pmd_mean`、`mirror_bpo`、`mirror_mdpo`、`mirror_opd_onpolicy`、`mirror_opd_is` 和 `mirror_opd_is_no_baseline` 被转交给 `compute_mirror_opd_from_cache`（[`losses.py:194-199`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:194)）。teacher 配置同时保留 native teacher pool 字段，但 `mirror_teacher_model_path` 明确用于冻结 FSDP teacher cache（[`distillation.yaml:13-18`](../../upstream/TA-OPD/verl/verl/trainer/config/distillation/distillation.yaml:13)）。

Mirror 模式是本地集成扩展；本地 `origin/master` 为 `62669afb5101bfdf57dc5ddf81e78f000c5ce2fc`，behavior-aware SC correction 已存在于该基线。当前 Mirror FSDP wrapper 导入主仓库 `mirroropd.training`/`mirroropd.integrations.verl`（[`fsdp/losses.py:19-28`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:19)），最终 policy loss 直接返回其 surrogate，并禁止 PPO 包装、task reward 和 clamp（[`losses.py:284-294`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:284)、[`losses.py:380-405`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:380)）。

SC-TA 的一个配置缺陷可以直接从当前代码确定：`use_policy_gradient=True` 时 `behavior_logp_y` 被置为 `None`，后面却无条件调用 `.detach()`，会在进入 correction 前报错（[`losses.py:592-604`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:592)）。默认 direct 配置不走该分支；审阅不能因此把 PG 模式列成已验证可用的组合。

### 判断

TA-OPD 最强的工程抽象是“loss registry + logits-processor 两阶段接口”；它能把完整 vocabulary 的梯度估计、top-k 近似、sample correction 和 Mirror cache 接到同一套 veRL actor 生命周期。代价是算法语义分散在 `losses.py`、FSDP kernel、teacher payload 和配置中，读代码时必须沿分派链追踪。

## ResOPD

### 入口与 pipeline

ResOPD 的入口是 [`examples/resopd/run_resopd.sh:60-78`](../../upstream/ResOPD/examples/resopd/run_resopd.sh:60)，配置 vLLM teacher、`loss_mode=resopd` 和 teacher top-k。README 明确要求 FSDP/FSDP2/VeOmni student、vLLM teacher；Megatron、SGLang、fused kernel 和 chunked top-k 在该 release 不启用（[`README.md:212-228`](../../upstream/ResOPD/README.md:212)）。脚本关闭 policy gradient、task reward 和两种 loss/log-prob clamp；最终 policy-loss 分支直接跳过 PPO（[`losses.py:259-265`](../../upstream/ResOPD/verl/trainer/distillation/losses.py:259)）。

teacher 服务对已生成的 student 序列设置 `prompt_logprobs=K`（[`teacher_manager.py:36-57`](../../upstream/ResOPD/verl/experimental/teacher_loop/teacher_manager.py:36)）；vLLM payload parser 保留实际 action 的分数，并按 rank 区分 head 与额外 sampled action（[`prompt_logprobs.py:27-64`](../../upstream/ResOPD/verl/workers/rollout/vllm_rollout/prompt_logprobs.py:27)）。rollout agent loop 再把它们写为 `teacher_logprobs`、`teacher_ids`、`teacher_sampled_logprobs`、`teacher_sampled_ids` 并合并 batch（[`agent_loop.py:1026-1081`](../../upstream/ResOPD/verl/experimental/agent_loop/agent_loop.py:1026)）。这是 ResOPD 区别于普通 top-k distillation 的数据接口：actual action 在 head 外时也必须有 teacher score。

trainer 的关键顺序是 student generation（[`ray_trainer.py:1513`](../../upstream/ResOPD/verl/trainer/ppo/ray_trainer.py:1513)）、teacher payload 随 rollout batch 回传、actor update（[`ray_trainer.py:1690`](../../upstream/ResOPD/verl/trainer/ppo/ray_trainer.py:1690)）、rollout weight sync（[`ray_trainer.py:1715-1716`](../../upstream/ResOPD/verl/trainer/ppo/ray_trainer.py:1715)）。入口把 mini-batch 设为完整 train batch、`ppo_epochs=1`、n=1、temperature=1、top-p=1 和 top-k=-1，直接落实 single-update/full-support 假设（[`run_resopd.sh:43-56`](../../upstream/ResOPD/examples/resopd/run_resopd.sh:43)）。

loss 注册在 [`verl/trainer/distillation/losses.py:124-170`](../../upstream/ResOPD/verl/trainer/distillation/losses.py:124)。当 mode 是 `resopd`，它额外取 teacher 对实际 student action 的 log-prob 和 token id，再调用 FSDP 适配器；普通 mode 仍走 forward-KL top-k。统一的 `distillation_ppo_loss` 仍采用“logits processor 先算 per-token，再由 distillation loss 聚合”的 veRL 契约（[`losses.py:217-257`](../../upstream/ResOPD/verl/trainer/distillation/losses.py:217)）。

### ResOPD estimator

核心在 [`resopd.py:26-53`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:26)。输入必须同时包含 teacher top-k support `S` 和实际动作 `A` 的 teacher score；teacher top-k 概率不在 support 内重新归一化。代码先计算 student 在 support 上的 log-prob、support mass 和 support ratio（[`resopd.py:66-84`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:66)），再由 student/teacher tail mass 得到 aggregate tail correction（[`resopd.py:86-94`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:86)）。

最终 surrogate 用 `head_hit` 做分支，并以 `centered_event = 1[A in S] - P(S)` 做控制变量中心化（[`resopd.py:96-102`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:96)）。所以它不是把 top-k KL 当作确定性 loss，而是“top-k coarse gradient + tail bucket + tail-hit sampled residual”。README 给出的等价估计量是 exact coarse gradient 加上 `1[A not in S](r_A s_A - mu_B)`（[`README.md:187-204`](../../upstream/ResOPD/README.md:187)）。

### 判断

ResOPD 的抽象边界很清楚：teacher 只传 sparse support 和 observed-token score，student 仍做 full-vocabulary normalization；通信稀疏化不等于 student 计算稀疏化（[`README.md:224-228`](../../upstream/ResOPD/README.md:224)）。无偏性依赖 full-support、当前 student 分布采样和每个 rollout 只更新一次；README 明确警告 truncated sampling、stale rollout 和重复优化需要另行修正（[`README.md:206-210`](../../upstream/ResOPD/README.md:206)）。

更精确地说，这是固定 visited prefix 上的 conditional reverse-KL gradient 估计器。令 $s_A=\nabla\log p(A)$、$r_A=\log(p(A)/q(A))$，$g_S=\sum_{v\in S}p_vr_vs_v$，$\mu_B=\log(p_B/q_B)\nabla\log p_B$，其梯度可写为

$$
\widehat g=g_S+p_B\mu_B+\mathbf1[A\notin S](r_As_A-\mu_B).
$$

当 $A\sim p$ 时，$\mathbb E[\mathbf1[A\notin S]\mu_B]=p_B\mu_B$，两项抵消，剩余 $g_S+\sum_{A\in B}p_Ar_As_A=\nabla D_{\mathrm{KL}}(p\Vert q)$。这里使用了 $\sum_Ap_As_A=0$ 消去 reverse-KL 导数中的常数项。这个证明针对固定 prefix；它没有额外求导整个 rollout 的 state visitation distribution。源码用 stopped coefficients 实现该梯度，并以 `value.detach() + surrogate - surrogate.detach()` 保留独立 forward 数值（[`resopd.py:96-102`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:96)）。

## One-Shot-OPD

### 入口与 pipeline

共享脚本把三种 recipe 都接到 `python -m verl.trainer.main_ppo`，并通过 `trainer.use_v1=False` 走 veRL 旧版 PPO trainer（[`recipe/_common.sh:1-9`](../../upstream/One-Shot-OPD/recipe/_common.sh:1)）。`opd.sh` 按 `DOMAIN` 选择 actor/teacher/data，按 `MODE=full|oneshot|template` 选择 prompt 来源（[`recipe/opd.sh:17-62`](../../upstream/One-Shot-OPD/recipe/opd.sh:17)），最后把公共参数、mode 参数和单 teacher 参数传给 `launch`（[`recipe/opd.sh:81-116`](../../upstream/One-Shot-OPD/recipe/opd.sh:81)）。

公共参数设置 `algorithm.adv_estimator=token_reward_direct`、vLLM rollout、`calculate_log_probs=True`、`policy_loss.loss_mode=vanilla` 或 `vanilla_topk`（[`recipe/_common.sh:173-228`](../../upstream/One-Shot-OPD/recipe/_common.sh:173)）。teacher 通过 `distillation.fsdp_teacher.enabled=True`、teacher temperature、top-k strategy 和 reward weight mode 注入（[`recipe/_common.sh:255-289`](../../upstream/One-Shot-OPD/recipe/_common.sh:255)）。

### 单 teacher 与多 teacher

README 把 OPD 定义为 teacher reverse-KL reward，MOPD 则按 `ability` 列逐行路由到多个 teacher（[`README.md:60-76`](../../upstream/One-Shot-OPD/README.md:60)）。`mopd.sh` 设置 `ABILITY_TO_TEACHER`、三个 teacher path 和多数据集 train files（[`recipe/mopd.sh:24-48`](../../upstream/One-Shot-OPD/recipe/mopd.sh:24)），然后将 name:path 对传给 `multi_teacher_args`（[`recipe/mopd.sh:58-67`](../../upstream/One-Shot-OPD/recipe/mopd.sh:58)）。

默认 `LOG_PROB_TOP_K=0` 时是 sampled-token OPD；大于零时 top-k 进入训练 reward，`METRIC_TOP_K` 只影响 observability（[`recipe/_common.sh:69-82`](../../upstream/One-Shot-OPD/recipe/_common.sh:69)）。框架内实际新增了 OPD teacher worker、trainer mixin、direct-token advantage、3-D policy-loss kernel 和 FSDP engine top-k hook。recipe/data coverage 是一层，teacher-to-actor 的训练接线是另一层。

### 主训练代码链与张量合同

1. `OpdTrainerMixin.register_opd_teacher` 将 forward-only FSDP teacher colocate 在 actor resource pool；teacher 参数在微批之间 CPU offload（[`opd_trainer_mixin.py:90-109`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_trainer_mixin.py:90)）。teacher 是独立 worker，不是 rollout vLLM 内的模型。
2. trainer 计算 `old_log_probs` 时，让 student engine 同时返回 `[B,T,K]` candidate ids/log-prob（[`ray_trainer.py:1324-1354`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/ray_trainer.py:1324)）。engine 用 top-k logits 减 full-vocabulary `logsumexp`，而不是在 top-k 内重新归一化 student 概率（[`transformer_impl.py:1303-1324`](../../upstream/One-Shot-OPD/verl/verl/workers/engine/fsdp/transformer_impl.py:1303)）。
3. teacher 按数据行 `ability` 路由、分组 forward 并 scatter 回原行序（[`fsdp_teacher_worker.py:331-416`](../../upstream/One-Shot-OPD/verl/verl/workers/fsdp_teacher_worker.py:331)）。多个 rank 同步每个 teacher 的微批次数，空 rank 也执行 dummy forward，保持 FSDP collective 调用顺序一致。
4. teacher 输出 sampled `[B,T]` 或 candidate `[B,T,K]` reward。trainer 将 verifier score 保存在 `true_token_level_scores`，用 teacher reward 覆盖 `token_level_scores`（[`opd_trainer_mixin.py:175-197`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_trainer_mixin.py:175)）。
5. `token_reward_direct` 在 `no_grad` 下把 masked token reward 原样作为 advantage/return；没有累加未来 token reward、GAE 或 value critic（[`opd_core_algos.py:53-78`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_core_algos.py:53)）。另一个 `token_reward_direct_plus_grpo` 分支将 verifier 的 GRPO outcome advantage 加回来（[`opd_core_algos.py:81-125`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_core_algos.py:81)）。
6. actor 的 PPO loss hook 在 top-k 模式中切换为 candidate log-prob（[`workers/utils/losses.py:64-123`](../../upstream/One-Shot-OPD/verl/verl/workers/utils/losses.py:64)），`vanilla_topk` 在每个 candidate 上计算 ratio/clipping，然后沿 K 轴求和，再用 response mask 聚合（[`opd_core_algos.py:128-187`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_core_algos.py:128)）。

sampled 默认 reward 为 $r_t=\log q(a_t\mid h_t)-\log p_0(a_t\mid h_t)$（[`fsdp_teacher_worker.py:418-421`](../../upstream/One-Shot-OPD/verl/verl/workers/fsdp_teacher_worker.py:418)）。top-k 则对每个 candidate $v$ 构造冻结 advantage：

$$
A_{t,v}=-w_{t,v}\left[\log p_0(v\mid h_t)-\log q(v\mid h_t)\right],\qquad \rho_{t,v}=\frac{p_\theta(v\mid h_t)}{p_0(v\mid h_t)},
$$

$$
L_t=\sum_v\max\{-A_{t,v}\rho_{t,v},-A_{t,v}\operatorname{clip}(\rho_{t,v},1-\epsilon_-,1+\epsilon_+)\}.
$$

`student_p`/`teacher_p` 使用 respective log-prob 在有效 candidate 集上归一化，`none` 是均匀权重；`union-intersection` 保留 raw probability 权重（[`fsdp_teacher_worker.py:134-198`](../../upstream/One-Shot-OPD/verl/verl/workers/fsdp_teacher_worker.py:134)）。冻结 advantage 的 ratio surrogate，与对当前分布的 literal KL 自动微分有明确区别。

### 支持集冻结与配置缺口

更新时 engine 重新从当前 logits 取 top-k，没有使用永久固定的 candidate id。因此 mixin 拒绝 top-k reward 的多 epoch 或小于 rollout batch 的 mini-batch，要求单完整 mini-batch、单 epoch（[`opd_trainer_mixin.py:145-169`](../../upstream/One-Shot-OPD/verl/verl/trainer/ppo/opd_trainer_mixin.py:145)）。这是 candidate 对齐约束；metric-only top-k 不改变训练 reward，不受同一约束。

配置枚举不能等同于五种完整支持集实现。当前 teacher scoring 只收集 teacher 在 student support 上的 log-prob 和 overlap mask，reward 总是接收 student support 的两个 K 列张量（[`fsdp_teacher_worker.py:402-443`](../../upstream/One-Shot-OPD/verl/verl/workers/fsdp_teacher_worker.py:402)）。`compute_top_k_reward` 的结果如下。

## Rethinking-OPD

### 主 OPD recipe

顶层 [`on_policy_distillation.sh:171-225`](../../upstream/Rethinking-OPD/on_policy_distillation.sh:171) 直接启动 `verl.trainer.main_ppo`，配置 actor/teacher model、vLLM rollout、`log_prob_top_k`、`top_k_strategy`、`reward_weight_mode` 和 teacher temperature。默认是 `token_reward_direct`、K=16、`only_stu`、`student_p`（[`on_policy_distillation.sh:40`](../../upstream/Rethinking-OPD/on_policy_distillation.sh:40)、[`on_policy_distillation.sh:61-63`](../../upstream/Rethinking-OPD/on_policy_distillation.sh:61)）。teacher 由 FSDP `RewardModelWorker` 持有；虽叫 reward model，实际加载的是 `AutoModelForCausalLM`（[`fsdp_workers.py:1720-1762`](../../upstream/Rethinking-OPD/verl/verl/workers/fsdp_workers.py:1720)），不是主 OPD 的远程 vLLM teacher。

### 主 OPD 的 reward/advantage/actor 链

student rollout 后，actor 重新 forward 获得 old action log-prob 和 student top-k payload，trainer 写入 strategy/temperature 等 metadata，调用 teacher `compute_rm_score`；K>0 时再由 actor `compute_distillation_reward` 组装 candidate reward（[`ray_trainer.py:1105-1144`](../../upstream/Rethinking-OPD/verl/verl/trainer/ppo/ray_trainer.py:1105)）。teacher worker 在 K>0 路径返回 sparse payload，K=0 才直接返回 sampled log-ratio reward（[`fsdp_workers.py:2712-2737`](../../upstream/Rethinking-OPD/verl/verl/workers/fsdp_workers.py:2712)）。

actor 在需要 teacher head 时再次 forward student，计算 student 在 teacher ids 上的 log-prob（[`dp_actor.py:451-506`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:451)），然后建立以下支持集。这里 $S$ 为 student top-k，$T$ 为 teacher top-k；概率本身仍由 full vocabulary 归一化，candidate reward 权重单独归一化。

| strategy             | 支持集         | 权重处理                                             | 源码                                                                                           |
| -------------------- | -------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `only_stu`           | $S$            | 在 $S$ 归一化                                        | [`dp_actor.py:560-564`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:560) |
| `only_tch`           | $T$            | 在 $T$ 归一化                                        | [`dp_actor.py:566-571`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:566) |

| `union-intersection` | $S\triangle T$ | raw student/teacher probability；`none` 时有效项为 1 | [`dp_actor.py:601-621`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:601) |

所有策略产生 $A_{t,v}=-w_{t,v}(\log p_0(v\mid h_t)-\log q(v\mid h_t))$，weight function 在 [`dp_actor.py:522-556`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:522)。`token_reward_direct` 在 `no_grad` 下直接返回 masked reward，不做未来回报累积（[`core_algos.py:854-880`](../../upstream/Rethinking-OPD/verl/verl/trainer/ppo/core_algos.py:854)）。actor 用 batch 中保存的 student/union ids 重算当前 candidate log-prob（[`dp_actor.py:828-841`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:828)），再交给支持 3-D candidate axis 的 clipped/dual-clipped PPO loss（[`core_algos.py:1122-1190`](../../upstream/Rethinking-OPD/verl/verl/trainer/ppo/core_algos.py:1122)）。`teacher_p` 因而是 teacher-weighted log-ratio advantage，也不是下节 GKD 的直接 forward-KL objective。

与 One-Shot 不同，这条 actor 路径保存并复用 candidate ids，可避免重新 top-k 造成的列错位。不过 `only_tch` 的 off-policy 分支有另一处缺口：reward 保存 `union_top_k_ids=T_ids`，没有保存同一 support 的 `union_top_k_log_probs=S_on_T`（[`dp_actor.py:566-571`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:566)）；更新端在缺少这个字段时回退到 student head 上的 `student_top_k_log_probs`，导致分子在 teacher token、分母在 student token（[`dp_actor.py:867-873`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:867)）。单完整 mini-batch、单 epoch 的 on-policy 分支使用 current log-prob detach 作分母，避开这个字段回退（[`dp_actor.py:854-875`](../../upstream/Rethinking-OPD/verl/verl/workers/actor/dp_actor.py:854)）；不能把这一局部支持推断为任意多步更新都正确。

### GKD/远程 teacher 实现

以下 `verl/recipe/gkd` 是仓库随带的另一条 recipe，由 `main_gkd.py`/专用 trainer 启动；主 `on_policy_distillation.sh` 调用的是 `verl.trainer.main_ppo`。两条路径必须分开阅读，GKD 的远程 teacher、forward-KL kernel 和 async scheduler 不能归为主 OPD 的实现。

仓库还包含更明确的 `verl/recipe/gkd` 实现。其 README 将目标写成 teacher top-k support 上的 token-wise `KL(P||Q)`（[`recipe/gkd/README.md:13-22`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:13)）。pipeline 是 actor 参数同步、vLLM rollout、ZeroMQ teacher service 返回 top-k、Megatron actor 的 TP-aware KL kernel、最后 optimizer step（[`README.md:58-65`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:58)）。

teacher client 从有效 input ids 构造微批请求，收集 future 返回的 `teacher_topk_logps` 和 `teacher_topk_indices`，再按 attention mask 填回 padded DataProto（[`teacher_utils.py:50-138`](../../upstream/Rethinking-OPD/verl/recipe/gkd/teacher_utils.py:50)）。actor 的 logits processor 只在 `calc_kl_mask` 的有效位置调用 `vocab_parallel_kl_divergence`（[`megatron_workers.py:306-324`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_workers.py:306)）。

TP kernel 在各 rank 上做 stable normalization、将 global teacher ids 映射到 local vocab shard、计算 teacher sparse distribution 与 student probabilities 的 forward KL，再 all-reduce per-token loss（[`megatron_kl_loss.py:38-117`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_kl_loss.py:38)）；backward 是 `student_probs - teacher_sparse_probs` 乘上 upstream gradient（[`megatron_kl_loss.py:127-145`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_kl_loss.py:127)）。

这段 kernel 存在 forward/backward 数学差异。teacher 端直接返回 vLLM top-k log-prob（[`teacher/vllm_engine.py:174-189`](../../upstream/Rethinking-OPD/verl/recipe/gkd/teacher/vllm_engine.py:174)），kernel 中的 target normalization 被注释（[`megatron_kl_loss.py:40-42`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_kl_loss.py:40)）。设 head mass $m_S=\sum_{v\in S}q_v$，当前 forward 是

$$
L_S=\sum_{v\in S}q_v(\log q_v-\log p_v).
$$

softmax 满足 $\partial\log p_v/\partial z_j=\mathbf1[v=j]-p_j$，所以该 forward 的正确导数为

$$
\frac{\partial L_S}{\partial z_j}=-\sum_{v\in S}q_v(\mathbf1[v=j]-p_j)=m_Sp_j-\mathbf1[j\in S]q_j.
$$

手写 backward 却使用 $p_j-\mathbf1[j\in S]q_j$，二者相差 $(1-m_S)p_j$；只有 $m_S=1$ 时一致。这是当前源码与规范 sparse forward objective 之间的静态差异，不能把 README 的 `KL(P||Q)` 表述直接当作 kernel 的梯度正确性证明。本次没有修改该上游 kernel，也没有进行分布式 GPU 验证。

### 异步抽象

GKD 支持 zero-step、one-step-off 和 two-step-off scheduler。one-step-off 重叠 rollout 与 actor update，并同时进行 weight sync 与 teacher retrieval；two-step-off 允许 teacher 更慢时继续交错 rollout/update（[`recipe/gkd/README.md:26-50`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:26)）。实际 `GenerationBatchFuture` 提交生成与 teacher future 的代码位于 [`ray_trainer.py:340-390`](../../upstream/Rethinking-OPD/verl/recipe/gkd/ray_trainer.py:340)，两个 scheduler 位于 [`ray_trainer.py:392-459`](../../upstream/Rethinking-OPD/verl/recipe/gkd/ray_trainer.py:392) 和 [`ray_trainer.py:461-531`](../../upstream/Rethinking-OPD/verl/recipe/gkd/ray_trainer.py:461)。这会牺牲严格 on-policy 的新鲜度换取吞吐，属于 pipeline 语义变化；实现必须单独审查 batch 版本与 weight sync 顺序。

## LSPD

### 入口与训练形态

`train_lspd.sh` 和 `train_lspd_rb.sh` 都调用共享 [`scripts/train.py:25-82`](../../upstream/LSPD/scripts/train.py:25)，通过 `--method LSPD|LSPD-RB` 选择是否启用 replay。脚本把 loss mode 固定为 `opd_squared_logprob`，并设置 entropy coefficient、log-ratio clip、candidate weighting、penalty mode 和 replay 参数（[`scripts/train.py:75-121`](../../upstream/LSPD/scripts/train.py:75)）。

启动器最终执行 `verl.trainer.main_ppo`（[`scripts/train.py:235-265`](../../upstream/LSPD/scripts/train.py:235)）。默认数据流是 student rollout → FSDP teacher 在完整序列上评分 → 保存 sampled teacher target → 普通或 replay actor update。teacher `compute_rm_score` 即使另外产生 log-ratio reward，仍将实际 action 的 teacher log-prob 独立保留为 `teacher_sample_log_probs`（[`fsdp_workers.py:2950-2973`](../../upstream/LSPD/verl/verl/workers/fsdp_workers.py:2950)）；平方 objective 直接消费这个 target，而不是消费 reward/advantage。

### LSPD objective

核心函数是 [`core_algos.py:981-1024`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:981)。2-D 输入表示 sampled rollout action，3-D 输入表示显式 candidate set；teacher log-prob 停止梯度，目标是 response token 上的 squared log-ratio penalty 减 student entropy bonus。实际 ratio、candidate weight 和 penalty 在 [`core_algos.py:1069-1128`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1069) 计算，支持 `uniform`、`student_p`、`teacher_p`、`mixture_p` 以及 squared/clamp/huber 变体。

LSPD 的 2-D 路径对采集时的 action 分布做 Monte Carlo 平均；默认入口显式使用 temperature=1、top-p=1、top-k=-1、repetition penalty=1 和 `log_prob_top_k=0`（[`scripts/train.py:128-144`](../../upstream/LSPD/scripts/train.py:128)）。所以初始采集覆盖 full vocabulary，且不再额外乘一次 action probability（[`core_algos.py:1069-1085`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1069)）。更新时 action 和 prefix 都固定，只有 current log-prob 的梯度；这是一种采样后直接回归的 surrogate。它不包含采样测度随参数变化的 score-function 项，不能直接等同于完整 $\nabla_\theta\mathbb E_{a\sim p_\theta}[(\log p_\theta-\log q)^2]$。双 rollout 扩展支持 `opd_rollout_source=0|1`，source 权重在 [`core_algos.py:1104-1116`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1104) 真正作用于 penalty 和 entropy；默认 launcher 选择单 student rollout。

LSPD 还把 EOS 与 tokenizer 兼容性作为 estimator 合同的一部分：preflight 要求 student/teacher 共享 vocabulary、non-thinking chat template，并固定 student EOS `151643`、teacher EOS `151645`（[`lspd/preflight.py:6-19`](../../upstream/LSPD/lspd/preflight.py:6)）。forward 前将 teacher EOS 的 logit mass 合并到 student EOS，再把 teacher EOS 置为数值零，见 [`verl/utils/torch_functional.py:249-278`](../../upstream/LSPD/verl/verl/utils/torch_functional.py:249)。这一步改变了 teacher conditional，不能在复现实验时只记录模型路径而省略 tokenizer/EOS 配置。

### LSPD-RB replay

Ray trainer 初始化 bounded `DataProtoReplayBuffer`（[`ray_trainer.py:423-430`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:423)），只保存可重算平方 loss 和 entropy 所需字段（[`ray_trainer.py:1213-1242`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:1213)），每个 rollout 后独立采样并执行配置次数的 actor updates（[`ray_trainer.py:1252-1290`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:1252)）。这使 LSPD-RB 成为带固定 teacher target 的 off-policy replay；buffer 实际不保存 behavior log-prob，actor 明确不消费 PPO old-log-prob 和 advantage（[`dp_actor.py:803-834`](../../upstream/LSPD/verl/verl/workers/actor/dp_actor.py:803)）。它重算当前 student log-prob 与 entropy，保留 teacher target；不能把它描述成重要性采样修正的 replay。

buffer 的抽象是 CPU 上按轨迹行保存的 FIFO chunks：追加时复制并淘汰最旧行；一次 sample 使用私有 RNG 的 `randperm`，在该 batch 内无放回均匀采样，多次 update 间可以重复选中同一行（[`replay_buffer.py:46-118`](../../upstream/LSPD/verl/verl/trainer/ppo/replay_buffer.py:46)）。trainer 先存入本轮 teacher-scored batch，再选择普通 actor update 或 replay update（[`ray_trainer.py:2639-2662`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:2639)）。

### Loss 与框架的连接

actor 的 `update_policy` 根据 loss mode 选择 sampled `teacher_sample_log_probs` 或 candidate `teacher_on_student_log_probs`，然后直接调用 `compute_opd_squared_logprob_objective`，不通过一般 PPO policy-loss registry 的分支（[`dp_actor.py:1026-1060`](../../upstream/LSPD/verl/verl/workers/actor/dp_actor.py:1026)）。平方 penalty 与 entropy 都先在每条 response 的有效 token 上求均值，再在 response 间求均值，固定为 `seq-mean-token-mean`（[`core_algos.py:1118-1128`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1118)）。

默认 2-D、squared 模式的 batch 目标可以写为

$$
L_{\mathrm{LSPD}}=\frac1B\sum_{i=1}^{B}\frac1{T_i}\sum_{t=1}^{T_i}\left[(\log p_\theta(a_{it}\mid h_{it})-\operatorname{sg}\log q(a_{it}\mid h_{it}))^2-\lambda H(p_\theta(\cdot\mid h_{it}))\right].
$$

clamp 模式先截断 log-ratio 再平方，超过阈值的 penalty 梯度为零；Huber 模式在阈值外保持线性 penalty 和非零有界梯度（[`core_algos.py:1087-1098`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1087)）。这项 clipping 是 log-ratio regression 的定义，与 PPO probability-ratio clipping 是不同操作。

## KLPO

### 核心数据合同

KLPO 的 [`klpo/loss.py:1-8`](../../upstream/KLPO/klpo/loss.py:1) 明确：没有 IS multiplier、reward centering、ratio clipping、critic、admission mask 或 trajectory-length normalization；返回 scalar 是 backward surrogate，不一定是 regression loss。每行必须是完整 trajectory，当前 log-prob 保持 autograd，历史 sampler log-prob 固定。

### 两条 route、四种 KL estimator

库将 route 与 KL estimator 解耦。token regression 使用每 token 系数 `h=R-beta*ell`；sequence regression 使用整条 trajectory residual。实现暴露 binary、full、top-k 和 MC 四种 estimator；API/组合表见 [`docs/algorithms.md:73-111`](../../upstream/KLPO/docs/algorithms.md:73)。

默认 token+MC-KL 的 auxiliary draw 是每个 prefix 独立、可重复采样的 M 个 token，`k_MC=mean(log q(v)-log p(v))`，不把 rollout action 当作 draw，也不 renormalize/deduplicate（[`docs/algorithms.md:19-40`](../../upstream/KLPO/docs/algorithms.md:19)）。实现中 MC 分支取 `mean(q_log-p_log.detach())`，loss 为 `-h * (current - mean sampled logp)`（[`klpo/loss.py:284-302`](../../upstream/KLPO/klpo/loss.py:284)）。

sequence full-KL 直接在 `[B,T,V]` conditional 上计算 `q*(log q-log p)`，用 detached trajectory residual 乘 `current + local_kl`（[`klpo/loss.py:76-110`](../../upstream/KLPO/klpo/loss.py:76)）。sequence TopK-KL 保留 K 个 head 并把余量聚成 tail，tail mass 用 `tail_floor` 稳定；代码明确对 literal stabilized KL 反传（[`klpo/loss.py:113-170`](../../upstream/KLPO/klpo/loss.py:113)）。token loss 的 MC/full/top-k/binary 分派和 detached coefficient 位于 [`klpo/loss.py:281-353`](../../upstream/KLPO/klpo/loss.py:281)。

### 与 OPD 的关系

KLPO 不把 teacher top-k 直接当作 forward-KL target；它把历史 sampler `q`、当前 policy `p`、terminal reward `R` 和 KL coefficient `beta` 组成 critic-free regression surrogate。它最接近“policy-loss 内核”，可由 rollout/trainer 提供满足采集合同的 log-prob records。TA-OPD/ResOPD 使用 teacher sparse payload 与 distillation hook；One-Shot/Rethinking 主 OPD 使用冻结 log-ratio advantage。KLPO 的 sequence MC 路径要求 `M>=2` 做 leave-one-out，token MC 则 `M>=1`，这是它区别于普通 sampled-token OPD 的关键统计设计（[`docs/algorithms.md:179-199`](../../upstream/KLPO/docs/algorithms.md:179)）。

### 默认目标的逐步解释

本节以 $q$ 表示历史 sampler，$p_\theta$ 表示当前 trainer。在固定历史 $h_t$ 上，先定义 action log-ratio 与 local KL：

$$
\ell_t=\log p_\theta(a_t\mid h_t)-\log q(a_t\mid h_t),\qquad k_t=D_{\mathrm{KL}}(q(\cdot\mid h_t)\Vert p_\theta(\cdot\mid h_t)).
$$

由于 $q$ 固定，local KL 的梯度为

$$
\nabla_\theta k_t=-\sum_v q(v\mid h_t)\nabla_\theta\log p_\theta(v\mid h_t).
$$

所以 corrected action score 是 $\nabla\log p_\theta(a_t)+\nabla k_t$，即减去 historical sampler 下的平均 score。实现默认以独立 $v_{tj}\sim q(\cdot\mid h_t)$ 抽样近似后者：

$$
L_{\mathrm{token,MC}}=-\frac1B\sum_i\sum_t\operatorname{sg}(R_i-\beta\ell_{it})\left[\log p_\theta(a_{it}\mid h_{it})-\frac1M\sum_{j=1}^{M}\log p_\theta(v_{itj}\mid h_{it})\right].
$$

代码中的 `h` 在 `torch.no_grad()` 中构造，当前 action 和 auxiliary-token log-prob 两项保留梯度（[`loss.py:281-295`](../../upstream/KLPO/klpo/loss.py:281)）。历史概率用来生成独立 draw 和定义 $\ell_t$，不再给每个 draw 额外乘一次 $q(v)$，因为采样频率已经提供 $q$ 的权重。$M=1$ 已经能无偏估计这一条件 score correction；MC 的负 KL 数值和重复 token id 都是允许的。

sequence route 则先把轨迹各 token 的 log-ratio 与 local KL 加总：

$$
D_i=R_i-\beta\sum_t(\ell_{it}+k_{it}),\qquad L_{\mathrm{sequence}}=-\frac1B\sum_i\operatorname{sg}(D_i)\sum_t[\log p_\theta(a_{it}\mid h_{it})+k_{it}].
$$

这是代码 `residual` 和 backward surrogate 的对应式（[`loss.py:99-110`](../../upstream/KLPO/klpo/loss.py:99)）。当 $\beta>0$ 且 $k$ 精确时，它产生 $D_i^2/(2\beta)$ 的梯度；用于反传的 scalar 值与报告的 squared regression loss 仍不同。$\beta=0$ 时更新仍定义良好，`with_regression` 不返回带 $1/\beta$ 的统计量（[`_validation.py:72-78`](../../upstream/KLPO/klpo/_validation.py:72)）。

sequence MC 不能让同一列的随机 residual 乘它自己的 corrected score，否则引入两者的协方差。实现为每列构造 $D_j$，用其他 $M-1$ 列的均值 $D_{-j}$ 作为 stopped coefficient：

$$
D_j=R-\beta\sum_t\left[\ell_t+\log q(v_{tj}\mid h_t)-\log p_\theta(v_{tj}\mid h_t)\right],\qquad D_{-j}=\frac{1}{M-1}\sum_{l\ne j}D_l,
$$

$$
L_{\mathrm{sequence,MC}}=-\frac1B\sum_i\frac1M\sum_j\operatorname{sg}(D_{i,-j})\sum_t[\log p_\theta(a_{it}\mid h_{it})-\log p_\theta(v_{itj}\mid h_{it})].
$$

`other_residual = residual - centered/(m-1)` 正是 leave-one-out 的向量化形式；`cross_product` 用交叉乘积扣除 MC 方差，报告的是无偏 U-statistic（[`loss.py:208-229`](../../upstream/KLPO/klpo/loss.py:208)）。固定 trainer、固定 trajectory 下的 auxiliary-draw 无偏性，与完整策略更新的 population 等价性是两个条件层次；源码对 full sequence route 还写明 deterministic transitions、terminal rewards 和 matched sampler rollout 的假设（[`loss.py:86-91`](../../upstream/KLPO/klpo/loss.py:86)）。

### TopK 与 Binary 的边界

TopK 的 support 是历史 sampler 的 head id，不是当前 trainer 的 top-k。令 $q_B=1-\sum_{v\in S}q_v$、$p_B=1-\sum_{v\in S}p_v$，未触发 floor 时

$$
k_S=\sum_{v\in S}q_v\log\frac{q_v}{p_v}+q_B\log\frac{q_B}{p_B},\qquad C=\sum_{v\in S}\operatorname{sg}\left(q_v-\frac{q_B}{p_B}p_v\right)\log p_v,
$$

$$
\nabla C=\sum_{v\in S}\left(q_v-\frac{q_B}{p_B}p_v\right)\nabla\log p_v=-\nabla k_S.
$$

token route 因此使用 $-\operatorname{sg}(h)(\log p(a)-C)$。当 tail floor 激活，token route 使用 floored-ratio 近似，而 sequence route 对 literal clamped KL 自动微分；两者在 floor 处的 backward 不相同（[`loss.py:125-137`](../../upstream/KLPO/klpo/loss.py:125)、[`loss.py:326-344`](../../upstream/KLPO/klpo/loss.py:326)）。finite top-k 是 coarsened KL，只有 full-vocabulary 分支恢复 exact local KL。

Binary 把实际 action 与其补集当作两个类别，通过稳定 `log1mexp` 得到 correction $(1-q(a))/(1-p(a))$（[`loss.py:18-37`](../../upstream/KLPO/klpo/loss.py:18)）。该 correction 一般不能在完整 sampler distribution 下精确中心化 score，因此 Binary 是近似分支，不应继承 full/independent-MC 的精确性宣称（[`loss.py:257-262`](../../upstream/KLPO/klpo/loss.py:257)）。

### 实际训练 pipeline 与 Molt 适配

CPU toy 是可以逐步跟踪的完整最小链路：冻结 sampler snapshot -> categorical rollout -> 保存每个 visited state 的 historical full conditional、action、terminal reward 和 sampler version -> 重算 current full/action log-prob -> 从保存的 historical conditional 重新抽 auxiliary token -> loss/backward/AdamW -> 按周期发布新 sampler。采集在 [`examples/train_toy.py:20-39`](../../upstream/KLPO/examples/train_toy.py:20)，snapshot/reuse/current scoring 在 [`train_toy.py:69-83`](../../upstream/KLPO/examples/train_toy.py:69)，MC draw 与更新在 [`train_toy.py:84-118`](../../upstream/KLPO/examples/train_toy.py:84)。它每个 learner step 重抽 draw，从旧 trajectory 自带的 $q$ 抽取，即使已经发布了新 sampler，也不替换旧记录的行为分布。

实际 LLM 入口为 `scripts/train_molt.py`，调用 `molt.cli.train_rl_ray`，配置 one rollout per prompt、temperature=1、top-p=1、单 pass learner 和 `actor.loss_mode=klpo`（[`scripts/train_molt.py:56-99`](../../upstream/KLPO/scripts/train_molt.py:56)）。默认 queue size=4 允许 bounded staleness，`--sync` 才同时开启 force-on-policy 与 force-sync；launcher 关闭额外 KL reward、advantage whitening 和 IS correction。这些 flags 说明训练策略，但本次 checkout 的 `external/labs-molt` 未初始化，不能据此声称已核实 backend 的 rollout MC record 采集实现。

`KLPOLoss` 是与 Molt 普通 actor loss 签名兼容的 adapter：虽然接收 `old_log_probs`、`advantages` 和 token count，真正传给内核的是 current log-prob、实际 `rollout_log_probs`、raw rewards 与 action mask（[`klpo/molt.py:36-79`](../../upstream/KLPO/klpo/molt.py:36)）。它按 route/estimator 分派后，将 local response mean 乘 $B_{\mathrm{local}}N_{\mathrm{DP}}/B_{\mathrm{global}}$，抵消 DDP/FSDP 平均，保持 optimizer step 的全局 response normalization；禁止再按 gradient accumulation 次数重复除法（[`molt.py:80-88`](../../upstream/KLPO/klpo/molt.py:80)）。这与 LSPD 的 response 内 token mean 不同：KLPO 始终先对轨迹 action token 求和，再对 response 求均值。

独立性、同一 sampled id 上的概率对齐和 trajectory 完整性都是采集合同。`_validation.py` 检查形状、mask、概率质量和数值范围，也 detach behavior/reward；它无法从一张 log-prob 张量推断 draw 是否独立、action 是否匹配 full conditional、轨迹是否语义完整（[`_validation.py:9-64`](../../upstream/KLPO/klpo/_validation.py:9)、[`_validation.py:81-96`](../../upstream/KLPO/klpo/_validation.py:81)）。
