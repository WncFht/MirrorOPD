# 上游 OPD 与 KLPO 代码审阅

本文核对以下 checkout 当前工作树中的实现：`TA-OPD`、`ResOPD`、`One-Shot-OPD`、`Rethinking-OPD`、`LSPD` 和 `KLPO`。引用统一指向代码文件和行号；行号以本次审阅时的工作树为准。这里的“pipeline”指从 prompt、rollout、teacher 评分到 actor 更新的执行链；“抽象”指损失如何表达、teacher 信号如何传递，以及它与 veRL 的边界。

## 总览

六个仓库可以分成三种实现形态。

| 形态                     | 仓库                         | 核心抽象                                                                                                              |
| ------------------------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| veRL distillation 插件   | TA-OPD、ResOPD               | rollout 产生 student token；teacher 返回 top-k/采样 token；logits processor 计算逐 token surrogate；actor 再聚合 loss |
| veRL 配方与 teacher 服务 | One-Shot-OPD、Rethinking-OPD | shell 配置实验条件；teacher 作为 vLLM/FSDP/远程服务；OPD 信号进入 policy loss 或稀疏 KL                               |
| policy-loss 内核         | LSPD、KLPO                   | 直接以当前 log-prob、历史行为 log-prob、teacher log-prob 和 mask 构造可反传 surrogate，训练器只负责采样和更新         |

共性 pipeline 是：`prompt -> student rollout -> response mask/log-prob -> teacher signal -> token/sequence objective -> actor update -> sync rollout weights`。关键差异在 teacher 信号的支持集、梯度估计方式和 rollout 是否严格 on-policy。

## TA-OPD

### 入口与 pipeline

启动入口是 [`train.sh:95`](../../upstream/TA-OPD/train.sh:95)。它调用 `verl.trainer.main_ppo`，关闭 reward 中的 KL（[`train.sh:98-99`](../../upstream/TA-OPD/train.sh:98)），用 vLLM 生成 `n=4` 条 response（[`train.sh:124-130`](../../upstream/TA-OPD/train.sh:124)），再开启 distillation、选择 teacher 和 loss mode（[`train.sh:136-147`](../../upstream/TA-OPD/train.sh:136)）。因此这是“veRL PPO 外壳 + distillation policy loss”，不是把 OPD 写成独立 trainer。

loss 的总调度位于 [`verl/verl/trainer/distillation/losses.py:172-239`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:172)。`compute_topk_loss` 按 strategy 选择 FSDP/VeOmni 或 Megatron 实现，并按 `loss_mode` 分派 `reverse_kl_topk`、`taopd_reverse_kl_topk`、`normalized_reverse_kl_topk`、`sample_corrected_ta_opd` 等算法。`distillation_ppo_loss` 明确区分两次调用：student logits 非空时，在 logits processor 阶段得到逐 token distillation loss；否则在 actor policy-loss 阶段把它与 PPO/任务项合并（[`losses.py:242-277`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:242)）。

TA-OPD 的注册抽象是 `DistillationLossSettings` + registry。每个 loss 声明是否需要 top-k、是否需要 sampled log-prob，注册后由名称查找函数（[`losses.py:84-155`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:84)）。这使算法选择成为 Hydra 配置，而不是修改 trainer 主循环。

### 数学与数据抽象

TA-OPD 的默认 teacher payload 是每个 prefix 的 teacher top-k ids/log-probs；FSDP loss 接收 `(student_logits, teacher_topk_log_probs, teacher_topk_ids)`（[`fsdp/losses.py:118-130`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:118)）。`sample_corrected_ta_opd` 将 teacher top-k 之外的实际 rollout token 作为 tail 样本，并用 `student_logp_y - behavior_logp_y` 作为 off-policy importance ratio；无 behavior log-prob 时退化为 on-policy 停梯度权重（[`fsdp/losses.py:60-115`](../../upstream/TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py:60)）。

当前 checkout 还接入了 MirrorOPD cache 路径：`mirror_pmd_mean`、`mirror_bpo`、`mirror_mdpo`、`mirror_opd_onpolicy`、`mirror_opd_is` 和 `mirror_opd_is_no_baseline` 被转交给 `compute_mirror_opd_from_cache`（[`losses.py:194-199`](../../upstream/TA-OPD/verl/verl/trainer/distillation/losses.py:194)）。teacher 配置同时保留 native teacher pool 字段，但 `mirror_teacher_model_path` 明确用于冻结 FSDP teacher cache（[`distillation.yaml:13-18`](../../upstream/TA-OPD/verl/verl/trainer/config/distillation/distillation.yaml:13)）。

### 判断

TA-OPD 最强的工程抽象是“loss registry + logits-processor 两阶段接口”；它能把完整 vocabulary 的梯度估计、top-k 近似、sample correction 和 Mirror cache 接到同一套 veRL actor 生命周期。代价是算法语义分散在 `losses.py`、FSDP kernel、teacher payload 和配置中，读代码时必须沿分派链追踪。

## ResOPD

### 入口与 pipeline

ResOPD 的入口是 [`examples/resopd/run_resopd.sh:60-78`](../../upstream/ResOPD/examples/resopd/run_resopd.sh:60)，配置 vLLM teacher、`loss_mode=resopd` 和 teacher top-k。README 明确要求 FSDP/FSDP2/VeOmni student、vLLM teacher；Megatron、SGLang、fused kernel 和 chunked top-k 在该 release 不启用（[`README.md:212-228`](../../upstream/ResOPD/README.md:212)）。

loss 注册在 [`verl/trainer/distillation/losses.py:124-170`](../../upstream/ResOPD/verl/trainer/distillation/losses.py:124)。当 mode 是 `resopd`，它额外取 teacher 对实际 student action 的 log-prob 和 token id，再调用 FSDP 适配器；普通 mode 仍走 forward-KL top-k。统一的 `distillation_ppo_loss` 仍采用“logits processor 先算 per-token，再由 distillation loss 聚合”的 veRL 契约（[`losses.py:217-257`](../../upstream/ResOPD/verl/trainer/distillation/losses.py:217)）。

### ResOPD estimator

核心在 [`resopd.py:26-53`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:26)。输入必须同时包含 teacher top-k support `S` 和实际动作 `A` 的 teacher score；teacher top-k 概率不在 support 内重新归一化。代码先计算 student 在 support 上的 log-prob、support mass 和 support ratio（[`resopd.py:66-84`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:66)），再由 student/teacher tail mass 得到 aggregate tail correction（[`resopd.py:86-94`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:86)）。

最终 surrogate 用 `head_hit` 做分支，并以 `centered_event = 1[A in S] - P(S)` 做控制变量中心化（[`resopd.py:96-102`](../../upstream/ResOPD/verl/trainer/distillation/resopd.py:96)）。所以它不是把 top-k KL 当作确定性 loss，而是“top-k coarse gradient + tail bucket + tail-hit sampled residual”。README 给出的等价估计量是 exact coarse gradient 加上 `1[A not in S](r_A s_A - mu_B)`（[`README.md:187-204`](../../upstream/ResOPD/README.md:187)）。

### 判断

ResOPD 的抽象边界很清楚：teacher 只传 sparse support 和 observed-token score，student 仍做 full-vocabulary normalization；通信稀疏化不等于 student 计算稀疏化（[`README.md:224-228`](../../upstream/ResOPD/README.md:224)）。无偏性依赖 full-support、当前 student 分布采样和每个 rollout 只更新一次；README 明确警告 truncated sampling、stale rollout 和重复优化需要另行修正（[`README.md:206-210`](../../upstream/ResOPD/README.md:206)）。

## One-Shot-OPD

### 入口与 pipeline

共享脚本把三种 recipe 都接到 `python -m verl.trainer.main_ppo`，并通过 `trainer.use_v1=False` 走 veRL 旧版 PPO trainer（[`recipe/_common.sh:1-9`](../../upstream/One-Shot-OPD/recipe/_common.sh:1)）。`opd.sh` 按 `DOMAIN` 选择 actor/teacher/data，按 `MODE=full|oneshot|template` 选择 prompt 来源（[`recipe/opd.sh:17-62`](../../upstream/One-Shot-OPD/recipe/opd.sh:17)），最后把公共参数、mode 参数和单 teacher 参数传给 `launch`（[`recipe/opd.sh:81-116`](../../upstream/One-Shot-OPD/recipe/opd.sh:81)）。

公共参数设置 `algorithm.adv_estimator=token_reward_direct`、vLLM rollout、`calculate_log_probs=True`、`policy_loss.loss_mode=vanilla` 或 `vanilla_topk`（[`recipe/_common.sh:173-228`](../../upstream/One-Shot-OPD/recipe/_common.sh:173)）。teacher 通过 `distillation.fsdp_teacher.enabled=True`、teacher temperature、top-k strategy 和 reward weight mode 注入（[`recipe/_common.sh:255-289`](../../upstream/One-Shot-OPD/recipe/_common.sh:255)）。

### 单 teacher 与多 teacher

README 把 OPD 定义为 teacher reverse-KL reward，MOPD 则按 `ability` 列逐行路由到多个 teacher（[`README.md:60-76`](../../upstream/One-Shot-OPD/README.md:60)）。`mopd.sh` 设置 `ABILITY_TO_TEACHER`、三个 teacher path 和多数据集 train files（[`recipe/mopd.sh:24-48`](../../upstream/One-Shot-OPD/recipe/mopd.sh:24)），然后将 name:path 对传给 `multi_teacher_args`（[`recipe/mopd.sh:58-67`](../../upstream/One-Shot-OPD/recipe/mopd.sh:58)）。

默认 `LOG_PROB_TOP_K=0` 时是 sampled-token OPD；大于零时 top-k 进入训练 reward，`METRIC_TOP_K` 只影响 observability（[`recipe/_common.sh:69-82`](../../upstream/One-Shot-OPD/recipe/_common.sh:69)）。因此 One-Shot-OPD 的主要贡献在数据/state coverage 与 recipe 组织，loss kernel 复用 veRL，而不是引入新的反向估计器。

## Rethinking-OPD

### 主 OPD recipe

顶层 [`on_policy_distillation.sh:171-220`](../../upstream/Rethinking-OPD/on_policy_distillation.sh:171) 直接启动 `verl.trainer.main_ppo`，把 `algorithm.adv_estimator` 设为 token-level estimator，配置 actor/teacher model、vLLM rollout、`log_prob_top_k`、`top_k_strategy`、`reward_weight_mode` 和 teacher temperature。它将 teacher 当作 reward/advantage 生成端，而不是在 actor 里维护完整 teacher model。

### GKD/远程 teacher 实现

仓库还包含更明确的 `verl/recipe/gkd` 实现。其 README 将目标写成 teacher top-k support 上的 token-wise `KL(P||Q)`（[`recipe/gkd/README.md:13-22`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:13)）。pipeline 是 actor 参数同步、vLLM rollout、ZeroMQ teacher service 返回 top-k、Megatron actor 的 TP-aware KL kernel、最后 optimizer step（[`README.md:58-65`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:58)）。

teacher client 从有效 input ids 构造微批请求，收集 future 返回的 `teacher_topk_logps` 和 `teacher_topk_indices`，再按 attention mask 填回 padded DataProto（[`teacher_utils.py:50-138`](../../upstream/Rethinking-OPD/verl/recipe/gkd/teacher_utils.py:50)）。actor 的 logits processor 只在 `calc_kl_mask` 的有效位置调用 `vocab_parallel_kl_divergence`（[`megatron_workers.py:306-324`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_workers.py:306)）。

TP kernel 在各 rank 上做 stable normalization、将 global teacher ids 映射到 local vocab shard、计算 teacher sparse distribution 与 student probabilities 的 forward KL，再 all-reduce per-token loss（[`megatron_kl_loss.py:38-117`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_kl_loss.py:38)）；backward 是 `student_probs - teacher_sparse_probs` 乘上 upstream gradient（[`megatron_kl_loss.py:127-145`](../../upstream/Rethinking-OPD/verl/recipe/gkd/megatron_kl_loss.py:127)）。

### 异步抽象

GKD 支持 zero-step、one-step-off 和 two-step-off scheduler。one-step-off 重叠 rollout 与 actor update，并同时进行 weight sync 与 teacher retrieval；two-step-off 允许 teacher 更慢时继续交错 rollout/update（[`recipe/gkd/README.md:26-50`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:26)）。README 给出的控制流是 `GenerationBatchFuture -> async teacher future -> merge DataProto -> update actor`（[`recipe/gkd/README.md:74-95`](../../upstream/Rethinking-OPD/verl/recipe/gkd/README.md:74)）。这会牺牲严格 on-policy 的新鲜度换取吞吐，属于 pipeline 语义变化，不是单纯工程优化。

## LSPD

### 入口与训练形态

`train_lspd.sh` 和 `train_lspd_rb.sh` 都调用共享 [`scripts/train.py:25-82`](../../upstream/LSPD/scripts/train.py:25)，通过 `--method LSPD|LSPD-RB` 选择是否启用 replay。脚本把 loss mode 固定为 `opd_squared_logprob`，并设置 entropy coefficient、log-ratio clip、candidate weighting、penalty mode 和 replay 参数（[`scripts/train.py:75-121`](../../upstream/LSPD/scripts/train.py:75)）。

### LSPD objective

核心函数是 [`core_algos.py:981-1024`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:981)。2-D 输入表示 sampled rollout action，3-D 输入表示显式 candidate set；teacher log-prob 停止梯度，目标是 response token 上的 squared log-ratio penalty 减 student entropy bonus。实际 ratio、candidate weight 和 penalty 在 [`core_algos.py:1069-1128`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1069) 计算，支持 `uniform`、`student_p`、`teacher_p`、`mixture_p` 以及 squared/clamp/huber 变体。

LSPD 的关键假设是 sampled action 可以作为 full-vocabulary Monte Carlo estimator；因此 2-D 路径不是 student top-k 截断。teacher rollout source 可标记为 student/teacher，并通过 `teacher_rollout_weight` 混合两类 state（[`core_algos.py:1044-1052`](../../upstream/LSPD/verl/verl/trainer/ppo/core_algos.py:1044)）。

### LSPD-RB replay

Ray trainer 初始化 bounded `DataProtoReplayBuffer`（[`ray_trainer.py:423-430`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:423)），只保存可重算平方 loss 和 entropy 所需字段（[`ray_trainer.py:1213-1242`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:1213)），每个 rollout 后独立采样并执行配置次数的 actor updates（[`ray_trainer.py:1252-1290`](../../upstream/LSPD/verl/verl/trainer/ppo/ray_trainer.py:1252)）。这使 LSPD-RB 从严格 on-policy 变成带固定 teacher target/behavior record 的 off-policy replay，但 objective 本身不变。

## KLPO

### 核心数据合同

KLPO 的 [`klpo/loss.py:1-8`](../../upstream/KLPO/klpo/loss.py:1) 明确：没有 IS multiplier、reward centering、ratio clipping、critic、admission mask 或 trajectory-length normalization；返回 scalar 是 backward surrogate，不一定是 regression loss。每行必须是完整 trajectory，当前 log-prob 保持 autograd，历史 sampler log-prob 固定。

### 两条 route、四种 KL estimator

库将 route 与 KL estimator 解耦。token regression 使用每 token 系数 `h=R-beta*ell`；sequence regression 使用整条 trajectory residual。实现暴露 binary、full、top-k 和 MC 四种 estimator；API/组合表见 [`docs/algorithms.md:73-111`](../../upstream/KLPO/docs/algorithms.md:73)。

默认 token+MC-KL 的 auxiliary draw 是每个 prefix 独立、可重复采样的 M 个 token，`k_MC=mean(log q(v)-log p(v))`，不把 rollout action 当作 draw，也不 renormalize/deduplicate（[`docs/algorithms.md:19-40`](../../upstream/KLPO/docs/algorithms.md:19)）。实现中 MC 分支取 `mean(q_log-p_log.detach())`，loss 为 `-h * (current - mean sampled logp)`（[`klpo/loss.py:284-302`](../../upstream/KLPO/klpo/loss.py:284)）。

sequence full-KL 直接在 `[B,T,V]` conditional 上计算 `q*(log q-log p)`，用 detached trajectory residual 乘 `current + local_kl`（[`klpo/loss.py:76-110`](../../upstream/KLPO/klpo/loss.py:76)）。sequence TopK-KL 保留 K 个 head 并把余量聚成 tail，tail mass 用 `tail_floor` 稳定；代码明确对 literal stabilized KL 反传（[`klpo/loss.py:113-170`](../../upstream/KLPO/klpo/loss.py:113)）。token loss 的 MC/full/top-k/binary 分派和 detached coefficient 位于 [`klpo/loss.py:281-353`](../../upstream/KLPO/klpo/loss.py:281)。

### 与 OPD 的关系

KLPO 不把 teacher top-k 直接当作 forward-KL target；它把历史 sampler `q`、当前 policy `p`、terminal reward `R` 和 KL coefficient `beta` 组成 critic-free regression surrogate。它最接近“policy-loss 内核”，可由任何 rollout/trainer 提供 log-prob records；而 TA-OPD/ResOPD/Rethinking 的主要接口是“teacher sparse payload + veRL distillation hook”。KLPO 的 sequence MC 路径要求 `M>=2` 做 leave-one-out，token MC 则 `M>=1`，这是它区别于普通 sampled-token OPD 的关键统计设计（[`docs/algorithms.md:179-199`](../../upstream/KLPO/docs/algorithms.md:179)）。

## 横向比较与对本仓库的启示

| 维度              | TA-OPD                                 | ResOPD                             | One-Shot                | Rethinking/GKD                   | LSPD                            | KLPO                                                    |
| ----------------- | -------------------------------------- | ---------------------------------- | ----------------------- | -------------------------------- | ------------------------------- | ------------------------------------------------------- |
| teacher 信号      | top-k、sample correction、Mirror cache | top-k + actual-token score         | reverse-KL reward/top-k | top-k sparse KL                  | sampled/full candidate log-prob | historical sampler + optional full/top-k/MC conditional |
| 梯度视角          | distillation loss 注入 actor           | unbiased reverse-KL estimator      | veRL policy loss        | TP-aware forward KL              | squared log-ratio + entropy     | score-centered regression surrogate                     |
| rollout freshness | 视 mode，可 IS 修正                    | 强依赖 full-support/current policy | 默认 on-policy          | scheduler 可 one/two-step off    | LSPD-RB 明确 replay             | 历史行为 policy 固定，可重算 current                    |
| 系统边界          | veRL distillation registry             | FSDP distillation kernel           | recipe/data abstraction | remote teacher + async scheduler | veRL policy loss + replay       | 独立 PyTorch loss API                                   |

对 MirrorOPD 的直接启示有三点。第一，TA-OPD 的 registry 和两阶段 logits-processor 契约适合作为生产接入边界。第二，ResOPD 的 tail residual 与 TA-OPD 的 sample-corrected off-policy ratio 都说明：一旦 rollout batch 被重复使用，behavior log-prob、teacher version 和采样支持必须进入显式数据合同。第三，LSPD/KLPO 的独立 loss API 和 CPU 级恒等式测试适合作为数学参考层；veRL/Ray/vLLM 适配应保持在 integrations 层，不能把分布式调度细节混进估计量本身。
