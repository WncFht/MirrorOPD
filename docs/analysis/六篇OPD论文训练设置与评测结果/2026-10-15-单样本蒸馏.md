论文 top-k 形式在式 (3) 只将学生概率在候选集合内归一化，教师项仍是原始 log-prob；它与 P4 文中两侧同时归一化的“子集 KL”公式有区别。论文的数学主实验是 top-16，§4 脚注明确机制实验改用 sampled-token，因此两部分绝对成绩不能混用。

## 4.5 状态覆盖与对齐诊断的全部设置和表值

状态用教师最后一层、该 prefix 最后一个 token 的 hidden vector 表示，原空间 1,536 维。full-data 训练 step1–500 每步取 5 条轨迹，每轨迹 8 个均匀相对位置；3 条进 reference、2 条 held-out，共 12,000/8,000 个状态。PCA 降至 50 维，保留 71.9% 方差；默认 K-means=200。评测每步 2 条轨迹，300 步累计 600 条；重复抽样 30 次，误差条为抽样标准差，不能解释为 30 次独立模型训练。

覆盖率是到访簇的比例，默认 one-shot step100=65.9%、step300=71.5%。不同 K 的原表 4 如下，K=500 时 held-out 也只有 95.6%，所以并非构造上保证 100%。

| $K$ | 1-shot | 4-shot | 16-shot | Full data (held-out) |
| --- | ------ | ------ | ------- | -------------------- |
| 50  | 0.755  | 0.829  | 1.000   | 1.000                |
| 100 | 0.727  | 0.803  | 1.000   | 1.000                |
| 200 | 0.715  | 0.798  | 0.989   | 1.000                |
| 500 | 0.564  | 0.695  | 0.904   | 0.956                |

原表 5 重建 reference：每种 setting 各 2,000 条 rollout 合并，再以 K=200 聚类。它的 full-data-anchored 行与表 4 的默认行不是同一组数值；论文未充分解释这个基线差异，本文保留两表而不合并。pooled coverage 也不是“恢复 full-data 覆盖”的度量。

| Reference construction | 1-shot | 4-shot | 16-shot | Full data (held-out) |
| ---------------------- | ------ | ------ | ------- | -------------------- |
| Full-data anchored     | 0.663  | 0.773  | 0.953   | 0.998                |
| Equal-size pooled      | 0.750  | 0.845  | 0.958   | 0.966                |

距离诊断在未 PCA 的 1,536 维空间计算到 10 个最近 reference 状态的平均余弦距离，以 held-out full-data 的 95 分位作 off-reference 阈值。原表 6：

| Setting         | Exceedance (%) | Mean distance | AUROC |
| --------------- | -------------- | ------------- | ----- |
| 1-shot          | 17.2           | 0.283         | 0.552 |
| 4-shot          | 4.4            | 0.218         | 0.477 |
| 16-shot         | 3.8            | 0.231         | 0.512 |
| Full data (all) | 4.0            | 0.215         | 0.476 |

状态位置对照使用最后一个 non-padding token、绝对位置 2,000、4,000 和默认 8 个相对位置；排序保持，最后 token 在少题时明显更低（图 16）。吸收率从 step30 开始，排除梯度裁剪主导区；距离为 sampled 动作上教师—学生 log-prob 差的绝对值平均，以各自 step30 归一化。吸收率用几何窗口$[t/1.4,1.4t]$两端附近距离中位数的 log 斜率估计，所以不能把图末端缺失当训练中断。原表 7：

| Setting (queries) | 1    | 4    | 16   | Full data |
| ----------------- | ---- | ---- | ---- | --------- |
| $d_{300}/d_{30}$  | 0.16 | 0.17 | 0.18 | 0.22      |
| $v_{50}/v_{200}$  | 5.6  | 5.2  | 4.2  | 6.4       |

公开 recipe 的 `opd.sh` Code 默认教师为 DeepCoder-1.5B-Preview、训练集 TACO，对应附录 E，不能直接复现正文的 Nemotron-v2-RLVE+Codeforces。`_common.sh` 默认评测 T=0.7、top-p=0.9、n=16；IF 独立脚本默认 T=0.6、top-p=0.95。它们是代码入口默认值，不是论文所有评测的统一实测设置。代码还为 one-shot 默认 prompt cap=8,192、普通默认 4,096，与论文表 3 的数学 1,024 不同；重现实验须显式覆盖。

代码补充的 BFCL 子集是 `simple`、`multiple`、`parallel`、`parallel_multiple`、`live_simple`；Multi-IF 须用独立三轮评测，不能以单轮 verl validation 替代。GRPO launcher 设置 n=8、`adv_estimator=grpo`；论文未给 one-shot RLVR 独立完整超参数表。MOPD 的序列平均归约也不同于单教师 token 平均。主实验所有种子、IF 抽样子集规模、完整训练命令快照和各 benchmark 实际采样参数仍不足以逐项还原，不能由 launcher 默认值自动补全。
