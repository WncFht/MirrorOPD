## 共同符号

沿用书稿的 $\pi_{k,n}$、$\pi_k$、$\pi_T$：分别是当前 student、冻结 rollout snapshot 和 teacher。固定已访问 prefix $s$，简记 $p=\pi_{k,n}(\cdot\mid s)$、$b=\pi_k(\cdot\mid s)$、$t=\pi_T(\cdot\mid s)$，动作记 $a$，score 为 $\psi(a)=\nabla\log p(a)$。A2 的 proxy 与 base 分布另定义，不能全部塞进 teacher 角色。

下文表格同一单元格中无斜线的简写继承首项的 namespace，花括号展开为并列字段；这些模板不是 W&B 自动生成的统一 schema。

Top-K 诊断集合记 $H^S=\operatorname{TopK}(p)$、$H^T=\operatorname{TopK}(t)$；实际 loss 使用的支持集记 $S$ 或 $C$。原生 Top-K、训练 candidate set、采样 top-k 截断和 KL 的 tail partition 是不同对象。

令有效 prefix/token 数为 $M$，响应条数为 $B$，第 i 条有效响应长度为 $T_i$。global token mean 使用 $1/M$；sequence-mean-token-mean 使用 $B^{-1}\sum_iT_i^{-1}\sum_t$；candidate sum 后再 token mean 与 candidate mean 也不同。日志比较需要同时给出这些分母。

## ResOPD：稀疏教师评分与事件控制梯度

### pipeline 和维护位置

发布脚本调用 `verl.trainer.main_ppo`，Ray driver 初始化 student 与独立 teacher 服务。student 生成完成后，agent loop 通过 teacher manager 对完整 student 序列查询 teacher prompt log-probs，返回 teacher 原生 Top-K IDs/LP，以及实际动作的 teacher LP。动作在 Top-K 外时也必须评分。

actor 使用完整 student logits 计算所需概率，FSDP adapter 处理 packed/nested 布局，纯 PyTorch `resopd_loss` 返回逐 token backward surrogate 和诊断。collector 恢复 padding、应用 response mask；engine 做 loss 全局缩放与 worker metric 归约；driver 同步 rollout 权重，最后一次性上传 outer 记录。

关键源码是 `ResOPD/verl/trainer/distillation/resopd.py`、`ResOPD/verl/trainer/distillation/losses.py`、`ResOPD/verl/experimental/teacher_loop/teacher_manager.py`与 `ResOPD/verl/trainer/ppo/ray_trainer.py`。独立 kernel 对数学验证友好，layout、服务和训练调度仍留在 verl。

### 梯度与 forward value

取 $S=H^T$，定义 $x_a=\log(p_a/t_a)$、$P_S=\sum_{a\in S}p_a$、$\tau_p=1-P_S$、$\tau_t=1-\sum_{a\in S}t_a$。令

$$
H_g=\sum_{a\in S}p_ax_a\psi(a),\qquad \mu_B=\log(\tau_p/\tau_t)\nabla\log\tau_p.
$$

其事件控制梯度写成

$$
\widehat g=H_g+\tau_p\mu_B+1[a\notin S]\bigl(x_a\psi(a)-\mu_B\bigr),\qquad a\sim p.
$$

对当前完整 student 分布取期望，最后两项的控制部分消去，得到完整 reverse-KL gradient。发布入口限制 full-support sampling、一个全 batch optimizer 更新，保护这一采样条件；多 inner 或截断采样需要另加合同。

代码用 `head_hit-P_S` 实现中心化事件，并分开 forward value 与 backward surrogate。forward 是 head-hit 时条件 head log-ratio 均值、tail-hit 时 sampled log-ratio，单点可以为负。`actor/distillation/loss` 不是确定性 head-tail KL。tail 的 dtype epsilon guard 也要与理想公式的边界区分。

## TA-OPD：分区 KL 与采样尾部校正

### pipeline 和三种主要模式

TA 主链与 Res 相近：独立 vLLM teacher 查询 student 已生成序列，输出真实 teacher IDs/LP；actor logits processor 先产生逐 token 蒸馏量，随后 loss registry 聚合并与可选任务项组合。框架初始化 checkpoint 后先同步 rollout，默认在训练前验证 student，然后从 global step1 开始更新。

源码分界是 `TA-OPD/verl/verl/trainer/distillation/losses.py`的 registry/collector、`TA-OPD/verl/verl/trainer/distillation/fsdp/losses.py`的概率与梯度程序，以及 teacher/agent 服务。稀疏 teacher payload 降低通信量，student full normalizer 仍然存在。

令 $S=H^T$。三个公开模式的对象如下。

| 模式                         | 优化或梯度对象                                                    | 额外输入                                                      |
| ---------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------- |
| `normalized_reverse_kl_topk` | 对 $p(\cdot\mid S)$ 与 $t(\cdot\mid S)$ 的 conditional reverse KL | teacher Top-K                                                 |
| `taopd_reverse_kl_topk`      | $S$ 中各 token 与一个聚合 tail 的 coarse reverse KL               | teacher Top-K                                                 |
| `sample_corrected_ta_opd`    | coarse score 程序加 sampled within-tail correction                | teacher Top-K、实际动作 teacher LP、direct 路径的 behavior LP |

默认 TA 目标是

$$
L_{\mathrm{TA}}=\sum_{a\in S}p_a\log(p_a/t_a)+\tau_p\log(\tau_p/\tau_t).
$$

它遗漏 tail 内部的条件 KL：

$$
\operatorname{KL}(p\Vert t)=L_{\mathrm{TA}}+\tau_p\operatorname{KL}(p(\cdot\mid S^c)\Vert t(\cdot\mid S^c)).
$$

SC 模式使用 sampled correction 补梯度，direct 分支有当前 action / behavior action ratio，代码没有为该 ratio 输出专属 ESS。它与框架的 rollout/FSDP mismatch correction 分开。

## Rethinking-OPD：真实候选集合与候选 PPO

### pipeline 与支持集

主脚本调用 Ray PPO trainer。actor/FSDP 先给出 old student LP 与原生 student Top-K；causal teacher 通过 RewardModelWorker 返回 teacher 原生 IDs、teacher 在 student IDs 上的 LP 和 membership mask。teacher-only 或 union 路径还取得 student 在 teacher IDs 上的概率，形成真实 candidate set，再计算 reward/advantage 与 PPO 更新。

主结构位于 `Rethinking-OPD/verl/verl/workers/fsdp_workers.py`、`Rethinking-OPD/verl/verl/workers/actor/dp_actor.py`、`Rethinking-OPD/verl/verl/trainer/ppo/core_algos.py`和 `Rethinking-OPD/verl/verl/trainer/ppo/ray_trainer.py`。默认 student/teacher 同温度 1，完整采样，teacher 冻结；训练权重通过 actor worker 的 rollout-mode 切换发布给 vLLM。

与本地 MD-OPD 的不完整 candidate 路径不同，这个固定 Rethinking checkout 确实构造 teacher-only 与去重 union。union 张量可达 2K 宽，teacher 部分重复 IDs 用 mask 排除。进一步核对复用路径发现，only_tch 虽然传递 teacher IDs，却未传相同 IDs 上的 old cross LP；其多更新分支可退回 student-slot LP。单次更新路径避开该错配，teacher-only 集合构造与任意 reuse 安全性须分别验收。

候选贡献为

$$
A(a)=w_C(a)[\log t_a-\log b_a],\qquad a\in C.
$$

常规 student_p/teacher_p 权重在 $C$ 上归一化，none 为均匀权重；`union-intersection` 表示对称差，却使用 `normalize=False` 的原始权重。因此切换集合策略还改变权重尺度。该 helper 的 `kl_estimator` 参数没有实际改变 log-ratio 算式。

每个 candidate 的 current/old ratio 经 PPO clipping 后对 K 求和，再做 token/sequence 归约。它与直接对 conditional KL autograd 不同。主脚本默认关闭内部周期验证，使用独立 vLLM 生成与 grade 程序评估保存的模型；仓库附带 SFT、rejection sampling、GKD 与 GRPO 路径，本文不把这些日志混入主 OPD。

## A2-OPD：四分布相对信号与可选自适应

### pipeline 与四模型评分

定义当前 target $P$、固定 target base $B_0$、proxy expert $E$ 和 proxy base $F$。target base 是初始化 target snapshot，proxy expert/base 定义要转移的能力变化。主数学脚本先启动独立 HTTP verifier server，再由 Ray trainer 生成 student 回答和任务正确率。

trainer 按 prompt group 的 all-correct/mixed/all-wrong 划分候选，GRPO 消费 mixed，OPD 消费 student rows。schedule 决定 OPD/GRPO/both/alternate/warmup；默认 GRPO 关闭且 n1，不能把 `update_mode=both` 解读为默认训练两种 loss。

both 模式中 GRPO 先更新，OPD 随后准备的 old scorer 可能已不同于生成时 student。OPD prep 在同一 prefix 和 candidate IDs 上收集四分布的 LP，构造 frozen utility、baseline 和候选 contribution；专门 `update_policy_opd` 做 PPO 更新，再把控制器统计和阶段指标送给 driver。主要边界是 `A2-OPD/verl/verl/trainer/ppo/a2opd_utils.py`、`A2-OPD/verl/verl/trainer/ppo/a2opd_controller.py`、`A2-OPD/verl/verl/workers/actor/dp_actor.py`与 `A2-OPD/verl/verl/trainer/ppo/ray_trainer.py`。

跨 tokenizer 路径使用 text-span bridge 和 candidate 翻译，交会后的有效 mask 才能进入概率比较；Top-K 可要求至少两个可翻译候选。数值 token ID 不能跨词表直接比较。

### utility、KL 与 controller

默认 $C$ 是 target student Top-K。令 old target 为 $P_0$，定义

$$
d_a=\log E_a-\log F_a,\qquad u_a=d_a-\lambda(\log P_{0,a}-\log B_{0,a}).
$$

在 $C$ 上重新归一化后，state baseline 与 contribution 是

$$
b_C=\sum_{a\in C}P_{0,C}(a)u_a,\qquad A_a=P_{0,C}(a)(u_a-b_C).
$$

proxy KL、anchor KL、transfer KL 与 transfer gap 都是同一个 $C$ 上重新归一化的 categorical KL，没有 aggregate tail：

$$
K_{proxy}=\operatorname{KL}(E_C\Vert F_C),\qquad K_{anchor}=\operatorname{KL}(P_{0,C}\Vert B_{0,C}),
$$

$$
G_C=\operatorname{softmax}(\log B_0+d),\qquad K_{transfer}=\operatorname{KL}(G_C\Vert B_{0,C}),\qquad K_{gap}=\operatorname{KL}(P_{0,C}\Vert G_C).
$$

K=0 sampled 分支使用单动作 k3 式量；由于样本来自 target，proxy KL 数值不能自动获得 proxy-distribution 下的无偏性。

`A2-OPD/verl/verl/trainer/config/algorithm/a2opd.yaml`默认 enable=true，但 adaptive budget、dual lambda 和 token emphasis 全部关闭。可选功能分别为：proxy/transfer/额外验证 reward 更新预算；根据 anchor-KL/budget 更新 lambda；根据候选 utility 方差给 token 重新加权。`token_sampling` 当前是 mask 权重，不是随机丢弃 token。

dual 更新形式为

$$
\lambda_{next}=\operatorname{clip}\left(\lambda\exp[\eta_\lambda(K_{anchor}/\mathcal B-1)]\right).
$$

该输入 KL 来自更新前 old target，日志中的新 lambda 面向下一次更新，同一记录不意味着同一状态。

### 中心化下的零均值陷阱

state baseline 保证

$$
\sum_{a\in C}A_a=\sum_aP_{0,C}(a)u_a-b_C\sum_aP_{0,C}(a)=0.
$$

worker 的 advantage 先 sum K，所以该族接近零是定义结果。两个候选的 $A=(0.5,-0.5)$ 也有零和，但 $-\sum_aA_a\nabla\log P_a$ 可以非零。检查学习和收敛应看 candidate-level RMS、更新梯度、transfer gap 与任务质量，不能只看 worker 的 sum-K mean/std。

## One-Shot-OPD：单题协议、teacher routing 与 PPO

### pipeline 和模块

recipe 层准备任务、单题/full/template 数据和 teacher 路由，公共脚本构造 Hydra 参数。actor 使用较新的 engine worker，teacher 在相同 resource pool 初始化并参数 offload；多 teacher 按 ability 分组评分，再按原 row index scatter 回来。

一次 outer 为 student rollout → old student LP → verifier outcome → teacher 在 student action 上的 LP → dense teacher reward → direct token advantage → PPO actor update → CheckpointManager 权重同步 →周期验证与日志。原 verifier 另存在 `true_token_level_scores`，但实际 `compute_data_metrics` 的 `critic/score` 仍读已覆盖的 `token_level_scores`；保留字段的注释不能替代 consumer 核验。

主要边界是 `One-Shot-OPD/verl/verl/trainer/ppo/opd_trainer_mixin.py`、`One-Shot-OPD/verl/verl/workers/fsdp_teacher_worker.py`、`One-Shot-OPD/verl/verl/trainer/ppo/opd_core_algos.py`和 actor `One-Shot-OPD/verl/verl/workers/utils/losses.py`。

one-shot 指数学单题重复成批，仍每轮生成新的 student response。template 模式让 student 先写输入，内容过滤后训练，限单 teacher；多 teacher MOPD 按 math/code/instruction following 路由，与 Mirror 算法中的 Mean/BPO/MDPO 名称无关。

### sampled 与 Top-K 训练形式

默认信号为

$$
A_t=\log\pi_T(a_t\mid s_t)-\log\pi_{old}(a_t\mid s_t).
$$

默认没有 baseline/discount，随后进入 PPO ratio/clipping，而不是直接 $-\operatorname{sg}(A)\log p$。额外 GRPO task advantage 是另一可选 estimator。主 recipe 的 `LOG_PROB_TOP_K` 与 `METRIC_TOP_K` 默认都 0：前者开启 3D 候选 reward，后者只测支持集而继续训练 sampled reward。

Top-K reward 路径要求单 epoch、一个完整 optimizer batch 等限制，避免当前 Top-K 与 old 槽位在更新后错配。这是保护条件，不能解读为已经具备任意多 inner 的冻结 candidate 合同。teacher-only/union 所需完整交叉概率也不能由此 student 候选路径推断。

## LSPD：直接 log-prob 回归与 FIFO replay

### pipeline 与 loss

`scripts/train.py`执行模型/tokenizer preflight、准备配置并启动老式 FSDP actor/vLLM与独立teacher RewardModelWorker。teacher EOS151645 被映射到 student EOS151643 的共同 action class；这改变教师条件分布，应与原始模型路径一起记录。

student rollout 后，teacher 对实际动作返回冻结 LP。actor 重新计算 current LP 与完整 entropy，直接调用 `LSPD/verl/verl/trainer/ppo/core_algos.py`，不消费 PPOold-LP/advantage 来构造回归梯度。`LSPD/verl/verl/workers/actor/dp_actor.py`负责 live forward 和优化；`LSPD/verl/verl/trainer/ppo/replay_buffer.py`负责 RB 轨迹采样。

定义 $\delta_{it}=\log p(a_{it}\mid s_{it})-\operatorname{sg}\log t(a_{it}\mid s_{it})$。默认 Huber 形式是

$$
P_c(\delta)=\begin{cases}\delta^2,&|\delta|\le c,\\2c|\delta|-c^2,&|\delta|>c,\end{cases}\qquad c=5,
$$

$$
L=\frac1B\sum_i\frac1{T_i}\sum_tP_c(\delta_{it})-0.1\frac1B\sum_i\frac1{T_i}\sum_tH(p(\cdot\mid s_{it})).
$$

可选 squared 和 clamp 是不同数值目标。sampled 二维路径不再乘 action 概率，完整 categorical 采样已经提供频率权重；它仍是 sampled 动作回归，不是每 prefix 全词表精确平方积分。三维 candidate 路径可以使用归一化 uniform/student/teacher/mixture 权重，但默认 Top-K0。

### 普通训练与 RB

普通版每 outer 为 64prompt×4response，mini16prompt 等价量在框架内乘 n4，所以共有 4 次 optimizer update。RB 将响应、mask、模型输入与 teacher LP 拷贝入 CPU FIFO，容量 65536response 行；本轮加入后立即采样，每次 64 行，默认 256 次更新，update 之间重新抽样。

replay 不保存 behavior LP 做 IS，不重算 teacher target；它是固定 target regression 的旧 state/action 重用。没有 IS/ESS 不等于没有 state distribution shift。下一 rollout 前同步当前 student 到 vLLM。scheduler 按实际 update 调用推进，RB 配置已据 reuse 次数调整计划。

## KLPO：历史 sampler 与辅助抽样

### 核心数据合同

KLPO 的 `KLPO/klpo/loss.py` 明确：没有 IS multiplier、reward centering、ratio clipping、critic、admission mask 或 trajectory-length normalization；返回 scalar 是 backward surrogate，不一定是 regression loss。每行必须是完整 trajectory，当前 log-prob 保持 autograd，历史 sampler log-prob 固定。

### 两条 route、四种 KL estimator

库将 route 与 KL estimator 解耦。token regression 使用每 token 系数 `h=R-beta*ell`；sequence regression 使用整条 trajectory residual。实现暴露 binary、full、top-k 和 MC 四种 estimator；API/组合表见 `KLPO/docs/algorithms.md`。

默认 token+MC-KL 的 auxiliary draw 是每个 prefix 独立、可重复采样的 M 个 token，`k_MC=mean(log q(v)-log p(v))`，不把 rollout action 当作 draw，也不 renormalize/deduplicate（`KLPO/docs/algorithms.md`）。实现中 MC 分支取 `mean(q_log-p_log.detach())`，loss 为 `-h * (current - mean sampled logp)`（`KLPO/klpo/loss.py`）。

sequence full-KL 直接在 `[B,T,V]` conditional 上计算 `q*(log q-log p)`，用 detached trajectory residual 乘 `current + local_kl`（`KLPO/klpo/loss.py`）。sequence TopK-KL 保留 K 个 head 并把余量聚成 tail，tail mass 用 `tail_floor` 稳定；代码明确对 literal stabilized KL 反传（`KLPO/klpo/loss.py`）。token loss 的 MC/full/top-k/binary 分派和 detached coefficient 位于 `KLPO/klpo/loss.py`。

### 与 OPD 的关系

KLPO 不把 teacher top-k 直接当作 forward-KL target；它把历史 sampler `q`、当前 policy `p`、terminal reward `R` 和 KL coefficient `beta` 组成 critic-free regression surrogate。它最接近“policy-loss 内核”，可由 rollout/trainer 提供满足采集合同的 log-prob records。TA-OPD/ResOPD 使用 teacher sparse payload 与 distillation hook；One-Shot/Rethinking 主 OPD 使用冻结 log-ratio advantage。KLPO 的 sequence MC 路径要求 `M>=2` 做 leave-one-out，token MC 则 `M>=1`，这是它区别于普通 sampled-token OPD 的关键统计设计（`KLPO/docs/algorithms.md`）。

### 默认目标的逐步解释

本节以 $q$ 表示历史 sampler，$p_\theta$ 表示当前 trainer。在固定历史 $h_t$ 上，先定义 action log-ratio 与 local KL：

$$
\ell_t=\log p_\theta(a_t\mid h_t)-\log q(a_t\mid h_t),\qquad k_t=D_{\mathrm{KL}}(q(\cdot\mid h_t)\Vert p_\theta(\cdot\mid h_t)).
$$

由于 $q$ 固定，local KL 的梯度为

$$
\nabla_\theta k_t=-\sum_v q(v\mid h_t)\nabla_\theta\log p_\theta(v\mid h_t).
$$

所以 corrected action score 是 $\nabla\log p_\theta(a_t)+\nabla k_t$，即减去 historical sampler 下的平均 score。实现默认以独立 $v_{tj}\sim q(\cdot\mid h_t)$ 抽样近似后者：

$$
L_{\mathrm{token,MC}}=-\frac1B\sum_i\sum_t\operatorname{sg}(R_i-\beta\ell_{it})\left[\log p_\theta(a_{it}\mid h_{it})-\frac1M\sum_{j=1}^{M}\log p_\theta(v_{itj}\mid h_{it})\right].
$$

代码中的 `h` 在 `torch.no_grad()` 中构造，当前 action 和 auxiliary-token log-prob 两项保留梯度（`KLPO/klpo/loss.py`）。历史概率用来生成独立 draw 和定义 $\ell_t$，不再给每个 draw 额外乘一次 $q(v)$，因为采样频率已经提供 $q$ 的权重。$M=1$ 已经能无偏估计这一条件 score correction；MC 的负 KL 数值和重复 token id 都是允许的。

sequence route 则先把轨迹各 token 的 log-ratio 与 local KL 加总：

$$
D_i=R_i-\beta\sum_t(\ell_{it}+k_{it}),\qquad L_{\mathrm{sequence}}=-\frac1B\sum_i\operatorname{sg}(D_i)\sum_t[\log p_\theta(a_{it}\mid h_{it})+k_{it}].
$$

这是代码 `residual` 和 backward surrogate 的对应式（`KLPO/klpo/loss.py`）。当 $\beta>0$ 且 $k$ 精确时，它产生 $D_i^2/(2\beta)$ 的梯度；用于反传的 scalar 值与报告的 squared regression loss 仍不同。$\beta=0$ 时更新仍定义良好，`with_regression` 不返回带 $1/\beta$ 的统计量（`KLPO/klpo/_validation.py`）。

sequence MC 不能让同一列的随机 residual 乘它自己的 corrected score，否则引入两者的协方差。实现为每列构造 $D_j$，用其他 $M-1$ 列的均值 $D_{-j}$ 作为 stopped coefficient：

$$
D_j=R-\beta\sum_t\left[\ell_t+\log q(v_{tj}\mid h_t)-\log p_\theta(v_{tj}\mid h_t)\right],\qquad D_{-j}=\frac{1}{M-1}\sum_{l\ne j}D_l,
$$

$$
L_{\mathrm{sequence,MC}}=-\frac1B\sum_i\frac1M\sum_j\operatorname{sg}(D_{i,-j})\sum_t[\log p_\theta(a_{it}\mid h_{it})-\log p_\theta(v_{itj}\mid h_{it})].
$$

`other_residual = residual - centered/(m-1)` 正是 leave-one-out 的向量化形式；`cross_product` 用交叉乘积扣除 MC 方差，报告的是无偏 U-statistic（`KLPO/klpo/loss.py`）。固定 trainer、固定 trajectory 下的 auxiliary-draw 无偏性，与完整策略更新的 population 等价性是两个条件层次；源码对 full sequence route 还写明 deterministic transitions、terminal rewards 和 matched sampler rollout 的假设（`KLPO/klpo/loss.py`）。

### TopK 与 Binary 的边界

TopK 的 support 是历史 sampler 的 head id，不是当前 trainer 的 top-k。令 $q_B=1-\sum_{v\in S}q_v$、$p_B=1-\sum_{v\in S}p_v$，未触发 floor 时

$$
k_S=\sum_{v\in S}q_v\log\frac{q_v}{p_v}+q_B\log\frac{q_B}{p_B},\qquad C=\sum_{v\in S}\operatorname{sg}\left(q_v-\frac{q_B}{p_B}p_v\right)\log p_v,
$$

$$
\nabla C=\sum_{v\in S}\left(q_v-\frac{q_B}{p_B}p_v\right)\nabla\log p_v=-\nabla k_S.
$$

token route 因此使用 $-\operatorname{sg}(h)(\log p(a)-C)$。当 tail floor 激活，token route 使用 floored-ratio 近似，而 sequence route 对 literal clamped KL 自动微分；两者在 floor 处的 backward 不相同（`KLPO/klpo/loss.py`、`KLPO/klpo/loss.py`）。finite top-k 是 coarsened KL，只有 full-vocabulary 分支恢复 exact local KL。

Binary 把实际 action 与其补集当作两个类别，通过稳定 `log1mexp` 得到 correction $(1-q(a))/(1-p(a))$（`KLPO/klpo/loss.py`）。该 correction 一般不能在完整 sampler distribution 下精确中心化 score，因此 Binary 是近似分支，不应继承 full/independent-MC 的精确性宣称（`KLPO/klpo/loss.py`）。

### 实际训练 pipeline 与 Molt 适配

CPU toy 是可以逐步跟踪的完整最小链路：冻结 sampler snapshot -> categorical rollout -> 保存每个 visited state 的 historical full conditional、action、terminal reward 和 sampler version -> 重算 current full/action log-prob -> 从保存的 historical conditional 重新抽 auxiliary token -> loss/backward/AdamW -> 按周期发布新 sampler。采集在 `KLPO/examples/train_toy.py`，snapshot/reuse/current scoring 在 `KLPO/examples/train_toy.py`，MC draw 与更新在 `KLPO/examples/train_toy.py`。它每个 learner step 重抽 draw，从旧 trajectory 自带的 $q$ 抽取，即使已经发布了新 sampler，也不替换旧记录的行为分布。

实际 LLM 入口为 `scripts/train_molt.py`，调用 `molt.cli.train_rl_ray`，配置 one rollout per prompt、temperature=1、top-p=1、单 pass learner 和 `actor.loss_mode=klpo`（`KLPO/scripts/train_molt.py`）。默认 queue size=4 允许 bounded staleness，`--sync` 才同时开启 force-on-policy 与 force-sync；launcher 关闭额外 KL reward、advantage whitening 和 IS correction。这些 flags 说明训练策略，但本次 checkout 的 `external/labs-molt` 未初始化，不能据此声称已核实 backend 的 rollout MC record 采集实现。

`KLPOLoss` 是与 Molt 普通 actor loss 签名兼容的 adapter：虽然接收 `old_log_probs`、`advantages` 和 token count，真正传给内核的是 current log-prob、实际 `rollout_log_probs`、raw rewards 与 action mask（`KLPO/klpo/molt.py`）。它按 route/estimator 分派后，将 local response mean 乘 $B_{\mathrm{local}}N_{\mathrm{DP}}/B_{\mathrm{global}}$，抵消 DDP/FSDP 平均，保持 optimizer step 的全局 response normalization；禁止再按 gradient accumulation 次数重复除法（`KLPO/klpo/molt.py`）。这与 LSPD 的 response 内 token mean 不同：KLPO 始终先对轨迹 action token 求和，再对 response 求均值。

独立性、同一 sampled id 上的概率对齐和 trajectory 完整性都是采集合同。`_validation.py` 检查形状、mask、概率质量和数值范围，也 detach behavior/reward；它无法从一张 log-prob 张量推断 draw 是否独立、action 是否匹配 full conditional、轨迹是否语义完整（`KLPO/klpo/_validation.py`、`KLPO/klpo/_validation.py`）。

## OpenKimi 的算法对象

### 论文定义

OpenKimi 论文把 LLM 训练写成 contextual bandit：prompt 是 state，完整 response 是 action，reward 是 response-level 标量。给定旧策略 `pi_t`，理想 PMD-part 目标是

$$
\min_\pi \frac12\mathbb E_{y\sim\pi_t}
\left[\log\frac{\pi(y)}{\pi_t(y)}-
\frac{r(y)}{\tau}+\log Z_t\right]^2,
\qquad
Z_t=\mathbb E_{\pi_t}\exp(r/\tau).
$$

PMD-mean 用旧策略下的 reward mean 代替 log-partition：

$$
\min_\pi \frac12\mathbb E_{\pi_t}
\left[\log\frac{\pi(y)}{\pi_t(y)}-
\frac{r(y)-\mathbb E_{\pi_t}r}{\tau}\right]^2.
$$

论文完整推导表明，PMD-mean 的 population 解不是 Gibbs target。它由 Lambert-W 给出，并等价于带自适应 `chi^2` 正则的 mirror subproblem。这个差异在无限样本时仍然存在；增加 rollout 数量只能消除均值估计误差，不能把 PMD-mean 变回 PMD-part。

论文的假设是旧策略在 response action 空间上严格正、policy class 可实现 target、优化误差有界、log-ratio 有界。论文实验使用 binary `+/-1` response reward、每 prompt 16 个 response、temperature 1、top-p 1。`top-p=1` 是支持假设的一部分，不能把截断 rollout 直接解释成同一个无偏 PMD 目标。

### verl 实现

固定 commit 的 verl core algorithms[^source-1] 注册了三类组件：`ploo` advantage、复用 verl `rloo` advantage、以及 `opmd` policy loss。

`ploo` 对同一个 prompt 的 response rewards 计算 leave-one-out log-mean-exp partition baseline：

$$
\widehat A_i=r_i-\tau\log\left(
\frac1{K-1}\sum_{j\ne i}e^{r_j/\tau}\right).
$$

`rloo` 使用 leave-one-out arithmetic mean。两者都在 response level 构造 scalar advantage，然后把同一个 advantage broadcast 到 response tokens。`opmd` 再把整条 response 的 current/old log-prob ratio 求和，形成 sequence-level `U_i`，并计算

$$
\frac{\tau}{2}\left(U_i-\frac{A_i}{\tau}\right)^2.
$$

默认 aggregation 是每条 response 的 token mean，再对 response 做 sample mean；`pmd_ratio_agg_mode=mean` 会改变 `U_i` 本身，而不是只改变 loss 的尺度。`partition_weights` 还可以在 prompt group 内按指数 reward 权重或 reward-range filter 筛选样本。

这条实现链的数学对象是 **response-level regression**，不是 MirrorOPD 的 **prefix/token-level fixed-measure objective**。把 `U_i` 换成每 token `u_{i,j}` 并不能保持等价，因为平方与求和次序不同：

$$
\left(\sum_j u_j-A\right)^2
\ne
\sum_j\left(u_j-a_j\right)^2
$$

除非另加非常强的独立、正交或特定 advantage 分解假设。统一实现必须把 `trajectory_integral` 与 `token_integral` 作为不同 recipe，而不能只增加一个 normalization flag。

### slime 实现

固定 commit 的 slime PMD loss[^source-2] 同样先对每条 response 的 `log_prob - old_log_prob` 按 loss mask 求和，再将 sequence ratio broadcast 回 token。默认 `pmd_length_normalization=true` 只在平方 loss 后乘 `1/response_length`，不改变 sequence ratio。实现还支持 adaptive tau：依据 advantage 的上下界把 tau 置为零或缩放，这改变每 token 的有效目标，不是普通数值稳定化。

slime 的 `get_sum_of_sample_mean` 对每个 sample 单独除以 response length，再跨 sample 求和；启用 per-token loss 时改为纯 token sum。context parallel 会先重建全 response 的 mask，再做 sample reduction。这个 reducer 处理的是 response sample 的公平权重，不等同于 MirrorOPD 的 prefix token sufficient statistics。

OpenKimi 还提供 partial rollout、dynamic reward-variance filter、weight-version staleness filter 和异步 weight update。它们解决吞吐与 stale sample admission，不改变 PMD objective；但 staleness filter 只限制 weight-version span，不提供 importance correction。复用其调度时，必须把 stale age 记录到 `ProposalRecord`，不能把“被过滤”误写成“已做 off-policy 校正”。

### 已验证的实现风险

`ploo` 用 shifted exp 的 group sum 减去自己的 exp 项计算 LOO。唯一高 reward response 的其余项远小于自身时，这个减法会丢失全部有效位。CPU float64 枚举 `scores=[1,-1]`、`tau=.005`，literal kernel 的 baseline 为 `[0.9078965963,1]`，advantage 为 `[0.0921034037,-2]`；直接 masked logsumexp 的 exact LOO baseline 为 `[-1,1]`，advantage 为 `[2,-2]`。即使 float64 仍然失败，因此不能只把 dtype 提高作为修复，应直接对排除自己的集合计算 logsumexp。

`opmd` 收到 token-wise `rollout_is_weights` 后，把这些权重按 response 做算术平均。若目标是 response action 的 anchor-measure integral，则一般需要完整 response 的 joint weight，即各 token ratio 的乘积；算术均值没有该语义。统一方案允许复现这种历史 correction recipe，但禁止标注为 exact trajectory correction。

slime example 使用 `advantage_estimator=grpo` 并关闭 std normalization。这是包含主样本的 group mean center，区别于 verl 的 RLOO mean center。对 $K$ 个同 prompt samples，group-mean advantage 是 RLOO advantage 的 $(K-1)/K$ 倍；在 PMD regression 中，该因子改变 target，而不只是整体 gradient scale。两个 backend 必须记录具体 center estimator，不应以同名 PMD 宣称逐样本等价。

OpenKimi theory 定义的 half-square 与 appendix experiment loss 的系数相差常数尺度；源码使用 `0.5*tau`，论文 appendix 写 `tau`。这不改变固定 target 的最优解，却改变相同 SGD learning rate 下的步幅；Adam、epsilon 和 clipping 下更不能将这种差异忽略。

### OpenKimi 代码与论文的差异

论文把 PMD-part/mean 写成完整 response action 的回归；源码把 advantage broadcast 到 response token，再由 sequence ratio 重建 action log-ratio。论文实验说明 reward 是 `+/-1`，源码配置允许一般 reward bounds 和 adaptive tau。论文的稳定性解释依赖 Lambert-W 的 population solution；源码的 finite group、length normalization、prompt filter 和 optimizer 误差没有进入该理论保证。论文没有证明异步 partial rollout 的 stale filter 保持原始 PMD 更新，因此该功能必须作为系统 heuristic 单独报告。

## 传统 MDPO 的算法对象

### 论文定义

传统 MDPO 论文研究连续控制 MDP，不是 LLM token distribution。它的 state measure 是 discounted occupancy `rho_pi`，action measure 是当前 policy 或 replay-induced distribution。On-policy MDPO 在旧策略 `pi_k` 采样 trajectory，固定 advantage `A^{pi_k}`，对如下 proximity objective 做多步 SGD：

$$
\max_\theta\;\mathbb E_{s\sim\rho_{\pi_k}}
\left[\mathbb E_{a\sim\pi_\theta}A^{\pi_k}(s,a)
-\frac1{t_k}\operatorname{KL}(\pi_\theta\|\pi_{\theta_k})\right].
$$

旧 policy 在每个 outer iteration 固定；inner 多步更新的目的正是让 KL curvature 在第一步以后发挥作用。论文明确指出，一步更新在初始化点没有 KL gradient，退化为普通 policy gradient。论文的 on-policy `t_k` 从约 1 退火到 0，传统代码中使用 `sgd_steps` 个更新。

Off-policy MDPO 从 replay buffer 取 state，critic 学习 `Q` 与 `V`，actor 用 reparameterization 优化 `log pi_theta - log pi_theta_k - t_k Q`。这不是 token-level teacher distillation，也不是 response reward 的简单 importance-weighted score；它需要连续 action、critic、target critic 和 replay state distribution。论文还分析了 Tsallis Bregman divergence 与 SAC 的关系。

### 传统代码

固定 commit 的 on-policy implementation[^source-3] 建立 `model` 与 `oldpi` 两套 policy，rollout generator 使用 old policy。每轮先计算 GAE/advantage，并标准化 advantage，然后执行 `sgd_steps` 次 actor update；完成后通过 `assign_old_eq_new` 硬同步 old policy。代码同时训练 value function，checkpoint 保存 TensorFlow 参数和超参数。

固定 commit 的 off-policy implementation[^source-4] 使用 replay buffer、double Q、value target 和 Polyak target update。actor、Q、V 使用独立优化器；policy old network 每隔训练周期硬同步。这个实现依赖 2020 年 TensorFlow 1.x、stable-baselines、MuJoCo 和旧版 Gym，源码的 `requirements.txt` 固定了 `tensorflow-gpu==1.15.0`、`torch==1.6.0`、`numpy==1.19.1` 等环境，不能直接作为 archbox 上的 LLM trainer dependency。

代码中 `mdpo_on` 的 `meankl` 是 Gaussian distribution closed-form KL；`mdpo_off` 的 policy proximity 通过 continuous Gaussian reparameterization 和 Q estimate 近似。两者都没有 token Top-K、sampled OPD、teacher requested IDs 或 vocabulary tail。它们可以贡献 outer/inner 生命周期与硬同步概念，不能贡献 MirrorOPD 的 token estimator。

`mdpo_off` 的 `gradient_steps` 实际用于 old-policy 硬同步间隔；主训练循环每个 eligible environment step 只执行一次 gradient update。这个行为对应论文说明的跨 environment steps 累积多步近似，区别于在一个固定 replay batch 上连做 $m$ 次。actor 使用 current `qf1_pi`，并随着 critic 更新继续变化，不能把该代码解释为整个 inner 中冻结 reward/critic 的 MirrorOPD 子问题。

当前源码还存在未完成或破损路径。off-policy `reparameterize=False` 分支引用未定义的 `logp_old` 和 `logp_pi_old_action`；on-policy TensorBoard writer 分支给 `compute_lossandgrad` 的 placeholder 输入数量少于其定义。save metadata 未完整保存所有 MDPO-specific configuration，也没有保存 replay buffer。它们不作为本方案可运行的实现来源；传统代码只承担公式与历史生命周期的对照。

### 传统 MDPO 的 paper-code 差异

论文的 on-policy objective 使用未标准化理论 advantage 和 state occupancy；代码默认 GAE、advantage standardization、gradient clipping 与学习率 schedule。论文的 off-policy objective 使用 replay states 与 approximate critic；代码还加入 target-network Polyak update、double-Q 与 Gaussian-specific regularization。论文结论是连续控制 benchmark 的多步 SGD 近似，不能直接推导 LLM fixed-prefix convergence。

### 固定状态下的目标分布

为了明确锚点差别，先固定状态并采用完整词表的理想目标。A2 的状态目标为：

$$
J(p)=\sum_a p(a)d(a)-\lambda\sum_a p(a)\log\frac{p(a)}{b(a)}.
$$

加入约束 $\sum_a p(a)=1$ 的乘子 $\nu$，内点驻值满足：

$$
0=\frac{\partial}{\partial p(a)}\left[J(p)+\nu\left(\sum_jp(j)-1\right)\right]
=d(a)-\lambda\left(\log\frac{p(a)}{b(a)}+1\right)+\nu.
$$

因此：

$$
\log\frac{p(a)}{b(a)}=\frac{d(a)}\lambda+\frac\nu\lambda-1,
\qquad p^*_{\mathrm{A2}}(a)=\frac{b(a)\exp[d(a)/\lambda]}{\sum_j b(j)\exp[d(j)/\lambda]}.
$$

BPO 对应的 outer mirror 目标使用 $r_k$ 和更新后的 anchor $q_k$：

$$
F_k(p)=\sum_a p(a)r_k(a)-\frac1\eta\sum_a p(a)\log\frac{p(a)}{q_k(a)}.
$$

同样加入归一化约束，对每个 $p(a)$ 求导：

$$
0=r_k(a)-\frac1\eta\left(\log\frac{p(a)}{q_k(a)}+1\right)+\nu,
\qquad \log\frac{p(a)}{q_k(a)}=\eta r_k(a)+\eta\nu-1.
$$

归一化得到：

$$
p^*_{k,\mathrm{BPO}}(a)=\frac{q_k(a)\exp[\eta r_k(a)]}{\sum_jq_k(j)\exp[\eta r_k(j)]}
=\frac{q_k(a)^{1-\eta}t(a)^\eta}{\sum_jq_k(j)^{1-\eta}t(j)^\eta}.
$$

A2 在固定初始学生上叠加 proxy 的变化；BPO 每轮从新学生向固定教师做一次 mirror 更新。这些是固定状态、完整支持集目标的解析解。神经网络共享参数、有限 optimizer step、A2 的候选截断以及 BPO 的粗粒化中心，都使生产训练偏离逐状态精确求解。

### 首步联系与多步区别

在 A2 特殊设置 $e=t$、$v=b$、$\lambda=1$ 下：

$$
U_k=(\log t-\log b)-(\log q_k-\log b)=\log t-\log q_k=r_k.
$$

BPO 的第一个 inner 中 $p_{k,0}=q_k$，所以 $u_{k,0}=0$、$\overline D(q_k\Vert p_{k,0})=0$，其上升系数为：

$$
-c_{k,0}=r_k+\overline D(q_k\Vert t).
$$

在完整词表中心下 $D(q_k\Vert t)=-\mathbb E_{q_k}[r_k]$，故首步是中心化教师差值的 score 梯度。A2 若也用完整词表、相同状态测度和相同聚合，首步方向一致。默认 proxy base、不同动作积分和不同 center 使实际两段代码不能逐项相等。

即使人为对齐首步，多步更新仍然不同：A2 保持 utility 与 advantage 固定，使用 $p/q_k$ 改变 surrogate；BPO 保持样本测度固定，使用 $u/\eta$ 和动态学生中心改变最优性残差。把 A2 的 `ppo_epochs` 设为 16 只会重复 PPO 更新，不会生成 BPO inner。

### A2 四动作核验

四动作核验直接加载本地 `a2opd_utils.py`，设学生分布为 $(0.55,0.30,0.10,0.05)$，候选为前三个动作。候选总质量为 0.95，实际候选权重归一化为和为 1。选择 proxy expert $(0.30,0.50,0.15,0.05)$ 和 proxy base $(0.40,0.30,0.20,0.10)$，并令 target reference 等于更新前学生。

得到候选 advantage 为 $(-0.145988,0.172531,-0.026543)$，其和为 $-3.73\times10^{-9}$。直接对初始 ratio surrogate 求导，logits 梯度与负候选贡献的最大误差为 $1.86\times10^{-10}$。该核验同时确认：初始 target-anchor 偏移为零时，proxy 信号仍然产生更新；中心化的零标量 loss 可以具有非零梯度。off-anchor 核验使用未裁剪 ratio 分支，不能用它代表超过 clip 区间后的完整 PPO 梯度。数值保存在 `results/analysis/2026-10-12-a2opd-pipeline-check.json`。

## 对照的适用边界

比较必须同时固定前缀测度、动作 proposal、支持集 ID、归一化、缓存版本和停止梯度。direct KL 的数值、构造 score 的 surrogate 及平方残差不是同一个对象。PPO 只可承担有明确行为分布的 ratio/clip 合同，不能为复用 kernel 再额外乘一次已由内核承担的 IS。

完整推导和尚未实施的统一伪代码作为[理论来源](../../theory/implementation-sources/README.md)保留，不作为未来一定实现的路线。上游支持与失败路径见[后端审计](2026-10-15-上游训练框架与后端审计.md)。旧数值核验的证据在[analysis 结果](../../results/analysis)，不等于重跑六个训练项目或复现论文成绩。
