### 1.1 结果与预算的统一解释

准确率表中的数值用百分数表示，差值用百分点（pp）表示。`avg@K` 是每题独立采样 K 次后逐次判分的平均准确率，不是 K 次中至少一次正确的 `pass@K`。跨 benchmark 的平均值保持论文原来的宏平均范围；不把只平均 AIME24/25 的图与平均四个或六个 benchmark 的表混为同一指标。

教师差距恢复率与全数据收益恢复率分别为：

$$
R_T=\frac{M_t-M_0}{M_T-M_0},\qquad R_F=\frac{M_t-M_0}{M_F-M_0}.
$$

$M_0$ 是初始学生成绩，$M_t$ 是当前学生成绩，$M_T$ 是教师成绩，$M_F$ 是同一步数的全数据蒸馏成绩。两种恢复率的分母不同。训练中的 prompt 数、每题 rollout 数、全局优化 batch 和 mini-batch 分开记录；这些量在不同框架中不能仅凭名字视为相等。

### 1.2 目标与实现差异

常见 sampled-token OPD 用学生采样动作 $a$ 上的教师—学生对数概率差作为停止梯度的权重：

$$
A(s,a)=\operatorname{stopgrad}\!\left[\log\pi_T(a\mid s)-\log\pi_\theta(a\mid s)\right],\qquad \ell(s,a)=-A(s,a)\log\pi_\theta(a\mid s).
$$

这是局部 token 信号的常见实现。它与将整条后缀回报回传到每个动作的序列目标梯度有区别；P6 明确讨论了后缀回报，不能把所有论文的“reverse KL”理解为完全相同的计算图。top-k 还要区分候选集合、概率权重、集合内归一化及是否停止梯度。P3 和 P4 的具体差异分别在对应章节说明。

### 5.5 论文公式与公开代码的差别

正文式 (5) 将学生和教师在同一候选集合内分别归一化后计算 KL。固定代码的 `dp_actor.py` 中，`only_stu` 分支计算原始 log-ratio，并只将学生权重在集合内归一化：

$$
\widetilde p(v)=\frac{p(v)}{\sum_{u\in S}p(u)},\qquad A(v)=-\widetilde p(v)\,[\log p(v)-\log q(v)].
$$

这个差别在 k=1 尤其明确：若两侧都在单元素集合上归一化，则 KL 恒为 0；代码却保留该 argmax token 的原始教师—学生 log-ratio，因此能产生非零信号。本文的 top1 失败结果指作者报告的实验实现，不将它解释为数学上恒为 0 的归一化单元素 KL。

代码还对交集分支归一化权重，但对`union-intersection`（对称差）设置`normalize=False`，使用未归一化概率；空交集引起的非有限权重经`nan_to_num`置 0。因而公开代码的交集/对称差消融同时改变 support 和权重标度，不能仅凭该实验宣称两个设置具有相同梯度尺度。以上为固定代码核验，不代表已经重跑并验证其全部训练结果。

## 7. P6: TOP-D, 2607.04751

来源：Xie 等的 TOP-D 论文[^topd]。完整实现定义见§3、Algorithm1，主结果在表 2/3，1.7B 扩展评测在附录 A 表 4，全部方法的超参数在附录 B 表 5。

### 7.1 算法中需要固定的量

每个外循环开始复制 behavior policy 为$\pi_{old}$，由它生成当前 batch。proximal teacher 按 token 条件分布做算术插值：

$$
\widetilde\pi_T=\alpha\pi_T+(1-\alpha)\pi_{old},\qquad \widetilde r_t=\log\!\left(\alpha\frac{\pi_T(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)}+1-\alpha\right).
$$

无需真的部署第三个模型；用缓存的 teacher 与 behavior log-prob 即可计算。它不是将 log-prob 线性插值，因为后者仅缩放原始 reward。Algorithm1 在内循环之前计算 reward、return 和 advantage，之后固定这些量；不能在每个 mini-batch 把分母替换为不断更新的学生，再声称复现了同一算法。

return 使用即时 reward 加长度归一化的未来 reward：

$$
\widetilde R_t=\widetilde r_t+\frac{1}{L-t}\sum_{j=t+1}^{L}\widetilde r_j.
$$

同一 prompt 的全部 response、全部有效 token 共同计算均值和标准差后标准化；policy loss 用当前策略与 behavior 策略的 token importance ratio，采用 PPO clipped surrogate，并按该组总有效 token 数归约。式 (8) 在最后 token 出现分母 0，论文未明确终止位置的代码回退；复现时须显式约定最后 token 未来项为 0，并标明这是实现选择。标准差为 0 时的 epsilon 也未披露。

| α敏感性                 | α={0.1,0.2,0.3}，相同 1.7B/30B 组合                                  | 稳定性、收敛速度、末期成绩差距小；没有数值表或置信区间             |
| 学习曲线                | 8B 各方法 AIME24/25/26；1.7B 消融 AIME 三项，图示到 400 步           | 结果见图 2、5；不从曲线补造末步精确值                              |

所谓“零额外开销”指不增加独立教师模型前向、reward 可代数变换，并非论文给出了端到端耗时持平的 benchmark。内循环 mini-batch 更新的总算力与不同基线的步数仍需独立计量。论文的单调改进结论依赖其理论下界与假设，不能直接替代有限 batch、PPO clipping 实训的逐步单调性验证。

### 7.5 复现缺口

AdamW betas、epsilon、weight decay、scheduler、梯度 clip、micro-batch、精度、奖励/advantage 终止处理、decoding top-k、完整模型 chat template 与 thinking 模式、GRPO/DAPO 奖励判分实现、Olympiad 具体版本、训练 seed、逐方法精确步数、逐运行α选择、评测频率和 checkpoint 选择均未完整披露。论文和所查索引未给 TOP-D 官方代码，不能套用另一篇名称相近的 Trust Region OPD 实现。

## 8. 六篇实验的可比性与复现优先信息

| 维度         | 直接比较时需要保留的区别                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| 初始学生     | Base、SFT、Instruct、RL 后训练学生具有不同起点；P4/P6 Base 实验不能与 P1 默认 instruction 学生作同难度比较 |
| 教师关系     | 同源 RL 后训练、跨规模同 pipeline、跨源 SFT、专家教师均不同；模型参数量不能替代教师—学生兼容性             |
| 学习率       | P1/P3/P4/P5/P6常用$10^{-6}$；P2为$10^{-5}$，量级不同                                                       |
| token 支持   | sampled action、student top-k、双方交集、对称差及归一化方式不同；P4 代码尤其需要检查                       |
| rollout 来源 | 当前学生、初始学生固定缓存、教师、SFT 后学生缓存含义不同；“off-policy”本身不足以描述训练输入               |
| 数据量       | unique query 数、prompt 实例数、独立轨迹数、有效 token 总量分别计量；一题可以反复生成大量状态              |
| 长度         | P1 常用 4K/16K 训练、32K/40K 评测；P2 达 40K/64K/96K sequence；P3/P4 默认 7,168；P6 为 16,384              |
| 优化预算     | 相同 step 不等于相同 rollout 数、optimizer update 数或 token 预算；P6 标准 OPD 与 TOP-D 的 mini-batch 不同 |
| loss 归约    | token 平均、序列内 token 平均再按序列平均会改变长短 response 的权重；P3 单教师与 MOPD 不同                 |
| 评测         | temperature、top-p、采样数、长度、thinking 模式、system prompt、benchmark 版本、判分器均需匹配             |
| 统计         | seed 重复、checkpoint 均值、平滑曲线、rollout 子采样误差是不同概念；不能互相替代                           |
| 成本         | GPU-hour 须明确包含离线采样/教师打分/训练/评测的哪些阶段，并记录 GPU 型号、并行及长度                      |

若以这六篇论文作为 MirrorOPD 实验对照，最先需要补齐的是运行级配置快照：初始化 checkpoint 精确身份、rollout 策略冻结与同步顺序、采样参数、每批更新次数、归约方式、评测生成与判分配置，以及累计有效 token 和 GPU-hours。本文只整理外部研究证据，没有把这些论文的算法变体加入 MirrorOPD 当前生产算法。
