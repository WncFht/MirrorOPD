# 六篇 OPD 论文的训练设置、评测协议与结果调研

更新日期：2026-10-15。范围：用户指定的六篇论文的正文、附录、数值表、训练曲线、消融及可核对的官方实现。本文整理作者报告的实验，没有重新训练模型。在线策略蒸馏（On-Policy Distillation，OPD）、多教师在线策略蒸馏（Multi-Teacher On-Policy Distillation，MOPD）、监督微调（Supervised Fine-Tuning，SFT）和可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards，RLVR）在下文固定使用这些缩写。

## 横向总结：参数、任务域与教师—学生组合

六篇论文中，OPD 的默认学习率主要是 **$10^{-6}$**，P2 的 OPD/MOPD 使用 **$10^{-5}$**；P3 另测了 $5\times10^{-7}$ 和 $2\times10^{-6}$。batch 常见名义值为 64、128、512，但必须同时看 prompt 数、每题 response 数和一次更新实际使用多少样本。训练域共 **数学、代码、科学、指令遵循、工具调用** 五类，另有通用对话与无题目模板作为输入的消融。

能精确排序的最大一组是 P1 的 **17 个初始 top-64 overlap**。其中最低的是 **Qwen3-1.7B (non-thinking)←Qwen3-235B-A22B-Instruct-2507 (non-thinking)，56.9%**；其次是 **Qwen3-1.7B (thinking)←Qwen3-30B-A3B-Thinking-2507 (thinking)，58.9%**。P1 另做的 Base 学生对照更低：**Qwen3-1.7B-Base (thinking/non-thinking 未披露)←Qwen3-4B (non-thinking)，55.2%**，但它不属于这 17 组主扫描。以下按可比指标分开列出，P2/P3/P4 的 top-16 不与 top-64 合并排名。

### batch 的实际计量

为避免把 batch=64 理解成相同预算，下面把生成条数和更新分批分开。response 数是由论文 prompt 数乘每题 rollout 数计算的名义值，动态筛选等实现仍可能改变实际有效样本。

| 论文 / 方法       | 每批 prompt         | 每题 response | 名义生成 response          | 一次更新的 batch 或 mini-batch                                          |
| ----------------- | ------------------- | ------------- | -------------------------- | ----------------------------------------------------------------------- |
| P1 OPD / Semi-OPD | 128                 | 1             | 128                        | global128；mini-batch 未披露；Semi-OPD 从固定缓存读取                   |
| P2 OPD / MOPD     | 128                 | 4             | 512                        | mini-batch 与每批更新次数未披露                                         |
| P3 单教师 / MOPD  | 64                  | 1             | 64                         | rollout batch64、mini-batch64；MOPD 改用序列平均归约                    |
| P4 OPD            | 表中 global batch64 | 4             | 按 64 个 prompt 计算为 256 | 表中 mini-batch64；展开 response 后的内部切分需结合实现                 |
| P5 OPD            | rollout prompts300  | 8             | 2,400                      | 另报 global optimization batch64；与 rollout 池的完整对应未披露         |
| P6 标准 OPD       | 512                 | 8             | 4,096                      | 512 个 prompt/4,096 个 response，1 个 mini-batch                        |
| P6 TOP-D          | 512                 | 8             | 4,096                      | 每 mini-batch32 个 prompt/256 个 response，共 16 个；off-policy epoch=1 |

### 1.1 结果与预算的统一解释

准确率表中的数值用百分数表示，差值用百分点（pp）表示。`avg@K` 是每题独立采样 K 次后逐次判分的平均准确率，不是 K 次中至少一次正确的 `pass@K`。跨 benchmark 的平均值保持论文原来的宏平均范围；不把只平均 AIME24/25 的图与平均四个或六个 benchmark 的表混为同一指标。

教师差距恢复率与全数据收益恢复率分别为：

$$
R_T=\frac{M_t-M_0}{M_T-M_0},\qquad R_F=\frac{M_t-M_0}{M_F-M_0}.
$$

$M_0$ 是初始学生成绩，$M_t$ 是当前学生成绩，$M_T$ 是教师成绩，$M_F$ 是同一步数的全数据蒸馏成绩。两种恢复率的分母不同。训练中的 prompt 数、每题 rollout 数、全局优化 batch 和 mini-batch 分开记录；这些量在不同框架中不能仅凭名字视为相等。

### 1.2 目标与实现差异

常见 sampled-token OPD 用学生采样动作 $a$ 上的教师—学生对数概率差作为停止梯度的权重：

$$
A(s,a)=\operatorname{stopgrad}\!\left[\log\pi_T(a\mid s)-\log\pi_\theta(a\mid s)\right],\qquad \ell(s,a)=-A(s,a)\log\pi_\theta(a\mid s).
$$

这是局部 token 信号的常见实现。它与将整条后缀回报回传到每个动作的序列目标梯度有区别；P6 明确讨论了后缀回报，不能把所有论文的“reverse KL”理解为完全相同的计算图。top-k 还要区分候选集合、概率权重、集合内归一化及是否停止梯度。P3 和 P4 的具体差异分别在对应章节说明。

若以这六篇论文作为 MirrorOPD 实验对照，最先需要补齐的是运行级配置快照：初始化 checkpoint 精确身份、rollout 策略冻结与同步顺序、采样参数、每批更新次数、归约方式、评测生成与判分配置，以及累计有效 token 和 GPU-hours。本文只整理外部研究证据，没有把这些论文的算法变体加入 MirrorOPD 当前生产算法。
