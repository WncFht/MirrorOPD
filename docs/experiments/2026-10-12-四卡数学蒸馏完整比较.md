# 四卡数学蒸馏完整比较

## 完成情况与判断

full on-policy、MDPO 和 BPO 均完成用户要求的 50 个 outer。on-policy 每轮一次更新，总计 50 次；MDPO 和 BPO 每轮 16 次更新，各计 800 次。三组均正常退出，完整本地记录与在线 W&B 已核验，每组保留初始化及每五轮一次的 11 次全量 570 题评测。监督程序最终状态为 `all_runs_verified`，逐项证据见 [完成审计](../../results/training/math-4gpu/final-completion-audit.json)。

这组四卡配置完成了三种算法的训练链路，显存采样峰值最高 35.90 GiB。三组在 MATH-500 和 AMC23 上的最终成绩均高于各自起点；AIME25 只有 MDPO 最终高于起点。教师对齐诊断下降与测试准确率的变化分别反映蒸馏对齐和数学答题结果，本次长响应预算下，两者没有形成全程一致的改善关系。

## 配置与比较单位

学生为 DeepSeek-R1-Distill-Qwen-1.5B，教师为 JustRL-DeepSeek-1.5B，训练与测试保持原 MD-OPD 的 DAPO、MATH-500、AMC23、AIME25 数据。三组均从原始学生权重开始。完整参数、环境修复、预检与数据校验见 [实验设计](2026-10-12-四卡数学蒸馏实验.md)，实际解析的配置差异见 [配置比较](../../results/training/math-4gpu/formal-config-comparison.json)。

| 共同设置                             | 值                                                       |
| ------------------------------------ | -------------------------------------------------------- |
| 物理 GPU / 并行                      | 0–3 / FSDP=4、TP=1、SP=1                                 |
| 全局 batch / mini-batch / 每题生成数 | 64 / 64 / 1                                              |
| actor / anchor / teacher micro-batch | 1 / 1 / 1，动态 batching 关闭                            |
| AdamW                                | lr=1e-6，weight decay=0，gradient clip=2                 |
| eta / Tail-aware Top-k               | 0.3 / 16                                                 |
| prompt / response / context          | 2048 / 7168 / 9216 token                                 |
| 训练 / 测试生成                      | temperature=1、top-p=1、top-k=-1 / greedy、temperature=0 |
| 参数与计算精度                       | FP32 存储、BF16 前向、FP32 reduce/buffer                 |
| 显存控制                             | 参数与优化器 offload，gradient checkpointing             |
| vLLM                                 | memory utilization=0.25，每 replica 最多 32 条序列       |
| 验证                                 | 整批 570 题排队，outer0/5/10/…/50 各一次                 |
| 数据与模型种子                       | 42；生成 replica 种子 0–3                                |

正式配置仅在算法、inner 次数和运行专属路径上存在差异。on-policy 与另外两组的优化更新量相差 16 倍；这是相同 outer 数的比较。三组单种子初始化 greedy 成绩也存在差异，因此改善量使用各自初始化评测。

## 全量测试结果

单元格按“初始化 → outer50 最终（变化百分点）”表示。所有成绩使用相同的 7168 token 响应预算和评分协议。

| 方法            | MATH-500，500 题      | AMC23，40 题         | AIME25，30 题            |
| --------------- | --------------------- | -------------------- | ------------------------ |
| on-policy，50×1 | 69.4% → 74.6%（+5.2） | 52.5% → 65%（+12.5） | 16.67% → 10%（-6.67）    |
| MDPO，50×16     | 70.6% → 77.4%（+6.8） | 47.5% → 52.5%（+5）  | 16.67% → 20%（+3.33）    |
| BPO，50×16      | 69.2% → 75.2%（+6）   | 47.5% → 60%（+12.5） | 16.67% → 13.33%（-3.33） |

MDPO 在本次最终 MATH-500 和 AIME25 上取得三组最高成绩，on-policy 在最终 AMC23 上最高。MDPO 与 BPO 在教师对齐诊断上的轨迹接近，最终测试结果仍有差异。完整轨迹包含 MDPO outer10 的成绩回落，以及 BPO outer20 的 AIME25 高点；统一采用预先安排的 outer50 结果。

| 方法      | 最终 MATH / AMC / AIME 正确数 | 最终 MATH / AMC / AIME 预算耗尽率 |
| --------- | ----------------------------- | --------------------------------- |
| on-policy | 373 / 26 / 3                  | 27.6% / 40% / 90%                 |
| MDPO      | 387 / 21 / 6                  | 25.6% / 52.5% / 73.33%            |
| BPO       | 376 / 24 / 4                  | 27% / 52.5% / 83.33%              |

AIME25 的最终预算耗尽率为 73.33%–90%。本次统一预算是四卡长响应链路预检后选定的保守设置，原实验更长的生成预算需要另行验证。只有一个种子，且没有逐题配对输出，三组结果不足以给出跨种子的方法优劣结论。原始 DAPO 与 MATH-500、AMC23、AIME25 的精确题目重叠分别为 2、5、0 条，保持原始数据的同时记录其对泛化解释的限制。

## 教师对齐、reward 与更新稳定性

下表的窗口均为前十与后十个 outer。KL center 与 sampled reward 使用每个 outer 更新前的 inner_step=0 快照，验证器分数使用对应训练批。

| 方法      | Tail-aware teacher KL center | sampled reward        | 训练验证器分数      |
| --------- | ---------------------------- | --------------------- | ------------------- |
| on-policy | 0.100426 → 0.054077          | -0.109688 → -0.057712 | 0.345313 → 0.468750 |
| MDPO      | 0.044978 → 0.002794          | -0.048519 → -0.002503 | 0.453125 → 0.570313 |
| BPO       | 0.044319 → 0.002807          | -0.047300 → -0.002555 | 0.478125 → 0.564063 |

Tail-aware KL 把选出的 16 个 token 和尾部桶作为支持，是完整词表 KL 的下界。图中的负采样 reward 对应冻结 rollout 上的 sampled reverse KL 估计；在每轮起点，学生与锚点同步，因此三方法按相同起点口径展示。生成前缀和长度分布逐轮变化，固定前缀的完整词表 KL 仍需独立评测。

MDPO 将动作重要性比率用于梯度系数，BPO 使用冻结 rollout 权重。BPO 的 ESS 和重要性比率仅用于诊断；图的 ESS 面板按这个口径阅读。三组起点同步均在约 1e-7 的 RMS 浮点误差范围内，冻结缓存保持一致，所有更新指标有限。

| 方法      | 更新数 | 梯度范数范围 | 裁剪次数 |  最低 ESS 比例 | GPU 采样峰值 | 训练 outer 均值 |
| --------- | -----: | -----------: | -------: | -------------: | -----------: | --------------: |
| on-policy |     50 |  0.525–1.408 |        0 |           约 1 |    35.88 GiB |        96.15 秒 |
| MDPO      |    800 |  0.031–1.275 |        0 |       0.992315 |    35.88 GiB |       218.82 秒 |
| BPO       |    800 |  0.030–4.166 |        1 | 0.992093，诊断 |    35.90 GiB |       220.72 秒 |

耗时字段不含初始化及周期评测，GPU 峰值来自定期采样。BPO 唯一一次裁剪位于 outer_call11/inner_step3，下一次梯度范数为 0.15468。MDPO outer10 性能回落时重新检查了原公式、生产系数、EOS 与预算末 action、缓存冻结、全局 token 归约和权重同步，未发现能支持算法缺陷判断的证据；完整推导及枚举梯度实验见 [回落检查](2026-10-12-MDPO前十步性能回落检查.md)。
