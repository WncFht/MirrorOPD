# One-Shot 长期吸收与有效时间消融设计

## 目标与预测

本实验检验固定监督的长期吸收、BF16 小步更新的数值效应，以及学习率与 optimizer 更新数的乘积是否解释主要时间尺度。原始学生为 DeepSeek-R1-Distill-Qwen-1.5B，教师为 JustRL-DeepSeek-1.5B。实验在结果产生前固定以下预测与判据。

1. BF16 首步台阶：零学习率更新后的 anchor–student KL 均值应小于 $10^{-6}$，RMS 应小于 $10^{-5}$；BF16 首次 lr=$10^{-6}$ 更新后的 KL 预测为 $10^{-4}$～$10^{-3}$。相同输入下改变学生前向精度，应改变首步幅度或后续早期轨迹。若零更新也产生台阶，优先调查评分路径与训练路径差异。
2. 固定监督持续学习：标准学习率的 frozen OPD 在 update100 后仍应改善固定动作平均绝对 log-prob 差。预注册长期吸收判据为 $d_{200}/d_{100}\le0.8$ 且 $d_{300}/d_{100}\le0.7$，至少两个种子满足。完整词表 KL、Top-16 overlap 与数学准确率独立报告，防止单个动作指标掩盖分布失配。
3. 有效时间：定义 $u=(\mathrm{lr}/10^{-6})t$，$t$ 只计真实 optimizer 更新。学习率为 $5\times10^{-7},10^{-6},2\times10^{-6}$，分别训练 600、300、150 次更新，三组终点均为 $u=300$。预测按有效时间对齐后的对数距离离散度，比按原始 step 对齐至少降低 30%。同一数值网格 $[30,150]$ 上比较两种横轴，完整 $u\in[30,300]$ 另报。FP32 frozen 的中后期配对距离预测在 20% 以内；BF16 早期更容易偏离。
4. 镜像内层：$\eta=0.3$ 时，anchor–student KL 保持较小仍应伴随非零当前教师距离与非零目标误差。冻结初始锚点与每 16 次更新重设锚点的两种条件，应产生不同的 student center 外观。目标误差按每轮目标 $p^*\propto q^{0.7}T^{0.3}$ 评分，不用 student center 代替。

判据失败时保留原结果，报告失败区间及对应精度、裁剪和优化器状态。AdamW 的动量、二阶矩、裁剪、有限步长与低精度舍入均会破坏精确时间缩放；本实验检验的是给定配置中的近似关系。

## 与论文的对应

One-Shot OPD 第 5.3 节冻结初始学生从同一个 query 采得的 64 条轨迹，观察数百步内的对齐与测试改善；附录 C.2 对在线 one-shot 在半倍、标准与两倍学习率下展示时间轴缩放[^oneshot]。本实验分别运行 frozen 与 online。两类训练各自比较学习率，避免把固定状态与变化状态混成同一个因果判断。

训练 batch 与 mini-batch 均为 64，每次更新使用全部 64 条轨迹，micro-batch 为每卡 1 条。每个 seed 的 frozen 轨迹跨学习率、学生精度和镜像条件复用，固定 tokens、EOS 及预算截断状态。在线条件每次更新重新从当前学生采样 64 条响应。

## 实验矩阵

种子为 42、142、242。主要 prompt 为历史实验及论文的 t22，读取 `MD-OPD/data/math/DAPO-oneshot/t22.parquet`，核对 64 行是否为同一个 prompt。prompt 保留原始文本，响应上限为 7168 token，temperature=1、top-p=1、top-k 关闭，EOS 自然终止。响应达到上限时保留最后一个预测动作，并记录截断比例。

| 条件                            | 学生前向    | 学习率             | 更新数          | 种子数 | run 数 |
| ------------------------------- | ----------- | ------------------ | --------------- | -----: | -----: |
| frozen sampled OPD              | BF16        | 5e-7 / 1e-6 / 2e-6 | 600 / 300 / 150 |      3 |      9 |
| online sampled OPD              | BF16        | 5e-7 / 1e-6 / 2e-6 | 600 / 300 / 150 |      3 |      9 |
| frozen sampled OPD              | FP32        | 5e-7 / 1e-6 / 2e-6 | 600 / 300 / 150 |      3 |      9 |
| frozen MDPO，固定初始锚点       | BF16        | 1e-6               | 300             |      3 |      3 |
| frozen BPO，固定初始锚点        | BF16        | 1e-6               | 300             |      3 |      3 |
| frozen MDPO，每 16 更新重设锚点 | BF16        | 1e-6               | 800             |      3 |      3 |
| frozen BPO，每 16 更新重设锚点  | BF16        | 1e-6               | 800             |      3 |      3 |
| 零学习率控制                    | BF16 / FP32 | 0                  | 4               |      3 |      6 |

计划 45 个 run、16074 次 optimizer 更新。该矩阵同时提供跨学习率、跨种子、跨精度和锚点生命周期的消融。canary 单独执行，用于验证长响应、全局 token 归约、评分路径与 GPU 资源控制；canary 不能替代上述正式 run。在线 run 成本包含重复生成，按实际预检速度记录预算。

所有条件使用 FP32 master 参数，AdamW 的 $\beta_1=0.9$、$\beta_2=0.999$、$\epsilon=10^{-8}$、weight decay=0.01、clip norm=1，与论文默认优化器配置对应。学习率恒定，无 warmup。镜像两方法均使用生产缓存与 loss 核，Top-16 加尾部桶、$\eta=0.3$。教师固定为 BF16 前向定义的分布，学生精度消融保持教师监督一致。

## 测量与判分

每次 optimizer 更新记录更新前后的计数、学习率、累计有效时间、全局有效 token 数、梯度范数、裁剪比例、anchor–student Tail-aware KL、冻结 teacher center、sampled reward、当前固定动作绝对差与 RMS、surrogate 梯度系数和重要性比率。更新前后的测量时点分别标识；第 16 次更新后的结果需要独立评分。

完整词表诊断使用每个 seed 固定抽取的 4096 个响应预测位置。抽样在全部有效响应 token 中均匀无放回完成，保持前缀、动作、抽样位置与权重跨条件一致。每 5 次更新及预注册时间点评分当前学生的完整词表反向 KL、正向 KL、Top-16 overlap、镜像目标误差和尾部条件 KL。完整词表诊断与生产 Tail-aware 指标分开存储。

保存共同有效时间 $u=0,50,100,200,300$ 的模型，并在训练进程结束后依次执行完整 570 题评测：MATH-500、AMC23 与 AIME25。统一 greedy、7168 token 上限，保存逐题输出、正确性与预算耗尽状态。镜像条件按真实 optimizer 更新数保存 0、50、100、200、300；800 步条件另保存 800。题目、评分实现和模型快照的 SHA-256 入档。

曲线从 step0 绘制，同时展示原始 update 轴和有效时间轴。距离使用论文的平均绝对差与完整词表 KL 分别绘制。主要时间缩放评分在固定网格上插值 $\log d$，计算三个学习率之间的对数离散度及最大/最小距离比。先报每个 seed，再报跨 seed 均值和区间，不用平滑曲线替代原始数据。稀疏准确率只在实际评测点比较。

## GPU 隔离与执行顺序

所有 GPU 子进程固定 `CUDA_VISIBLE_DEVICES=0,1,2,3`。启动前检查四张卡的计算进程及显存占用，任一张卡被其他进程使用时保持等待。只运行一个实验 job，job 内四个 distributed rank 属于同一个实验。下一阶段必须等待上一阶段所有 GPU 子进程退出、四张卡再次空闲。

资源监督程序持有 GPU0–3 的共享工作区锁，记录各 rank 的 driver 进程标识并检查外来 GPU 进程。检测到资源冲突时停止本实验子进程，保留已完成 checkpoint 和日志，等待资源恢复；不终止其他会话进程，不在剩余卡上继续混跑。GPU4–7 不进入可见集合。

启动顺序为 CPU 核验、长响应 canary、固定轨迹准备、三个种子的主条件、在线条件、镜像条件及完整评测。实验失败按真实进程退出与错误记录处理；观察工具超时不构成重启理由。完整训练、数据和报告均在当前工作区保留，提交只包含源码、设计与可引用的统计证据。
