# 训练启动条件与实验设置

## 当前可执行范围

本仓库维护 MirrorOPD 核心包、训练入口和上游集成补丁。补丁修改 TA-OPD/verl 的调用位置，运行时导入 `src/mirroropd/`，因此补丁与核心包共同构成可执行实现。补丁是源码集成方式，不是 Python 运行时加载格式。

当前训练入口默认使用 `~/src/mirroropd-taopd/.venv/bin/python` 和该目录内的 `verl/`，同时将本仓库 `src/` 加入 `PYTHONPATH`。`make upstream` 重建的是本仓库的 `upstream/TA-OPD/`；它不自动更新独立的 archbox 运行目录，也不安装 CUDA 依赖。两个路径必须显式区分。

2026-10-08 的只读核验显示：本机为 Apple M4、16 GB 内存；archbox 为 RTX 4070 SUPER、12 GB 显存，已有训练 Python 环境，但没有 `~/src/mirroropd` 新仓库，远端损失文件仍内嵌提取前的函数。新布局完成 CPU 验证和补丁重放，尚未完成远端部署与提取后 GPU 验证。

远端启动新布局之前，必须部署同一提交的核心包、训练脚本和补丁，在固定上游基线上重放补丁，并确认远端 Python 实际导入部署的核心文件。已有远端源码有本地改动时，先核对差异，保留运行产物，不能直接覆盖或重复叠加补丁。随后依次进行 canary、恢复验证和真实数据训练。

## 支持集与 KL 方向

官方 TA-OPD 使用 teacher Top-k 支持集，记 student 为 $p$、teacher 为 $q$，$S=\operatorname{TopK}(q,k)$。把支持集外 token 合并成一个类别后，优化

$$
\sum_{v\in S}p(v)\log\frac{p(v)}{q(v)}
+p(S^c)\log\frac{p(S^c)}{q(S^c)}.
$$

这是粗粒化分布上的 $\operatorname{KL}(p\Vert q)$。Normalized 版本在同一个 teacher 支持集上分别归一化 student 和 teacher。官方 README 给出这两个目标与 sample-corrected 版本[^ta-readme]；代码中的 loss 是判断实际梯度的依据[^ta-loss].

本仓库 Mirror 模式以 rollout anchor $\pi_k$ 的 Top-k 建立固定缓存，估计的是 $\operatorname{KL}(\pi_k\Vert\pi_\theta)$ 与 $\operatorname{KL}(\pi_k\Vert\pi_T)$。第二个 KL 在 outer 内冻结，第一个随 inner 更新。它们不能直接替换成官方当前 student 与 teacher 的 KL；支持集来源、左侧分布、冻结规则和梯度位置都不同。

官方 sample-corrected 分支带停止梯度和 score 修正。分析该训练 surrogate 与 KL 数值估计时，应分别写出目标与估计量。比较两个代码库的曲线之前，必须检查它们是否估计同一个 KL、使用同一个支持集。

## 单卡 MirrorOPD 实验方案

本方案验证两个命题：在相同 rollout 预算下，有限 inner 更新与 hard sync 能否稳定推进；Tail-aware center 的误差如何影响实际 KL 与任务表现。失效判据包括非有限梯度、缓存或 rollout 版本不一致，以及在足够 seed 下持续恶化的 full-vocab KL 或任务表现。只看停止梯度 surrogate loss 的下降不能判定收敛。

已有可执行模型组合为 Qwen3-0.6B student、Qwen3-1.7B teacher、LoRA rank 8 / alpha 16、BF16、单 GPU、sequence parallel size 1。它用于已有训练链路的回归验证。大规模 inner-budget 扫描优先采用下文的更小模型。Qwen3-1.7B student / 4B teacher 留作资源允许后的扩展；它在当前 12 GB 训练配置上尚未验证。

Qwen 数学任务实验使用 GSM8K。固定 seed 从官方训练集划分互不重叠的 1024 条训练样本和 128 条验证样本，保存样本 ID；完整训练后使用官方测试集评测。超参数只根据训练与验证选择。链路 canary 的四条算术 prompt 不用于科学结论。

初始资源探测采用 prompt 上限 512、response 上限 256，关闭 thinking。正式 pilot 目标为 response 上限 1024；同步调整 vLLM 的模型长度与 batched-token 预算，并先测真实峰值显存。长度配置属于待验证方案，现有 64-token canary 不证明它可运行。保存 EOS、长度截断与生成长度分布；长度上限前未终止的轨迹按截断轨迹报告，不能描述成完整 rollout。

每个 prompt 一条 rollout，温度 1、top-p 1、关闭采样 top-k，确保动作分布与用于缓存的分布匹配。温度 0.7 作为独立配置，改变温度时统一修改 rollout 与 teacher/anchor/student 概率定义。训练 prompt batch 先取 4，mini-batch 4、micro-batch 1；若显存不足，先减并发和 micro-batch，不静默改变目标与 token 预算。一个 outer 内保持缓存冻结，完成 inner 更新后 hard sync，再生成下一批数据。

先固定 `eta=0.1`、Top-k 32、inner epoch 2 和 100 个 outer，作为调试后的 pilot；每个 mini-batch 的 optimizer step 数写入记录。随后分别扫描 `eta` 为 0.1、0.3、1，inner epoch 为 1、2、4。Top-k 误差实验固定轨迹，扫描 0 到 32；它与每次重新 rollout 的训练效果实验分别报告。独立训练条件至少使用三个 seed，数据划分固定。

学习率先延续现有可执行值 `1e-5`，随后在固定算法与 `eta` 下用验证集选择。PMD-mean 和 BPO 的梯度尺度随 `eta` 的变化不同；共同学习率的结果不能被解释成纯粹的算法几何差异。除相同学习率对照，还应报告理论尺度匹配的对照：若以 PMD-mean 为参照，BPO 取 `lr_BPO = eta * lr_PMD`，使两者在 inner 初始化处的 reward 梯度尺度一致。后续梯度的 center 差异仍然存在，这个调整不使两种方法等价。Adam 的自适应尺度与 epsilon 还会改变实际参数更新，需同时记录更新范数。

评估包括任务正确率、完整词表的两个 Mirror KL（在固定抽样 prefix 上离线计算）、Top-k center 的 bias/variance/RMSE、梯度范数、参数更新范数、MDPO importance ratio 分布、rollout 版本和生成长度。缓存空间与 GPU 峰值按实际张量形状记录。以不同随机性计算的估计方差与 prefix 间的差异分别报告。

## 基线与入口边界

当前共用 launcher 只接受三种 Mirror 模式，默认关闭原生 teacher GPU pool，使用冻结 FSDP teacher 缓存。不能仅将 `loss_mode` 改成原生 TA-OPD 就认为完成基线切换。官方 baseline 使用原生 teacher top-k 推理路径；单卡适配该路径还需要独立的配置与链路验证。

基线分成 vanilla sampled-token OPD、Normalized Top-k 和 Tail-aware Top-k。先复用官方原生损失及其支持集定义，保持相同模型、prompt、rollout token 预算和评测方式；明确 teacher Top-k baseline 与 anchor Top-k Mirror center 的不同。Full-vocab OPD 在小规模离线 prefix 上作为数值参照，资源许可后才纳入训练基线。EMA 估计实验与参数 EMA outer sync 是两个变量，第一轮训练只用 hard sync。

本机 Mac 用于 CPU 数学与 causal-LM 集成验证、真实模型的离线评分及结果分析。当前 TA-OPD CUDA/vLLM/FSDP 训练链路在 archbox 运行。CPU 集成测试使用随机初始化 tiny GPT-2，检验语义，不代表预训练模型的 GSM8K 蒸馏效果。

## 更小模型的动力学实验

沿用先前选型：第一阶段使用 Pythia-14M student / Pythia-70M teacher，第二阶段使用 Pythia-31M / 160M 作为规模对照。官方模型配置中，14M 和 70M 均为 GPT-NeoX causal LM，模型输出词表大小为 50304[^pythia14][^pythia70]。小模型阶段优先全参数更新，关闭现有 Qwen 的 LoRA 默认值；这样也能避免把 LoRA 子空间限制混入 inner 收敛分析。模型变小不会自动完成框架兼容性验证，GPT-NeoX 的 actor、冻结 teacher 和 vLLM 链路仍须运行 canary。

2026-10-08 直接核对官方 tokenizer JSON：14M/70M 的 vocabulary-to-ID 映射、BPE merges、added tokens、normalizer 和 pre-tokenizer 相同，但 post-processor 与部分序列化配置不同。不能宣称两个 tokenizer 文件逐字节一致。实验统一加载一个 tokenizer，明确 special-token 处理，并核对实际输入 ID 与模型输出维度。

较新的备选为 SmolLM2-135M student / SmolLM2-360M teacher，二者均为 Llama 架构、输出词表大小为 49152[^smol135][^smol360]。此次核对两个 `tokenizer.json` 的 SHA-256 完全相同，均为 `9ca9acddb6525a194ec8ac7a87f24fbba7232a9a15ffa1af0c1224fcd888e47c`。此前早期审计中声称 SmolLM2 没有同系列小模型配对的表述已纠正；135M/360M 可以组成同 tokenizer 配对。该组合比 Pythia-14M/70M 大，适合作为架构与模型代际对照。

小模型主实验使用 WikiText-2 等自然文本的固定长度 prefix 和自由续写：训练 prefix 来自训练 split，诊断 prefix 来自独立验证 split，保存 ID、tokenizer 版本和截取规则。初始 prompt 64、生成上限 64、每个 prompt 一条轨迹、温度 1。保留 EOS 和长度截断记录。测量两个 Mirror KL、student/teacher KL、残差、梯度范数及 held-out 文本指标。Pythia-14M/70M 的 GSM8K 正确率不适合作为动力学实验的首要判据；teacher 参数量更大也不保证每个 prefix 上更优。

## 全量 rollout 更新与梯度累积

记每个 outer 的 prompt 数为 $B$，每个 prompt 的轨迹数为 $N$，则 rollout batch 有 $BN$ 条轨迹。prompt batch 决定本轮访问哪些问题；mini-batch 决定一次 optimizer step 纳入多少轨迹；micro-batch 决定一次 forward/backward 实际加载多少轨迹。epoch 表示对固定 outer rollout 完整遍历一次。

当前 TA-OPD 的 `ray_trainer.py::_update_actor` 将 `ppo_mini_batch_size` 乘以 `rollout.n` 后传给 engine。因此设置 `data.train_batch_size=B`、`ppo_mini_batch_size=B`，实际 optimizer batch 是 $BN$ 条轨迹。单卡 micro-batch 为 $m$ 且可整除时，每个全量 inner step 累积 $BN/m$ 次 backward，仅执行一次 optimizer step。mini-batch 配置为 $b<B$ 时，每个 epoch 执行 $B/b$ 次 optimizer step，$E$ 个 epoch 的更新次数为 $E B/b$。padding、过滤、动态 batch 和多卡布局发生变化时以实际执行计数为准。

第一阶段采用 $B=16$、$N=1$、`ppo_mini_batch_size=16`、micro-batch 1。这样每个 inner epoch 是一次全量 rollout 梯度更新，反复更新 $J$ 次就对应 $J$ 个 epoch，减少 mini-batch 顺序对动力学比较的影响。无需让 16 条轨迹同时驻留 GPU。外层缓存与支持集在这 $J$ 次更新内冻结，每次全量更新重新计算当前 student 及其 center，最后 hard sync 并重新 rollout。

token-mean 目标的有效 response token 总数记为 $M$，micro-batch $j$ 的有效 token 数记为 $M_j$，其平均梯度为 $\bar g_j$。正确的全量梯度为

$$
\nabla_\theta\widehat L
=\frac{1}{M}\sum_{i=1}^{M}\nabla_\theta\ell_i
=\sum_j\frac{M_j}{M}\bar g_j,
\qquad M=\sum_j M_j.
$$

因此不能无条件把每个 micro-batch 的 token-mean loss 除以累积次数：不同轨迹长度会使 $M_j$ 不同。框架需以全量有效 token 数归一化，多卡时还要匹配梯度归约语义。累积过程中参数不更新，完成所有 backward 后统一 clipping 和 optimizer step；Adam 状态只更新一次。与同时处理全量 batch 的梯度等价要求相同目标、正确权重和可加损失；dropout 随机实现与浮点归约次序还会产生数值差异。

MDPO 官方 on-policy `multistep-SGD` 分支在同一 `td_map` 中使用整批 observation/action，循环 `sgd_steps` 次 `_train`；value-function 的 mini-batch 循环另行执行[^mdpo-code]。OpenKimi PMD 将 rollout 与 old log-prob 固定，继承 verl actor 的 mini-batch/micro-batch/epoch 更新路径[^pmd-code]。两者都支持复用固定 outer 数据多次更新；mini-batch 是优化实现选择。PMD 理论中的精确镜像子问题与有限数据、有限优化、函数逼近下的实现仍须分别讨论。

## Inner budget 的判定实验

先进行固定 outer 的实验：克隆同一个 student、anchor、teacher、rollout 和 optimizer 初态，运行到 $J=32$，在 $J\in\{1,2,4,8,16,32\}$ 记录结果。full-batch 使这些位置都是同一优化路径上的 checkpoint。扫描 $\eta\in\{0.1,0.3,1\}$，记录 step、token backward 数和时间，避免仅按 epoch 名称比较。

随后将不同 $J$ 固定为不同的 outer/inner 配置，各自重新 rollout，至少三个 seed。它们的后续访问分布会分叉，因此不能把固定 outer 的曲线当成完整训练结论。分别报告相同生成 token 预算和相同计算预算下的结果；较大的 $J$ 增加反向传播成本，优势需要与该成本共同判断。

诊断包括训练 prefix 和 held-out prefix 的精确 KL/残差、完整全量 surrogate 梯度范数、参数更新范数，以及 MDPO 的 importance ratio 尾部与 ESS。停止梯度 surrogate 的标量下降不足以证明原目标下降；梯度小也可能来自模型表达能力、softmax 饱和或样本覆盖不足。理想目标在完整词表可算时，额外记录 student 与该目标的分布差距。

经验收敛对应固定 rollout 上的有限样本优化，不等于 population Mirror 子问题已求解。有限 sampled action、center 近似和函数逼近误差不会随增加 inner epoch 自动消失。只有 full-batch inner 误差下降且 held-out 指标不恶化时，增加 $J$ 才有证据支持。最终 $J$ 由验证曲线与预算选择，当前 `ppo_epochs=2` 仅是 canary 配置，不是确定的最优值。
