# BPO 全量学习率扫描与阶段对照

## 阶段最佳学习率与零下降率的语义

相同距离区间的阶段平均下降量随学习率呈二次响应，给出阶段性的最佳 lr 与零下降率候选。该经验拟合没有固定不同分支的参数和 Adam 状态，因此当前历史 OPD 结果支持开展同状态对照，尚未证明 BPO 的阶段规则。

精确二次目标沿当前方向 d 满足

$$
Q(\theta-\alpha d)-Q(\theta)=-\alpha A+\frac12\alpha^2B.
$$

A>0、B>0 时，最佳 lr 为 A/B。正的零下降边界为 2A/B；在这个位置，目标值变化为零，参数位移通常仍非零。以单方向 GD 为例，alpha lambda=2 时误差每步改变符号，平方误差保持不变。这是震荡边界，不是梯度为零的最优点。历史阶段平均零点还包含统计拟合和状态变化，不能直接等同于精确边界。

阶段最佳 lr 随有效方向曲率、梯度方向与 Adam 矩变化。共享网络的 Jacobian、固定经验监督偏差和数值精度也参与这些变化。最佳 lr 没有预设单调方向：慢方向主导能支持较大的步长，噪声或震荡主导则要求缩小步长。

对调度的直接启发是低频测量可用下降区间，并选择具有实测下降收益的步长。监测变化落在数值或统计分辨率内时，不能把相等读数反复解释为必须减半。候选是否更好仍以完整目标、teacher KL、backward 次数和耗时共同判分。当前先做 lr 搜索和机制对照，再比较现有 search/feedback；没有将经验二次系数先行写成新生产 scheduler。

## 固定 setting

每个条件使用固定的全部 64 条 rollout，每条轨迹全部有效 token 参与梯度。逐条 micro-batch 累积 64 次 backward 后，只裁剪一次并执行一次 AdamW 更新。不存在有放回抽取轨迹。

| 项目             | 设置                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 模型             | DeepSeek-R1-Distill-Qwen-1.5B / JustRL-DeepSeek-1.5B                                             |
| 固定数据         | 复用现有缓存的前 64 条轨迹，各响应上限 256 token                                                 |
| Anchor / teacher | 单 outer 冻结，inner 不重新 rollout                                                              |
| 训练场           | sampled action BPO、Top-16 加尾部桶 center、eta=0.3                                              |
| 梯度聚合         | 全部响应 token 的均值，按轨迹长度加权累积                                                        |
| 网络与 optimizer | FP32、dropout=0、AdamW betas=(0.9,0.999)、epsilon=1e-8、weight_decay=0、clip=2                   |
| 独立指标         | 固定训练/验证各 4096 prefix 的完整词表 BPO、KL(student 到 teacher)、KL(q 到 student)、动作绝对差 |
| 每步指标         | 裁剪前完整 pool grad norm、实际 lr、裁剪标记、forward/backward 次数和 token 数、耗时             |
| GPU              | 仅物理 GPU0–3                                                                                    |

完整 pool 梯度仍来自每个 prefix 的固定 sampled action，不能把它称为完整词表期望梯度。256-token 条件用于隔离 batch 与 lr 因素，不冒充 7168-token 长轨迹设置。长轨迹复验单列为 fulllong，不由短轨迹结果外推其最佳 lr。

## 第一阶段：全程常数 lr 校准

使用与独立确认分离的 seed1042。八个 lr 为 1.25e-7、2.5e-7、5e-7、1e-6、2e-6、4e-6、8e-6、1.6e-5，各运行 240 次更新，每 10 步审计一次。保留 update40、120、240 的参数及完整 optimizer 快照，供后续同状态试探使用。

先进行全量梯度四步 canary，必须正常结束且恰有 256 次轨迹 backward。校准按完整训练 BPO 的归一化 log-loss 曲线积分排序，选前两个完整、有限的常数条件。失败条件保留，不加入候选排序。若最大 lr 获胜，再增加 3.2e-5 与 6.4e-5，避免在尚未看到收益饱和的网格边缘宣称已定位最佳点。

校准同时报告 teacher KL；BPO 的目标 pG 与 teacher 不同，不能把两个距离混为一个优化目标。

## 第二阶段：相同 checkpoint 的阶段 lr 对照

从校准胜出的常数分支 update40、120、240 三个 checkpoint 分叉。每个阶段测试相同八个 lr，每个分支再执行 40 次完整 pool 更新，在第 1、2 步及每 5 步审计；如果扩展校准的前两名含更大的 lr，同样纳入阶段网格。

参数、Adam 一二阶矩、optimizer step、q、teacher、全部输入和审计位置均从同一阶段起点保留。只改变下一步的 lr，分支日志从零重新计数，但 optimizer 的偏差修正步数继续递推。由此可以观察同一个起点的大步、中步和小步分别带来多大下降、何时反弹，以及 grad norm 是否停住。

第 1 步的各分支具有相同梯度与 Adam 方向，可以对同一方向的净下降拟合局部 lr 响应。随后比较第 5、10、20、40 次分叉更新的绝对目标误差、teacher KL 与实际成本。额外以区间平均每步下降量对 lr 作描述性拟合，所有阶段和失败点均保留。没有通过变更 betas、清空二阶矩或调整 center 改变方向。

## 第三阶段：多种子确认及原实验收尾

使用 seed42、142、242，分别验证校准选择的两个常数 lr、每四步搜索、target_rate=0.01 的反馈，共 12 组，各 600 步。搜索与反馈从校准最佳常数 lr 起步，保持其原规则；上限至少 1.6e-5，并覆盖最佳常数的两倍，以避免用较窄候选范围人为限制调度。

主判分为三个种子上完整 BPO 曲线几何平均误差的改善方向一致、中位改善至少 10%，训练终点与验证 BPO/teacher KL 退化不超过 5%。实际耗时收益另行判断。所有常数对照与失败运行保留，不使用确认结果重新挑选参数。

短轨迹确认后先完成旧矩阵的剩余确认，再执行长轨迹迁移检验，最后继续 17 项旧消融。旧矩阵条件及已有结果保持原先定义。此前尚未启动的 21 组 fullpool 矩阵保留配置归档，由本次校准、阶段对照与确认矩阵替代。

## 长轨迹迁移检验

另生成并冻结 seed42 的 64 条训练和 16 条验证响应，响应上限 7168，沿用相同模型、FP32、eta=0.3、Top-16 center 与 optimizer。先运行完整 64 条梯度的一步 canary，检验显存与数值链路；通过后比较短轨迹校准的两个常数，以及 1e-6、2e-6、4e-6，每组 80 步。重复 lr 合并。

这些条件使用新长轨迹，跨 lr 复用完全相同输入。它是迁移与稳定性初筛，不作为完整长程收敛结论，也没有声称与短轨迹数据逐 token 相同。新的长 cache 留在 runs 中，不把完整词表大缓存写入 Git。

## 排队顺序与恢复

原全量队列在等待资源时因 owner.json 消失于检查与读取之间而退出。修复使该状态返回等待，CPU 回归检验覆盖该竞争条件。

新的监督程序只停止旧 controller 继续派发任务，让其已经启动的四个 worker 正常完成。随后退出旧 controller，由共享 GPU 租约和 driver 检查接管资源，执行 fullpilot、fullstage、fullconfirm，随后执行旧 confirm、fulllong，最后执行旧 ablate。没有中止正在执行的 backward 或删除 checkpoint。

入口为 `training/scalar_queue_handoff.py` 和 `training/scalar_full_pool_study.py`。配置计划保存在 `results/scalar-large/fullpool-lr-study/plan.json`，工作日志与 checkpoint 留在 `runs/scalar-large/`。全量梯度 canary 已正常完成，恰有 256 次轨迹 backward。首批四个 lr 条件已完成各 240 次更新，统计、原始日志快照及局部曲线见[《BPO 全量扫描首批结果》](2026-10-13-BPO全量扫描首批结果.md)。四个较大 lr 条件尚未完成，最终校准选择与后续分叉、确认结果仍待分析。
