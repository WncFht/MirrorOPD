# BPO 标量调度实验设计

## 问题与判定标准

固定 anchor、teacher、prefix 和 action pool，检验全局标量调度能否减少达到相同剩余误差阈值所需的 backward 次数。所有 AdamW 分支固定 betas、epsilon、weight decay 和梯度机制；调度只改变标量学习率。loss 变换作为独立对照，观察其改变 Adam 状态后的方向差异。

主要阈值为初始精确 BPO 平方误差的 10%、1% 和 0.1%，另记录 teacher reverse KL。每个阈值记录首次达到及连续五步保持的步数。比较常数学习率网格中的最佳分支，避免把超过保守基线写成超过常数学习率。记录 forward、backward、失败试探次数、运行时间、累计学习率、相对吸收率、末尾误差、残差平方与精确目标的差异。以相同累计学习率重绘轨迹，检查收益是否主要来自数值时间增加。

## 分层验证

1. 精确二次模型：可控谱宽、旋转坐标、多种种子，比较固定 lr、loss 倒数规则、相对下降率反馈、Polyak 型规则与沿既有更新方向的一维二次试探。梯度下降用于核验推导，AdamW 用于检验迁移；理想曲率只用于标注 oracle 对照。
2. 分类模型：冻结 q 采样动作，分别使用完整词表二次目标、完整 center 的 sampled score、生产 Top-k 加尾部桶 center。共享线性及非线性参数用于检验自由 logits 结论的边界。固定 action pool 的经验 residual 平方与总体目标分别记录。
3. 已训练语言模型：使用本地 DeepSeek-R1-Distill-Qwen-1.5B / JustRL-DeepSeek-1.5B，共享 tokenizer，冻结 q rollout 和 teacher logits。GPU 0--3 各运行独立分支；其他卡保持原有任务。小型固定 prefix benchmark 只判断优化速度，不替代数学任务正确率评测。

## 候选规则与证伪条件

相对下降率反馈以观测到的 log loss 下降率决定下步 lr，并限制增长与上限。若没有方向曲率保护，高曲率方向重新进入时出现上冲即证伪其无条件稳定性。

一维二次试探固定一次 AdamW 产生的方向，只通过额外 forward 测量不同全局步长的 residual 平方。精确二次模型中三个函数值可以恢复沿方向的二次多项式；共享参数与 Top-k 模型中只作为局部拟合，并按实测函数值接受或回退。若减少 backward 的收益不足以抵消 forward 耗时，结论应为 backward 效率改善而非总时间改善。若经验 residual 下降而总体 BPO 或 teacher KL 上升，应判定为指标失配。

## 复现与记录

实验程序维护在 `experiments/toy/` 与 `experiments/analysis/`，结果写入 `results/scalar-schedule/`，大缓存与运行日志保存在 `runs/scalar-schedule/`。每次运行保存配置、种子、源码 SHA-256、输入来源及计数。理论正文更新当前主稿的 inner 动力学章节，结果解释单独维护实验报告。

## 大规模调参与独立确认

### 数据规模和重复

大规模阶段固定模型、teacher、anchor、$\eta=0.3$ 和完整词表。调参 seed 为 1042，确认 seed 为 42、142、242、342、442。调参与确认的 prompt 行互不重叠；每个 seed 单独按原始学生 $q$ 生成固定 response pool。主条件为 64 条独立 prompt/trajectory，每条 response 上限 256 token，最多 16384 个 prefix，是原先 416-prefix 验证的约 39 倍。额外准备 128 条训练轨迹和 32 条独立验证轨迹，供 16/64/128 条训练轨迹的规模消融使用；最大训练 pool 为 32768 个 prefix。prompt 保留完整文本，筛选 tokenizer 长度不超过 512 的记录，不截断 prompt。EOS 自然终止，短 response 按实际 token 数计入。

主训练使用固定 pool 的 token 测度。每次更新按轨迹长度比例抽取 8 条轨迹，平均每条轨迹的 token-mean gradient，得到该固定 token 测度的无偏 minibatch 梯度。抽样索引序列跨算法配对复用。没有新 rollout，也没有 token 对损失。另对 8 与 64 条轨迹的 batch 消融区分 minibatch 噪声和固定 pool 偏差。

### 独立调参与确认条件

调参在 seed1042 上执行 240 次 optimizer 更新。常数学习率网格为 $2.5\times10^{-7},5\times10^{-7},10^{-6},1.5\times10^{-6},2\times10^{-6},4\times10^{-6},8\times10^{-6},1.6\times10^{-5}$。候选为三点搜索（每步或每 4 步拟合）、相对下降率反馈（目标 log 收缩 0.01 或 0.03）；额外保留 log loss 梯度缩放对照，共 13 条调参轨迹。学习率上限统一为 $1.6\times10^{-5}$。三点搜索采用完整词表 BPO 监测，生产梯度保持 sampled action 与 Top-16 加尾部桶 center。

按调参完整 BPO 的 log-loss 曲线积分选择最好的两条常数学习率，按同一指标选定一个主 scalar 候选；确认阶段锁定参数。五个确认 seed 对两条常数基线、每步搜索、每 4 步搜索和选定反馈分别执行 600 次更新，共 25 条确认轨迹。主比较是预先选定的 scalar 与最佳调参常数，其他比较作为预注册消融，避免从确认结果中重新挑选赢家。

### 消融与判据

1. Pool 为 16/64/128 条轨迹，检验小 pool 中的经验过拟合是否改变结论。
2. Center 为 Top-16、Top-64、完整 center；另保留完整 BPO 梯度的 oracle 对照。完整 center 的 sampled score 仍按原生产停止梯度语义更新，不能混成完整平方目标。
3. 固定搜索监测集为 512 或 2048 个 prefix，主条件覆盖 8 条固定轨迹，另对 2 条轨迹覆盖作独立消融。比较完整 residual 与 sampled residual；独立评分集始终为训练 pool 中均匀抽取的 4096 个 prefix 和验证 pool 中的 4096 个 prefix。
4. Student forward 为 FP32 或 BF16；teacher 和 anchor 监督保持一致，完整误差评分始终用 FP32。
5. 每步拟合与每 4 步拟合分别统计真实 forward 成本、backward 调用、backward token 数及 optimizer 更新数；梯度累积不能被计为单次物理 backward。
6. Batch 为 8 或 64 条轨迹，所有 betas、epsilon、全局裁剪 2 及 weight decay=0 固定。

主要评分为完整 BPO 的归一化曲线积分与末段误差，在相同 optimizer 预算及相同实际耗时两种口径下比较。每 20 次更新做独立完整词表评分，阈值报告采样区间，不宣称精确跨阈值 step。记录 0.5、0.2、0.1、0.01、0.001 倍初始完整误差的首次达标、连续两次 audit 达标及其后的反弹。

只有五个独立确认 seed 的主比较方向一致、中位改善至少 10%、验证 prefix 误差没有超过 5% 的退化时，才将结果列为可重复的优化收益。只有同一时间预算也改善，才称总体效率更好；仅 backward 减少则按成本交换报告。五对独立重复采用精确配对符号检验及逐 seed 结果，训练曲线的多个点不能当作独立样本。失败、未达阈值与拒绝步都保留。

### 资源与恢复

所有 GPU 子进程仅看见物理 0–3，复用 workspace 的原子目录预留协议 `runs/gpu-locks/physical-gpu-0-3.lease`，与其他已授权实验协调。正式阶段持有四卡预留，启动前检查空闲；一个阶段内最多四个单卡分支并行，阶段结束释放锁。禁止终止其他会话进程或转用 4–7 卡。发现外来占用时停止本实验子进程并从 checkpoint 恢复。

先跑较长输入 canary 测量内存、零步对齐和真实耗时，确认缓存与 mask 正确，再执行调参及确认队列。每 100 次更新保存参数、AdamW 状态、采样随机数状态、调度状态和累计计数，可恢复而不重置 moments。原始大 cache 和 checkpoint 留在 `runs/scalar-large/`，可引用统计归档到 `results/scalar-large/`。

正式计划包含 13 条调参、25 条确认与最多 17 条消融轨迹，合计最多 24360 次 optimizer 更新。五个确认 pool 主训练共有 81920 个 prefix，六个 seed 全部准备 128 条训练与 32 条验证轨迹，共 245760 个缓存 prefix。response 均达到 256 预算时，该计数为精确值；自然提前 EOS 时按 manifest 中的实际计数报告。

### 确认阶段的计算成本口径

独立确认阶段只计算算法需要的监测量。常数 lr 每步直接完成原生产梯度与 AdamW 更新，完整误差仍按共同的每 20 步 audit 评分；每 4 步搜索仅在拟合步计算固定 proxy。反馈和 log loss 缩放按各自规则逐步计算 proxy。禁止给常数 lr 额外添加逐步 proxy 成本，再将其耗时作为原算法的部署成本。

调参阶段前八条常数轨迹保留了逐步 proxy 日志，其更新预算和参数轨迹不受该额外无梯度 forward 影响，按完整 BPO 的更新轴积分选参；这批耗时仅是含诊断的调参耗时，不用于主时间效率判断。确认阶段开始前锁定上述精简监测口径。运行 summary 标识 `monitoring_policy`；CPU 测试验证去掉非必需 proxy 后参数、AdamW 一阶矩、二阶矩和 step 计数逐字节一致。

主统计量固定为更新轴上归一化 log-loss 积分的指数，即整个 600 步预算的几何平均完整 BPO 误差。主改善定义为 $1-\exp(A_{\rm scalar}-A_{\rm constant})$，其中 $A$ 为归一化 log-loss 积分；精确配对符号检验作用于五个 seed 的这个主改善。要求五对方向一致、中位改善至少 10%，末段完整 BPO 及两项验证误差均不得退化超过 5%。末段误差比、阈值和 matched-time 结果另行报告，不能在确认结果出来后替换主统计量。只有主优化判据与独立时间判据都通过，才称总体效率更好。

监测 prefix 数、监测量方向与覆盖轨迹数的三项消融对预选出的标量候选始终执行，反馈候选同样依赖这三个因素。不会因调参选出 feedback 而省略这些已命名的消融。
