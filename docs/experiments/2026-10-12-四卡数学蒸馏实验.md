# 四卡数学蒸馏实验

## 目标与比较条件

本实验在当前节点的物理 GPU 0、1、2、3 上比较 full on-policy 蒸馏、镜像下降策略优化（Mirror Descent Policy Optimization，MDPO）和 BPO inner。三个正式实验都从同一份 DeepSeek-R1-Distill-Qwen-1.5B 原始权重开始，以 JustRL-DeepSeek-1.5B 为冻结教师；各执行 50 次 outer rollout。on-policy 每次 outer 做一次全 batch 更新，MDPO 与 BPO 每次 outer 做 16 次全 batch 更新。教师、数据顺序、采样分布、优化器和评分协议保持一致。GPU 4–7 属于其他运行，实验入口固定屏蔽它们。

实验要验证两件事：四卡能否完成长响应生成、锚点缓存、教师打分、梯度累积、权重同步与周期评测；在同一训练预算与评分协议下，teacher KL、数学 reward 与测试准确率是否提供一致的学习证据。短程验证要求两次 outer 均成功，实际 inner 更新数符合配置，同步后的 student center 为零，指标有限且 W&B 在线记录可回读。出现 OOM、非有限梯度、缓存版本错误或更新数不符时，先修复链路并重新验证，再启动正式实验。

## 模型、数据与评分

模型固定版本与权重 SHA256 见 [数据与模型审计](../../results/training/math-4gpu/2026-10-11-数据与模型审计.md) 和 [结构化审计](../../results/training/math-4gpu/data-model-audit.json)。两模型词表和原生模板逐项相同，模板以 `<think>` 起始生成。使用原生模板和完整参数训练，不配置 LoRA。

训练读取 `MD-OPD/data/math/DAPO/train.parquet` 的 17,917 行；该文件包含 17,255 个唯一 prompt。验证读取原始 MATH-500 的 500 题、AMC23 的 40 题和 AIME25 的 30 题。2048 token 的 prompt 预算覆盖全部输入，最长训练 prompt 为 1493 token，最长测试 prompt 为 796 token。

原始 DAPO 与 MATH-500 有 2 道完全相同的 prompt，与 AMC23 有 5 道相同的 prompt，与 AIME25 无完全相同的 prompt。这一重叠属于输入数据事实，原始 split 按用户指定保留；解释 AMC23 分数时必须交代其中 12.5% 的题在训练语料中出现。字符串重叠检查覆盖原始 prompt 序列化结果，不能证明其余题目没有语义重叠。

数学评分复用 MD-OPD 的 `ttrl_mathverify` 路径：有 boxed 答案时使用原 boxed 答案核验；无 boxed 答案时使用最后 2000 字符的 Math-Verify fallback。评分仅用于监控，训练梯度来自蒸馏。移入后端的第三方模块及其 SHA256 见 [评分集成清单](../../results/training/math-4gpu/reward-integration.json)。保留第三方版权说明，避免重新实现数学答案判分。

当前后端 agent loop 只使用 validation 的 temperature、top-p 和 top-k，未接通独立 `max_tokens`。因此本实验训练和周期评测都明确使用 7168 token，而 MD-OPD recipe 的独立 validation 默认预算为 31744。这里的分数解释限定在 7168 预算；若预算耗尽率高，长预算独立评测应另列条件，不能将短预算结果当成模型完整推理能力。

配置维护于 [dapo-deepseek-4gpu.json](../../training/configs/dapo-deepseek-4gpu.json)，入口为 [run_dapo_math_4gpu.sh](../../training/run_dapo_math_4gpu.sh)。每次启动保留实际 resolved config、全部 overrides、代码指纹、模型/数据审计、inner/outer JSONL、GPU CSV、console 日志、W&B run 信息和退出码。启动使用 `nohup setsid` 脱离终端；本地 Ray 使用独立目录和 `address=local`，只声明四个 GPU 资源。GPU 可见性与资源数的设置遵循 Ray 官方 accelerator 说明[^ray-gpu]；独立本地实例使用 Ray 的 local address 选项[^ray-init]。

## 指标与判断

teacher center 使用冻结 anchor 的 Top-16 与尾部合并的 Tail-aware KL，属于完整词表 KL 的下界。它和 action 上的 sampled reverse-KL reward 分开报告。BPO 使用近似中心会产生确定的中心误差；[算法核验](../../results/training/math-4gpu/2026-10-11-algorithm-audit.md) 写明原始公式、实现和误差关系。surrogate loss 的 scalar 值不能当作真实镜像目标。

KL 随 outer 波动同时受到 rollout prefix 分布变化影响。比较学习效果时同时检查同一 outer 内的 inner 动力学、固定测试准确率、格式率、预算耗尽率、梯度范数和有效样本量（Effective Sample Size，ESS）。每个 outer 的首 inner student center 应回到零，后续 inner 的偏离与 ESS 反映固定 anchor 上的变化。

正式效果报告逐测试集列出初始与最终准确率、绝对变化、样本数和截断情况，结合全程曲线给出结论。训练成功运行与学习有效分别判定。单次 seed 的小测试集变化只能作为该运行的观察，不能替代跨 seed 统计证据。

第三个 canary 完成两 outer、两次实际 optimizer 更新及初始/最终 16 题测试，退出 0，W&B 服务端为 finished、11 条 history；显存采样峰值为 35721 MiB。原始记录见 [canary 诊断](../../results/training/math-4gpu/canary-03-diagnostic.json)。四个 DP rank 各写一次已聚合的 inner 指标，导致两次更新产生 8 行重复记录；同步点 student center RMS 约 $9.05\times10^{-9}$。该结果证明执行链路完成，同时暴露多卡日志缺陷。

概率支持核验发现另一处实现差异：两模型输出宽度是 151936，tokenizer 的连续 ID 范围为 0–151664，共 151665 个 ID。vLLM 在采样前屏蔽后面的 271 列，HF 原路径却将它们纳入 softmax。设完整 HF 分布为 $p$、可采样支持为 $A$，rollout 实际分布为

$$
p_A(a)=\frac{p(a)}{p(A)},\qquad a\in A.
$$

因此同一个有效动作满足

$$
\log p(a)-\log p_A(a)=\log p(A).
$$

直接在四个固定 DAPO prompt 的最终位置执行真实模型 BF16 前向，student 的支持外质量为 $3.04\times10^{-9}$–$4.47\times10^{-9}$，teacher 为 $1.01\times10^{-10}$–$2.33\times10^{-10}$。这些位置的差异很小，不能把既有训练效果或日志问题归因于该质量；修复用于保证采样和梯度所定义的动作空间相同。测量见 [支持外质量](../../results/training/math-4gpu/support-mass-probe.json)，复现入口为 [probe_vocab_support.py](../../experiments/scoring/probe_vocab_support.py)，运行时设置 `CUDA_VISIBLE_DEVICES=0`。

修复在 FSDP 输出归一化前统一裁剪到 tokenizer 支持，覆盖 actor、teacher、锚点、当前 loss、entropy 与普通 log-prob 两条 padding 路径。使用切片保持梯度，并使支持外参数的对应 logits 梯度为零；直接保留 `-inf` 列会使当前 entropy 算式出现 $0\cdot(-\infty)$。生产入口启用 `MIRROR_ALIGN_ROLLOUT_VOCAB=1` 并拒绝未处理该支持的 fused 路径。13 项 CPU 回归覆盖额外列不变性、三种 loss、梯度和真实 backend 的两条归一化分支，全部通过。

inner 写入限制为 global rank 0，保持原有 DP gather、moment reduction、loss 与梯度裁剪不变。四 rank、两 outer、每 outer16inner 的回归只产生 32 条唯一记录，所有调用方统计保持不变；3 项 CPU 回归通过。新上游 patch 在固定基线干净重放通过。使用 Conda opd 环境执行 Makefile 中全部 CPU 测试入口通过，`make check` 通过。
