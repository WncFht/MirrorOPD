# DAPO 数学环境与基线评测

## 目标和实验顺序

本实验检验 SmolLM2-1.7B-Instruct 教师能否在 DAPO 数学题上提供比 SmolLM2-360M-Instruct 学生更准确的解答，以及这种能力能否通过现有 on-policy OPD 传递。第一阶段测预训练模型；第二阶段根据训练题的输出长度确定预算；第三阶段测简单测试集；第四阶段先做显存 canary，再训练。现有 GSM8K 1000-outer 任务完成后才使用 GPU，不改变该任务的模型、数据或超参数。

数学答案准确率只作诊断和评测，OPD 梯度仍来自教师/学生 token 概率比及 KL baseline。正式实验沿用 B=64、J=1、每题一条学生 rollout、全局 token 平均、micro-batch=1、lr=3e-7、clip=2、K=16 Tail-aware KL baseline、无额外 KL 正则、无 checkpoint。DAPO 计划 1000 outer，每 5 outer 测一次简单测试集，包含 step 0；4 epoch 的数据容量足以覆盖 1000 个 64-prompt batch。canary 为独立的 2 outer，不把它当作完整训练结果。

## 上游协议与本机环境

核对的 One-Shot-OPD 版本为 `6b6b1782cc3f04749dd077de19353f839f6bc048`。它的数学入口使用 DAPO 全量题作为训练集、MATH-500 作为在线评测集，教师为 JustRL-DeepSeek-1.5B，学生为 DeepSeek-R1-Distill-Qwen-1.5B。论文评测还包括 AMC 2023、AIME 2025。其 README 报告 avg@16，采样温度 0.7、top-p=0.9，数学评测回答上限 31,744 token。[^oneshot]

本实验保留既有 SmolLM2 模型对，使用其原生 chat template，包括 tokenizer 自动加入的系统消息。题面作为单条 user message；答案仅存于 reward_model，不进入 prompt。这是数据和 verifier 对齐的适配实验，不能称为 One-Shot-OPD 论文数字的直接复现。

| 项目                  | 上游 README        | 本实验已安装环境       |
| --------------------- | ------------------ | ---------------------- |
| Python                | 3.12               | 3.12.13                |
| PyTorch               | 2.13.0             | 2.8.0                  |
| Transformers          | 5.10.4             | 4.57.6                 |
| vLLM                  | 0.28.0             | 0.11.0                 |
| GPU                   | 多卡服务器配方     | RTX 4070 SUPER，12 GiB |
| Math-Verify           | 数学 verifier 依赖 | 0.9.0                  |
| latex2sympy2_extended | 数学 verifier 依赖 | 1.11.0                 |

独立基线用 vLLM BF16 推理，最多 4 条并发序列，显存利用率 0.7，eager 模式。训练保留现有 TA-OPD/verl 环境和 FP32 参数、BF16 forward、显式推理 offload。不会在正在运行的任务中升级 CUDA、PyTorch 或 vLLM。

上游长度配置存在应明确的差异：README 写数学 prompt=1024、response=7680；这个版本的 `recipe/opd.sh` 数学分支没有覆盖 `_common.sh` 的 prompt=4096、response=7168 默认值。评测默认上限则为 31,744。这里显式记录每次运行的 resolved config，不把 README 的数值当作脚本实际执行值。[^recipe]

## 数据准备和泄漏检查

DAPO 源版本固定为 `65877096c24ffa7abc4e4fa5edb95cf3413a5674`，MATH-500 固定为 `6e4ed1a2a79af7d8630a6b768ec859cb5af4d3be`。原始 DAPO parquet 为 1,791,700 行，以 `extra_info.index` 保序去重后为 17,917 题；每题的 100 份副本不会被当作 100 个不同训练样本。去掉官方数据附加的开头和结尾 `Answer:` 指令，保持 One-Shot-OPD 数据准备语义。[^datasets]

输入已在 archbox 和本地的 `data/dapo-suite/` 准备完毕。原始下载留在 archbox `runs/dataset-cache/`，约 300 MB；对齐后的训练 parquet 约 3.2 MB。manifest 记录来源 commit、行数、去重规则和 SHA-256。读取原始 parquet 使用 Arrow 分批处理，实测准备任务峰值主机内存约 750 MB，不加载 179 万行到一个 pandas DataFrame。

| 输入                |   数量 | 用途                                 |
| ------------------- | -----: | ------------------------------------ |
| DAPO 官方保序去重版 | 17,917 | 双模型全训练题基线，复核上游         |
| DAPO clean-train    | 17,915 | 正式 OPD 训练                        |
| MATH-500 全量       |    500 | 保留的参考输入                       |
| MATH-500 Level 1–2  |    133 | 简单数学测试                         |
| GSM8K test          |  1,319 | 基础数学测试，沿用现有 prompt/scorer |

DAPO 与 MATH-500 的题面精确匹配检查发现 `MATH-500-80`、`MATH-500-276` 两题重合。clean-train 去掉这两题，官方版另保留。精确字符串去重不能证明没有改写题或预训练数据污染；此检查解决当前输入中已确认的两题泄漏。测试集不划 valid，不跑 AMC 或 AIME。

## 评分与长度选择

DAPO 和 MATH 共用上游 `ttrl_mathverify.reward_func`：先解析 boxed 并用其数学 grader 判定；出现可解析 boxed 时直接返回该结果；没有 boxed 时，对回答最后 2000 个字符调用 Math-Verify。GSM8K 沿用当前 GSM8K scorer，两个数据源分开报告。不能用“能抽出一个数字”替代数学等价判定。

已经在 archbox 通过五个 CPU 协议用例：boxed 正确、boxed 错误、分数与小数等价、无 boxed 的 final-answer 兜底，以及没有答案。独立评测直接导入固定上游 verifier，不复制改写 grader。训练开始前仅同步所需 verifier 文件到 TA-OPD 后端，保留不同旧文件及校验值，并重新执行同一组协议测试。

先对两模型分别评测全部 17,917 训练题，greedy、seed=42，context=8192。每个 prefix 的回答预算是 8192 减去原生模板后的 prompt 长度；遇到过长 prompt 报错，不静默截断。每 32 题追加逐题记录和中间汇总，保存完整回答、完成原因、prompt/response token 数、答案分数及数据校验值。断点续跑核对输入、顺序和参数。

另对每模型做固定 seed 随机选择的 1024 道训练题 T=1、top-p=1 的长度 pilot。greedy 准确率不能代表训练采样的长度尾部，两个协议都会参与预算选择。

从长回答截取 512、1024、2048、4096 token 前缀，用同一 verifier 重新评分。这是固定生成轨迹的预算回放，不是四次独立生成实验。统计平均准确率、boxed rate、预算溢出率、context 耗尽率，以及输出长度 p50/p90/p95/p99/max。真实长度受到原生 8192 context 截断的回答仍标为 censored，不能当成自然完成长度。

选择最小预算，使两模型全训练题基线及 T=1 pilot 的溢出率均不超过 1%，回放准确率损失均不超过 0.5 个百分点，且 prompt 上限加 response 上限不超过模型原生 8192。prompt 上限由全训练题实测最大长度向上取 128 的倍数。选择不使用测试答案或测试准确率。

没有预算达标时仍测简单测试集的原生 context 基线，但自动训练停止，输出 `needs_length_analysis`。不能为了启动训练默认回退到 2048，也不能把推理可运行当作反向传播显存足够。预算达标后先做 2-outer B=64 的训练 canary；canary 失败不会启动 1000-outer DAPO。

## 队列与结果位置

`training/followup_dapo_math.sh` 在 systemd 用户任务 `mirroropd-dapo-context-followup.service` 中等待 `mirroropd-gsm8k-opd-o1000.service` 成功完成。父任务失败或没有成功退出记录时停止。后续依次做双模型全训练题基线、T=1 长度 pilot、context 选择、简单测试集基线、verifier 集成、canary、正式 DAPO 训练。

队列输出为 archbox `~/src/mirroropd/runs/dapo-context-baselines/`。每模型各有逐题 JSONL、分组 summary、版本 manifest 和 console；预算决策为 `context-selection.json`。正式训练运行名 `dapo-smollm2-opd-onpolicy-o1000-j1`，W&B project `mirror-opd-dapo`、group `dapo-math-context-calibrated`，保留既有逐 inner/outer 记录和 test logging。

当前完成的是数据物化、泄漏检查、数学评分协议测试和队列准备。DAPO 教师/学生 GPU 准确率尚未产生，不用 GSM8K 结果冒充 DAPO 结果。当前未训练教师在现有 GSM8K 2048-token 协议下为 620/1319（47.01%），它只用于核对现有 baseline，不决定 DAPO 长度。
