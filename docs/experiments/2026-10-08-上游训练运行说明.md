# Tail-aware MirrorOPD 上游训练运行说明

训练工程位于 archbox 的 `~/src/mirroropd-taopd`，学生更新、reference teacher 推理、vLLM rollout、权重同步及 checkpoint 都使用修改后的 TA-OPD/verl。三个训练模式为 `mirror_pmd_mean`、`mirror_bpo`、`mirror_mdpo`。PMD-Part 没有启用。

## 源码与环境

源码依据 TA-OPD commit `62669afb5101bfdf57dc5ddf81e78f000c5ce2fc`。框架接入改动保存在 [重放补丁](../../patches/ta-opd-mirror-token-loss.patch)。补丁路径从 TA-OPD 仓库根开始，包含 `verl/verl/`；在该 commit 的干净仓库根运行 `git apply --check <补丁绝对路径>`，再运行 `git apply <补丁绝对路径>`。不要额外添加 `--directory=verl`。补丁已经对干净的修改后源码执行 reverse check，通过核验。

实际 GPU 环境使用 Python 3.12、PyTorch 2.8.0+cu128、vLLM 0.11.0、FlashAttention 2.8.1、transformers 4.57.6、datasets 4.8.5 和 Ray 2.59.0。完整包版本见 [环境快照](../../results/training/2026-10-08-upstream-canary-environment.txt)。快照中的 FlashAttention 本地 URI 指向实际安装的 wheel，因此不能直接作为任意机器上的联网安装锁文件。archbox 保留该 wheel：

```text
~/src/mirroropd-taopd/scratch/flash_attn-2.8.1+cu12torch2.8cxx11abiTRUE-cp312-cp312-linux_x86_64.whl
SHA256: 55331d797171973c8babf2b5e5fce5f78859b1cd298d54a136e8994147fe9e95
```

已有 `~/src/MD-OPD/.venv` 的 torch/vLLM 组合与该上游版本不兼容。训练入口固定使用新工程自己的 `.venv/bin/python`。大文件和临时目录位于工程的 `scratch/` 与 `~/.cache/mopd-ray`，不使用 `/tmp`。

## 本仓库算法包与远端部署

MirrorOPD 的生产 token loss 和缓存现在位于本仓库 `src/mirroropd/training/`，verl 数据适配位于 `src/mirroropd/integrations/verl/`。上游补丁只保存框架导入、薄包装和训练流程接入，运行时需要同时可导入 `mirroropd` 包。启动脚本默认将其所属仓库的 `src/` 加入 `PYTHONPATH`，并保留上游 `verl` 包的路径。

远端运行时需要同步完整的本仓库源码和新的上游补丁。单独复制启动脚本不能部署算法包；若使用已有独立运行目录，可设置 `MIRROROPD_SRC_ROOT` 为已部署的 `src/` 绝对路径。以下新布局命令假定仓库已部署到 archbox 的 `~/src/mirroropd`，上游运行目录已应用对应补丁；它不表示此次已经更新远端。

```bash
cd ~/src/mirroropd
MIRROR_UPSTREAM_ROOT="$HOME/src/mirroropd-taopd" \
  bash training/run_upstream_mirror_training.sh mirror_bpo \
  "$HOME/src/mirroropd-taopd/data/train.parquet" \
  "$HOME/src/mirroropd-taopd/data/test.parquet" \
  trainer.total_training_steps=100 trainer.total_epochs=10
```

下文短名称启动命令记录的是既有 archbox 环境。生产内核提取后已通过全部 CPU 数学与模型集成测试；新的远端 GPU 运行尚未执行，既有 GPU 记录不作为新部署的验证证据。

## 共用入口和数据格式

[共用训练入口](../../data/refactor-20261015/legacy-source.tar.gz#training/run_upstream_mirror_training.sh) 接受算法名、训练 Parquet、验证 Parquet，后续参数作为 Hydra overrides 原样传给上游 trainer。Parquet 使用原生 verl 数据格式：`prompt` 是 role/content 消息列表；`data_source` 标识评分来源；`reward_model.ground_truth` 保存参考答案；`extra_info` 保存索引和 split。当前共用入口附带的评分适配器用于 GSM8K 格式答案，评分只用于监控，不参与这三个 MirrorOPD 损失。其他数据集应通过 `reward.custom_reward_function.path` 指定适当评分函数。

在 archbox 上使用已有工程和已有数据的命令为：

```bash
cd ~/src/mirroropd-taopd
bash run_upstream_mirror_training.sh mirror_bpo \
  "$HOME/src/mirroropd-taopd/data/train.parquet" \
  "$HOME/src/mirroropd-taopd/data/test.parquet" \
  trainer.total_training_steps=100 trainer.total_epochs=10 \
  trainer.default_local_dir="$HOME/src/mirroropd-taopd/checkpoints/bpo-run"
```

上述正式数据路径需要由实验的数据准备步骤生成；当前验证没有冒充生成这两个文件。入口保留已验证的保守内存默认值：训练 batch 为 2，prompt/response 上限为 64，模型为 Qwen3-0.6B student 与 Qwen3-1.7B teacher，LoRA rank 8，单 GPU、完整本地词表，actor 和 teacher 参数常驻 GPU，optimizer 卸载。改变模型、轨迹长度或并发后，需要重新验证显存与主存预算。12 GB 卡上的短轨迹结果不支持任意长轨迹的可运行性结论。

[小规模验证入口](../../data/refactor-20261015/legacy-source.tar.gz#training/run_upstream_mirror_canary.sh) 只生成四条算术 prompt，然后调用同一个共用入口。在 archbox 上保留的短名称为 `run_mirror_canary.sh`：

```bash
cd ~/src/mirroropd-taopd
bash run_mirror_canary.sh mirror_pmd_mean
bash run_mirror_canary.sh mirror_bpo
bash run_mirror_canary.sh mirror_mdpo
```

三条命令应顺序执行。这是训练链路检查，输出长度上限和数据量不足以评估 GSM8K 性能。共用入口允许覆盖 `data.max_response_length`、`actor_rollout_ref.rollout.max_model_len` 等配置，验证脚本不会另写一套训练循环。

## Outer、inner 与恢复语义

第一个 outer rollout 使用版本 0；每个 outer 的 actor 更新完成后，通过上游 checkpoint engine 把新权重同步给 vLLM。下一个 rollout 报告新的 server `global_steps`。Mirror 模式要求每条轨迹的 server 版本等于当前训练步减一，版本缺失、混合或陈旧时在建立 anchor 缓存前报错。该检查证明同步顺序；vLLM 与 FSDP 的概率仍有数值差异，版本相同不代表逐位一致。

一个 outer batch 内固定 anchor top-k 支持、anchor action/head/tail log-prob、teacher action log-prob 和 teacher Tail-aware center。每次 inner forward 都用当前 student logits 重算 anchor‖student center。Mean/BPO 没有 student/anchor importance ratio；MDPO 保留该比率。整个解析 score 系数停止梯度，surrogate 直接归约，不再进入 PPO advantage/clipping 包装。

`actor_rollout_ref.actor.ppo_epochs` 控制同一 outer 数据上的 inner epochs；具体 optimizer 更新次数还取决于 mini-batch 数量。`distillation.distillation_loss.mirror_eta` 与 optimizer learning rate 独立。当前使用 hard sync；参数 EMA 和逐 prefix 概率混合不等价。

恢复验证使用以下命令：

```bash
bash run_mirror_canary.sh mirror_bpo \
  trainer.resume_mode=auto trainer.total_training_steps=3 trainer.total_epochs=2
```

该命令从本方法输出目录的最新 checkpoint 恢复，因此运行前核对 `latest_checkpointed_iteration.txt`。恢复到第 2 步时，下一次 rollout 应报告版本 2，随后完成第 3 步。模型、optimizer、随机数和学习率调度器均由原生 checkpoint manager 恢复；数据迭代状态也由上游路径保存和加载。

## 验证证据与解释

[实现审计](2026-10-08-%E5%8E%9F%E5%A7%8B%E8%AE%AD%E7%BB%83%E6%A1%86%E6%9E%B6%E4%B8%8EOPD%E5%AE%9E%E7%8E%B0%E5%AE%A1%E8%AE%A1.md) 记录 PMD、MDPO、One-Shot-OPD、TA-OPD 的原始代码依据以及移植区别。[GPU 验证数据](../../results/training/2026-10-08-upstream-gpu-validation.json) 保存真实更新与恢复记录；原始日志位于 archbox 工程的 `logs/`。本地数学、缓存路由与小型 causal LM 检查分别位于 `test_upstream_opd_semantics.py`、`test_upstream_mirror_wiring.py` 和 `test_upstream_mirror_lm.py`。

Tail-aware center 的偏差、BPO 半梯度和近似平方目标完整梯度的区别已经写入成书的第二章。SG surrogate loss 可以为负，其下降不是完整 KL 或平方残差下降的证据。当前 GPU 检查证明指定配置上的训练链路可运行；准确率、完整 KL 收敛以及三种算法的性能排序需要另行设置正式训练和评测实验。
