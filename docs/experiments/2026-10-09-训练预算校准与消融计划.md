# 训练预算校准与消融计划

## 问题与现有证据

本轮先确定稳定且有效的学习率、完整 rollout batch、inner 预算和 outer 预算，再比较 Token-IS vOPD、MDPO、PMD-Mean 与 BPO。固定 prefix 上的 teacher 对齐改善、独立文本 NLL、显存和耗时共同决定配置。训练 surrogate 的下降不能独立证明 inner 收敛。

现有 Pythia-14M/70M 实验包括学习率 1e-5 与 1e-6、MDPO eta 为 0.03、0.1、0.3、1、无穷的单种子扫描，以及 on-policy 与 Token-IS baseline。MDPO 使用 32 outer、每轮 16 prompt、4 inner 更新。低学习率实验整卡采样显存峰值为 4267 MiB；固定验证 prefix 的 student-to-teacher KL 改善，但真实续写 NLL 退化。Qwen canary 只验证执行链路。旧实验的 top-k 为 32，新实验统一为 16，历史记录保持原值。

## 固定条件与比较单位

第一阶段继续使用 Pythia-14M student、Pythia-70M teacher、原有模型 revision 和 WikiText-2 的固定训练/验证 split。保持温度 1、top-p 1、生成 top-k 关闭、每 prompt 一条响应、全参数更新、hard outer sync、AdamW、weight decay 0、gradient clipping 1。缓存使用 anchor top-16 和一个聚合 tail 类别。它是 Tail-aware KL，不是 normalized head KL。诊断 oracle 使用完整词表。

先固定 prompt/response 上限为 64/64，context 128，以便隔离预算变化；后续另做 response 128/256 的长度对照。Pythia 基础模型的短续写不标为自然终止的完整轨迹。报告 EOS 率和长度截断率。

每个 inner 更新使用整个 outer rollout batch。mini-batch 等于 B，micro-batch 仅用于显存分块和梯度累积。记录 effective response token 数；不同 batch 的比较同时给出 outer 数、optimizer 更新数、生成 token 数、训练 token exposure 和 wall time。不同 B 采用相同 outer 数会改变数据预算，必须另按相同累计 prompt/token 预算比较。

固定 rollout 决定了 prefix 经验测度；token IS 只校正下一 token 的条件分布，不校正完整轨迹 occupancy。跨方法共享初始化、prompt 顺序和种子，但策略变化后的 rollout 自然不同；固定 rollout 的 paired inner 试验与在线 outer 试验分别报告。

## 阶段 A：显存与吞吐探测

| 变量                | 候选值     | 固定条件                      |
| ------------------- | ---------- | ----------------------------- |
| 完整 prompt batch B | 16、32、64 | J=4、lr=1e-6、eta=1           |
| GPU micro-batch     | 1、2、4    | mini-batch=B；相同 B 单独比较 |
| 每个探测预算        | 2 outer    | 相同短上下文、K=16            |

从 micro-batch 1 开始，逐步增加。记录整卡 nvidia-smi 采样峰值、actor allocated/reserved 峰值、生成/训练 token 每秒、outer wall time 和 OOM。整卡保留至少约 1.5 GiB 余量作为筛选目标，并检查最长序列下的峰值；采样峰值会漏掉瞬时尖峰。达到余量或吞吐饱和后停止增加 micro-batch。增大 B 不等于必须增大 micro-batch。

## 阶段 B：学习率与固定 rollout 的 inner 动力学

首个探测为 MDPO、eta=1、B=32、micro-batch=2、lr=1e-6、1 outer、J=32、K=16。它验证较长 inner 是否稳定、ESS 如何变化和资源是否允许扩大预算；它不能单独确认收敛。

正式 inner 校准分别对 Token-IS vOPD、MDPO、PMD-Mean、BPO 使用 lr 为 1e-7、3e-7、1e-6、3e-6。历史 1e-5 已出现验证退化，保留为高学习率诊断，不作为默认。先以 eta=1、一个固定 outer rollout、J=32 筛选，再对稳定候选运行 J=128，报告 J=1、4、16、32、64、128 的时点。共享该轮 rollout、冻结 cache、模型与 optimizer 初态，才能把 inner 路径作配对比较；当前 trainer 尚未导出可直接重放的完整 cache，需要在正式 paired 校准前补齐。

BPO、PMD-Mean 的系数尺度不同：初始化时 Mean 与 BPO 相差 eta 因子。AdamW 的归一化不能保证尺度影响完全消失，特别是 clipping 和 epsilon 存在。因此每个方法和 eta 分别校准 lr，同时报告同 lr 的机制对照。统一学习率的结果不能独立归因为目标更好。

inner 停止条件作为探索性规则：最近两个 8-update 窗口中，固定 rollout oracle 目标相对改善均小于 0.1%，参数相对更新 norm 和独立诊断梯度没有继续明显下降，再检查不同 batch/seed 是否一致。该阈值是预注册诊断规则，不是收敛定理。score coefficient RMS 尤其对 MDPO 不需要趋于零。PMD-Mean 的投影目标与 teacher KL 不同，分别评价投影 residual 和 teacher 对齐，不能只用 teacher KL 判定 inner 收敛。

ESS fraction 小于 0.5、ratio 极端增大、非有限损失或 KL 连续上升作为失稳告警。没有 silent ratio clipping；触发后保留原始记录，降低 lr 或缩短 J，再重复相同初态。由于响应内 token 相关，token ESS 只作权重集中度诊断，不作为独立样本数。

## 阶段 C：outer 预算与 batch 校准

筛选后的每个方法采用 B=32 或 64，在 64、128、256 outer 处保存并评价；允许训练集重复遍历，显式设置 total_epochs，避免原配置 total_epochs=1 使训练在到达指定 step 前结束。原训练集 512 prompt：B=32 时每个 epoch 16 outer，256 outer 至少需要 16 个 dataset epoch；B=64 时需要 32 个 epoch。

以固定验证文本上的 full-vocab 双向 KL、真实续写 NLL、熵和 teacher-generated/学生 rollout prefix 上的指标共同评估。选择规则为 KL 改善同时报告 NLL 代价，不把 NLL 退化隐藏在复合分数中。连续 3 个 checkpoint 改善小于 0.5% 且置信区间覆盖零时标记平台期；若未平台则延长到 512 outer。64 个历史验证文本用于校准，正式比较扩充到至少 256，并保留独立 test split 避免调参集兼作最终检验。

## 阶段 D：正式消融

| 因素             | 配置                                         |
| ---------------- | -------------------------------------------- |
| 主算法           | Token-IS vOPD、MDPO、PMD-Mean、BPO           |
| 采样基线         | On-policy vOPD，J=1、每次更新重新 rollout    |
| KL baseline 消融 | Token-IS vOPD with/without baseline          |
| eta              | MDPO/PMD-Mean/BPO：0.03、0.1、0.3、1         |
| 无穷端点         | 仅 MDPO 的冻结 reward 无镜像对照             |
| inner J          | 1、4、16、32；长 inner 最终值由阶段 B 决定   |
| seed             | 初筛 42，确认 42、43、44                     |
| top-k            | 主结果固定 16，少量 8/32/full-vocab 中心对照 |

vOPD 无 eta；MDPO eta=1 的总体梯度与无 baseline Token-IS OPD 一致，with-baseline 对照用于区分控制变量收益。eta 无穷不能直接用于 PMD-Mean/BPO，当前实现也拒绝这两个方法的无穷值。先完成预算校准，再对最有信息量的 J、eta 组合做三种子确认，避免全笛卡尔积耗费训练而缺少解释。

同 rollout 预算比较采样效率，同 optimizer/token exposure 比较优化效率，同 wall time 比较计算效率，三种横轴分别绘图。统计区间按 prompt/trajectory 聚类 bootstrap；多训练 seed 的变异单独展示。

## W&B 与每次实验交付

archbox 已安装 W&B SDK，现有凭据可用，2026-10-09 的在线测试已实际完成上传：[连接测试](https://wandb.ai/wncfht/mirror-opd/runs/p22qb3hg)。训练复用 verl 原生 tracking，通过 WANDB_MODE=online 与 trainer.logger=[console,file,wandb] 启用。默认启动仍允许 disabled/offline，用环境变量选择，所有 W&B scratch 放磁盘 runs/wandb 和 ~/.cache/wandb。

本地 resolved config、inner/outer JSONL、rollout、checkpoint 和 GPU CSV 保留为原始证据。W&B 展示在线 outer 指标；逐 inner 记录必须另外按 inner update/outer/inner index 明确上传，框架汇总值不能冒充逐 inner 曲线。每次结束生成以下产物后才登记为已分析：

1. 退出状态、完整配置、模型/data revision、远端核心与补丁 hash。
2. inner 位移、ESS、系数 RMS、梯度 norm、clipping 与参数更新曲线。
3. checkpoint 双向 full-vocab KL、NLL、entropy 曲线和逐 prompt 统计。
4. 显存、吞吐、累计生成/训练 token、wall-time 图。
5. 异常解释、比较限制和下一步保留/否决配置的依据。

## 首个探测后的调整

B=32、micro-batch=2、J=32、lr=1e-6 的探测已完成。峰值 4163 MiB，说明可继续增加 micro-batch 做吞吐探测；但 ESS 最低 0.426，独立 NLL 已退化。优先比较 lr=1e-7/3e-7 与 J=4/16/32，再决定是否上 J=128。长 inner 的 oracle 下降必须与 NLL、熵和 IS 集中度同时解释。资源上新增磁盘门槛：先确保至少 10 GiB 可用或规划独立归档盘；目前 1.8 GiB 不支持连续 checkpoint sweep。

## 默认保存策略修订

显存/吞吐和配置 smoke 默认不开 checkpoint，save_freq=-1；配置、原始 JSONL、rollout 和 GPU CSV 继续保存。正式 outer 预算比较需要独立 full-vocab 评价时，显式启用 model-only 保存，评价后再处理临时权重；当前离线评价程序不能在零权重条件下读取已释放的模型。不开保存的训练只标为训练诊断已完成。W&B 采用 [分组工作区](https://wandb.ai/wncfht/mirror-opd-pythia?nw=1wdmd1gnvqm)，详细约定见 [指标与保存策略](../operations/2026-10-09-WandB指标与保存策略.md)。

## 推理与训练的 attention 栈

rollout 仍使用 vLLM。配置中的 `actor_rollout_ref.rollout.name=vllm`、`calculate_log_probs=true` 和 `n=1` 使每个 outer step 由 vLLM 生成一条 response，并返回 rollout token 的旧策略 log-prob；这部分不经过带梯度的 PyTorch actor。PyTorch/FSDP 只负责 student actor 的反向更新，以及 reference/teacher 的精确 log-prob 前向。vLLM 不能替代 actor 更新，因为其 serving engine 不提供训练图和参数梯度。

attention kernel 的选择按 forward dtype 处理。正常 BF16 主路径保留 FlashAttention；FP32 诊断路径在 `FSDPEngine` 启动时自动把 `flash_attention_2/3` 切换为 PyTorch SDPA，因为 FlashAttention kernel 只接受 FP16/BF16。这个切换不影响 vLLM rollout。`dtype-smoke4` 验证了 BF16+vLLM+FlashAttention，`fp32-smoke3` 验证了 FP32+vLLM+SDPA；两者均完成 1 step，分别记录在 archbox 的 `runs/dtype-smoke4` 和 `runs/fp32-smoke3`。

## 校准矩阵执行入口

## 2026-10-09：矩阵结果与长程确认

校准矩阵已在 archbox 顺序完成 20 个作业，全部退出码为 0。每个作业有 `total_training_steps=1`，因此外层指标各只有一个点；这不是 inner 未执行。`J=1` 的 inner 文件有 1 行，`J=4` 有 4 行，`J=16` 有 16 行。资源组使用 B=16/32/64、micro-batch=1/2/4（B=64 的 micro=4 未运行），inner 组使用 J=1/4/16 与 lr=1e-7/3e-7/1e-6，eta 组使用 0.1/0.3/1.0。

矩阵首先排除了明显不稳定的组合。`J=16, lr=3e-7` 的最后一个 inner ESS fraction 为 0.062、最大 importance ratio 为 203.98；`B=16, micro=4` 为 0.088 和 121.96；这些配置不能作为默认。`J=4, lr=1e-7` 在 B=32、micro=2 下最后一个 inner ESS fraction 为 0.871，最大 ratio 为 9.93，作为长程候选。资源矩阵说明 B=32、micro=2 在 12 GiB RTX 4070 SUPER 上留有余量；B=64 没有带来足够稳定的权重集中度改善，先不作为默认。

随后运行了两个 16-outer、64-inner 的确认作业，均无 checkpoint、退出码为 0，并实时写入 W&B：[`eta=0.3`](https://wandb.ai/wncfht/mirror-opd-pythia/runs/abdxqqj2) 与 [`eta=1`](https://wandb.ai/wncfht/mirror-opd-pythia/runs/bpa3haul)。`eta=0.3` 的前两个 outer 出现瞬态尖峰（ESS fraction 0.180、0.079；最大 ratio 103.8、170.9），从第 3 个 outer 起 ESS 大多在 0.85--0.96，后续最大 ratio 多数小于 12。`eta=1` 的平均梯度范数更低，但在第 3、5、7 个 outer 仍反复出现 ESS 下探，最低 0.163，最大 ratio 108.98。基于这两个长程样本，当前 Pythia 默认暂定为 `B=32, micro=2, J=4, lr=1e-7, eta=0.3, K=16`；该选择是稳定性与 inner 计算量的工程折中，尚不是收敛定理。

这两次确认也改变了实验解释：单 outer 矩阵只能筛掉明显失稳点，不能证明 outer 动力学稳定。正式消融必须保留逐 inner ESS、importance ratio、梯度范数和 reward coefficient RMS，并把前两个 outer 的尖峰单独报告。下一轮应在同一 setting 下增加 seed 43/44，再与 Token-IS vOPD、PMD-Mean 和 BPO 对齐 outer/token 预算；只有在多 seed 的独立 full-vocab 评价完成后，才确定最终训练预算。

可复现入口为 `training/run_mdpo_calibration_matrix.sh`。它不保存 checkpoint，只保存 resolved config、outer/inner JSONL、rollout、GPU 采样和 W&B run。`MIRROR_CALIBRATION_STAGE=resource|inner|eta` 可单独运行阶段；默认顺序先完成 B/micro-batch 资源边界，再完成 J/lr inner 动力学，最后做 eta 对照。每个作业保持完整 rollout batch 等于 `ppo_mini_batch_size`，micro-batch 只改变梯度累积，不改变优化目标。
