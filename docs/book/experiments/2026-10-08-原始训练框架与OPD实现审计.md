# 原始训练框架与 OPD 实现审计

## 审计范围

正式训练应修改现有 verl/OpenKimi 数据流；独立 categorical 与随机 causal-LM 实现只作为数学 oracle。源码快照位于 `../../pmd-theory/MirrorOPD/source_audit/`，以下结论来自实际函数体。

|---|---|---|
| MDPO | c9bd3ba080e34f94e104ffe7633167e246dd63c6 | `mdpo_on/mdpo.py` |
| OpenKimi | 737515818bf950e0c3f3ee2483ae0c53be435385 | `openkimi/backends/verl/` |

## MDPO 的冻结策略与 inner 更新

`mdpo_on/mdpo.py` 的 `multistep-SGD` 最大化 `mean(ratio * atarg) - meankl / learning_rate_ph`，其中 ratio 是当前策略与 old policy 的 sampled-action 概率比，KL 使用 current‖old 方向。`sgd_steps` 在同一 feed 中重复优化，随后 `assign_old_eq_new` 把 model 变量复制给 oldpi。mirror 步长和 Adam 参数学习率由不同 placeholder 控制。

它是 TensorFlow/stable-baselines/MuJoCo 实现，可用于核对算法语义，不能直接承担 LLM rollout、teacher 推理和分布式训练。正式 LLM 实现应保留其冻结 anchor、多 inner step 和区分两种步长的语义。

## OpenKimi PMD 的 verl 接入

`core_algos.py::compute_policy_loss_opmd` 汇总整条 response 的 log-prob ratio，然后计算 sequence-level 平方残差；`rloo` 使用 group mean baseline，`ploo` 使用 leave-one-out partition baseline。它不是本文逐 prefix 的 token-level Mean/BPO。

`pmd_ray_trainer.py::fit` 生成 rollout 后，一次性重算 old log-prob，并缓存到 batch。actor 更新走继承的 `_update_actor`。`main_pmd.py` 在 Ray worker 进程导入 loss registry；只在 driver 注册会遗漏 worker。OpenKimi 的 verl 子模块固定为 `d9939add7a2a01923a9088891f913a5d20c4e622`，不能随意与其他 fork 的 actor API 混用。

## One-Shot-OPD 的 reward 路径

teacher worker 计算 sampled-token reward `teacher_log_probs - student_log_probs`，通过 `token_reward_direct` 作为 advantage 使用。`LOG_PROB_TOP_K` 会改变训练 reward；`METRIC_TOP_K` 只添加观测，不改变 sampled-token reward。

`compute_top_k_reward` 使用完整词表归一化的 log-prob 计算 log-ratio，然后对 student/teacher probability 权重在候选集内归一化。它没有把 log-ratio 同时替换为两边条件分布的 log-ratio，因此不能把这个函数称为标准 normalized conditional KL。`union-intersection` 权重还刻意不归一化。

`compute_policy_loss_vanilla_topk` 对每个候选 token 应用 PPO ratio/clipping，再沿候选轴求和。Mean/BPO 的冻结 anchor 测度公式不含这种 current/anchor ratio；不能仅替换 advantage 后沿用该 PPO loss。MDPO 需要 ratio，但 clipping 会引入另一种近似，也必须显式声明。

## TA-OPD 的直接损失路径

`fsdp/losses.py::compute_taopd_reverse_kl_topk` 计算 student 完整词表 logits 的 logsumexp，再 gather teacher top-k ids 上的 logits，避免额外保存完整 log-softmax。随后追加聚合 tail token，计算 reverse KL。它直接对 student logits 求导，固定访问 prefix 下尾部质量也有梯度。normalized 变体则分别减去 head logsumexp；unnormalized 变体只保留 head。

其 `log1mexp` 使用 `log(-expm1(x))` 与 `log1p(-exp(x))` 两个稳定分支，但先把输入上界裁到 `-1e-6`。这意味着极小尾部被设定为约 `1e-6` 的下限；函数具有稳定的数值行为，却不是所有概率质量下都精确的尾部计算。移植时需要单独验证小尾部、全支持集和归一化残差，不能把官方代码当成无误差 oracle。

`distillation_ppo_loss` 分成 logits processor 与最终 reduction 两阶段；当不使用 task reward 时，policy loss 被关闭，只保留 distillation loss。`sample_corrected_ta_opd` 对条件尾部 log-ratio 停止梯度，通过 student/behavior 概率比补上 sampled tail；复用 rollout 后必须提供 old log-prob，代码明确不静默裁剪该 ratio。

## 本项目应复用和改动的位置

1. 保留已有 verl rollout manager、actor optimizer、FSDP、response mask、checkpoint 和 vLLM 权重同步；不自建第二套训练循环。
2. 仿照 One-Shot 的 teacher worker 生成 frozen teacher action log-prob；增加 anchor top-k ids/head log-prob/tail mass，以及 teacher 在同一 anchor support 上的 head/tail 信息。
3. 仿照 TA-OPD logits processor，在每个 inner microbatch 从 student logits 计算 anchor‖student 的 Tail-aware center。支持集由 outer anchor 固定，方向与 TA-OPD 的 student‖teacher 不同。
4. 在 OpenKimi registry 注册独立 token-level Mean/BPO/MDPO loss，复用公共 reduction。center 和 residual 在解析 PG 权重中停止梯度；Mean/BPO 不引入 PPO ratio，MDPO 使用显式的停止梯度 current/anchor ratio。
5. 固定 outer batch 的 anchor 缓存贯穿全部 inner epochs。开始新 outer 前完成权重同步，再重新 rollout。严格同步第一版不混入异步陈旧策略。

## 固定 verl 子模块的调用链核验

已初始化 OpenKimi 固定的 verl 子模块。`workers/actor/dp_actor.py::update_policy` 通过显式 `select_keys` 筛选 batch，目前只保留 sampled log-prob、advantages、mask 等标准字段，不保留 head ids/head log-prob/tail mass。loss 调用也没有传递 OpenKimi `opmd` 签名中的 `extra_loss_kwargs`。因此在 legacy actor 路径下，仅增加 trainer 字段或注册新 loss 都不足以让 Tail-aware 数据到达 inner 更新。

该 actor 将 batch 按 `ppo_mini_batch_size` 拆分，再在 `ppo_epochs` 内反复更新。配置的 epoch 不等于单个 optimizer step；microbatch gradient accumulation、mini-batch 数量与 epoch 一起决定实际 inner 更新预算。冻结 `old_log_probs` 在这些循环内保持不变，但 student center 必须每个当前 student forward 重算。

父类 `RayPPOTrainer::_update_actor` 的新 worker 路径把 DataProto 转成无 padding TensorDict，设置 epochs、seed、shuffle，再交给 engine。`engine_workers.py` 在初始化时绑定 `ppo_loss`，提供 `set_loss_fn`；已有 TA-OPD 的 engine 路径在这里接入 distillation logits processor。这是比改 legacy actor 的 sampled-only forward 更直接的复用点，但仍需完整核对 mask、字段 layout 与 teacher 服务。

父类 `RayPPOTrainer::fit` 在 actor 更新后显式调用 `checkpoint_manager.update_weights()`，OpenKimi 自己重写的 `fit` 中没有对应调用。对 OpenKimi HEAD 原始文件的 `git show` 核对也确认该差异。异步 agent-loop 的 `generate_sequences` 入口没有自行触发 actor 权重更新。该静态差异必须通过权重版本或 canary log-prob 的运行测试核实；在验证前，不能声称它满足本文每轮 outer hard sync 的语义。

后续实现优先复用具有 teacher 服务和 distillation logits processor 的现有 verl engine，移植 OpenKimi 的注册方式及 PMD 语义；不用旧的 sequence-level PMD loss 充当 token-level Mean。正式实现选择 TA-OPD/verl 的 distillation logits processor 与冻结 reference teacher 路径，teacher 配置和 worker 生命周期的 CPU/GPU 验证见后文。

## Teacher 服务的信息约束

TA-OPD 的 `experimental/teacher_loop/teacher_manager.py` 通过 vLLM `prompt_logprobs=topk` 取 teacher 自己的 top-k 和 sampled token 概率。这不是任意 anchor top-k token 的打分接口：两个模型 top-k 不重合时，teacher 返回值中没有完整的 anchor 支持集概率。本文两个 KL 都以 anchor 为左分布，因此要使用 anchor support，就必须增加指定 token ids 的 teacher gather，或复用 One-Shot 的 FSDP teacher forward。不能通过扩大 teacher top-k 后默认所有 anchor ids 都存在。

该 teacher manager 明确拒绝非 1 的 distillation temperature，因为当前 vLLM prompt-logprob 接口不支持它。student rollout temperature、student score temperature 和 teacher score temperature必须定义一致；第一版使用 1，后续若使用 0.7，需要专门的温度调整评分路径，不能只修改生成参数。

One-Shot 的 `compute_top_k_teacher_log_probs` 接受 student candidate ids，使用 teacher 完整 logits 的 logsumexp 后 gather，能满足指定 anchor support 的 teacher 打分要求。因而 teacher 数据收集应参考这个路径，actor 侧 Tail-aware 重算参考 TA-OPD 的 logits processor。vLLM 仍用于 student rollout；复用这些组件不要求 teacher 推理也强制使用 vLLM。

## 官方函数的数值核验

`test_upstream_opd_semantics.py` 用 AST 提取上述官方纯张量函数的原始函数体，跳过 Ray/FSDP 服务导入后直接执行。此方法只验证函数数学行为，不证明整个 worker 管线正确。

对支持集上的完整概率 $p=(0.6,0.3)$、$q=(0.3,0.2)$，One-Shot 的 `only_stu`、`student_p` reward 求和为 −0.597253156，而负的条件分布 KL 为 −0.009466492。两者满足

$$
\sum_{v\in S}r(v)=-\mathrm{KL}(\bar p\Vert\bar q)-\log(P_S/Q_S).
$$

这是带归一化权重的 raw log-ratio reward，不是纯条件 KL。该恒等式并不意味着整条 PPO 梯度等于对上述标量求导：advantage 被冻结，候选 token 还经过 ratio 和 clipping。

TA-OPD 的 `log1mexp` 在真实尾部为 $10^{-3},10^{-6},10^{-8},10^{-12}$ 时，返回约 $10^{-3},10^{-6},10^{-6},10^{-6}$。稳定分支在裁剪阈值外正确；阈值内人为抬高尾部质量。对于本项目高度集中的 prefix，移植必须显式记录这个下限，或采用能保留真实尾部的计算方式。现有 full-vocabulary 标量实验使用直接 float64 尾部累加，因此没有该下限。

还枚举了四动作 behavior 分布，直接调用官方 `sample_corrected_ta_opd`：当 behavior 与当前 student 不同时，加入 student/behavior ratio 后，其期望 value 和梯度均匹配完整 reverse KL。核验使用精确聚合尾部，因此验证的是 correction 函数本身，不包括前置尾部下限的误差。官方函数把输入转成 float32，梯度比较采用相应数值容差。

验证命令 `uv run --with torch --with numpy python experiments/test_upstream_opd_semantics.py` 已通过 reward 恒等式、尾部阈值以及 reused-behavior correction 的 value/gradient 检查。

## 接入验证门槛

正式训练补丁必须同时通过：指定 anchor ids 的 teacher gather 对照 full-vocabulary oracle；no-padding/response-mask 字段对齐；三个 token loss 的原始梯度核验；每个 inner 更新重算 student center；outer 末端 actor-to-vLLM 权重版本一致；下一轮 rollout 来自新权重；checkpoint 恢复保持 global step、optimizer 和同步状态一致。CPU oracle 验证只覆盖数学与小模型 forward，不替代这些分布式调用链测试。

## 现有 TA-OPD 模块内的首个实现补丁

已在 TA-OPD 的 `verl/trainer/distillation/fsdp/losses.py` 增加 `compute_mirror_opd_token_loss`，可重放补丁保存于 `upstream_patches/ta-opd-mirror-token-loss.patch`。输入是当前 student logits、rollout actions，以及冻结 anchor support/head/tail/action log-prob、teacher action log-prob 和 teacher KL center。它在当前 logits 上重算 anchor‖student 的 Tail-aware center，返回逐 token surrogate 和诊断量；使用已有 logits-loss 模块，不另建训练循环。

Mean/BPO 的系数及 centers 停止梯度；MDPO 使用停止梯度的 student/anchor importance ratio，不做隐式裁剪。尾部通过当前完整词表 logits 上的掩码 logsumexp 计算，全支持集尾部为零。该函数只支持 local complete vocabulary，尚未实现 tensor-parallel vocabulary shards。三个模式已接入 loss registry、缓存消费入口及 trainer 的两阶段缓存生产调用链。三个模式已完成真实 GPU 的两轮更新和 checkpoint 保存。真实 vLLM rollout 的版本检查已通过，BPO 恢复续训完成；恢复后的真实 rollout 也已通过版本检查，版本为 2。

官方函数审计脚本已增加 9 个方法/support 检查；全支持集时三个方法的枚举 action 期望梯度均匹配原始损失，部分支持集 center 停止梯度且更新有限。这一步证明计算模块正确，不证明生产调用链正确。

后续补丁已注册 `mirror_pmd_mean`、`mirror_bpo`、`mirror_mdpo`，在原有 `compute_topk_loss` 分发到缓存适配器，并扩展 `left_right_2_no_padding` 保留八个 `mirror_*` 字段。缓存按完整序列的预测位置组织：response token 的动作与概率写入其前驱位置，prompt 内部和终止位置设为无效。适配器先筛选有效位置再计算，因此无效位置的 NaN 概率和占位 ids 不会污染 loss。新增 jagged 测试覆盖三个方法的缓存读取、无效位置零梯度和有效位置梯度，结果与直接计算模块一致。

配置中的 `mirror_eta` 与 optimizer learning rate 分开。三个模式要求 `use_policy_gradient=false`、`use_task_rewards=false`、`loss_max_clamp=null`、`log_prob_min_clamp=null`：surrogate 已包含解析 score 梯度，再进入已有 PPO reward 包装会改变算法。配置与 loss 入口均拒绝这些冲突选项。当前只支持 sequence parallel size 1 和完整本地词表；指定 anchor ids 的 teacher 缓存生产已经在真实训练中执行。两轮训练已覆盖外层同步调用和 checkpoint 保存；权重版本的一致性及恢复续训需要分别验证。

### 完整词表缓存生产与 causal LM 验证

上游 logits-loss 模块新增 `build_mirror_opd_cache_from_full_logits`。它接收同一组 prefix 的冻结 anchor 与 teacher logits，以 anchor top-$J$ 定义支持集，计算 teacher 在这些 ids 上的 log-prob、聚合尾部和 rollout action 的 log-prob，生成八个缓存字段。两侧尾部均通过支持集外 logits 的 logsumexp 计算，不采用概率质量相减或人为尾部下限。无效预测位置在 log-softmax 及 gather 前屏蔽；有效缓存全部停止梯度。

缓存生产拆成 `build_mirror_anchor_cache` 与 `complete_mirror_teacher_cache` 两个接口，完整词表函数调用它们作为 oracle。第一次 forward 后只保留每个 prefix 的 $J$ 个 ids、head log-prob、tail log-mass 和 sampled action log-prob；第二次 teacher forward 对指定 ids 评分并生成 center。两个模型的完整词表 logits 无须同时驻留，也无须通过 worker 通信传输。中间缓存额外记录词表大小，并在 teacher 端拒绝尺寸不一致；tokenizer 的词表语义一致性仍需初始化时验证。分阶段计算与 oracle 逐字段相等，teacher 补全不会原地修改 anchor 缓存。小型 causal LM 测试使用这两个分阶段接口。

张量验证覆盖 $J=0$、部分支持、$J=|\mathcal V|$、小于 $10^{-16}$ 的尾部以及无效位置 NaN 和非法占位 ids。完整支持下 teacher center 与完整 KL 一致；空支持下聚合 KL 为零；极小尾部保持真实 log-mass。该生产函数尚需在分布式 worker 上连接真实 teacher forward，不能用原生 teacher top-$J$ 返回结果代替指定 anchor ids 的评分。

`test_upstream_mirror_lm.py` 使用随机初始化的一层 GPT-2 causal LM，直接调用上游缓存生产函数、token loss 与缓存适配器。PMD-Mean、BPO、MDPO 各运行 3 个 outer step，每轮从当前 anchor 生成 4 个 token，再执行 4 个 SGD inner step，$\eta=0.5$、$J=4$。验证逐轮 hard sync、冻结 anchor 参数、冻结缓存、outer 起点 student center 为零、inner 更新后 center 重算及所有 loss 和梯度有限。三个方法均通过。生成时显式提供全有效 attention mask，避免把随机生成的 pad-id 当作 padding。

复现命令为 `uv run --with torch --with numpy --with transformers python 科研/MirrorOPD/experiments/test_upstream_mirror_lm.py`。这是对上游计算模块的 CPU 模型集成验证；Ray 调度、FSDP CUDA backward、vLLM 权重广播及 checkpoint 恢复尚未由该测试覆盖。

FSDP engine 的 log-prob 分支在同时计算 top-$J$ distillation 时关闭 `inplace_backward`，使 sampled log-prob 与 distillation 的梯度共享 logits 时保留原值。该更改仍需实际 CUDA engine 测试确认，CPU loss 测试不会经过该分支。

### Worker 推理入口与预测位置对齐

FSDP engine 已增加独立的 `mirror_cache_stage=anchor/teacher` 推理入口。缓存评分与 distillation training 分成不同 forward；评分要求 `compute_loss=false`、完整本地词表 logits、非 fused kernel 以及 sequence parallel size 1。anchor 阶段返回带 trailing head 维度的 jagged 缓存，teacher 阶段只返回 sampled action log-prob 与 teacher center。该入口复用现有 `infer_batch` 的模型加载、micro-batch 切分与 CPU 返回机制；trainer 在重算 old log-prob 时发出 anchor 请求，随后发出 teacher 请求，在 inner 更新之前完成缓存。

`build_mirror_prediction_fields` 将 response action 写到前驱预测位置，联合 response mask 和相邻 attention mask 排除 prompt、padding 与跨序列终止位置。`no_padding_2_full_padding` 通过原 unpadding indices 恢复完整预测位置，不再移位；原有 `no_padding_2_padding` 继续负责 response-only loss 的一次移位。二者用途分开，避免将缓存当作 response 数组再次左移。

CPU 对齐测试使用两个不同长度的 prompt/response：一条左填充 prompt 与两个有效 response token，另一条完整 prompt 与四个有效 response token。验证六个 predictor 位置、两个评分阶段与 full-logit oracle 一致、head 维度保持、padding 位置归零，以及 response-only action 数组与原 rollout tokens 相同。这项 CPU 测试直接运行缓存和 padding 函数，不覆盖 FSDP engine 的完整 forward；后续真实 GPU 运行补充了 engine 执行证据。

实际 teacher 接入采用已有 reference worker 的冻结模型推理路径。原生 teacher server 返回 teacher 自己的 top-$J$，与 anchor support 不一致，不能用于此路径。Mirror 模式通过 `distillation.mirror_teacher_model_path` 创建独立的 teacher HF 配置，并检查 tokenizer 词表映射和模型词表大小一致。它强制分配 reference role，关闭 native teacher manager，并保留 distillation config。模型参数更新不经过 reference worker；teacher 推理要求 forward-only。

### Trainer 路由验证与运行边界

`test_upstream_mirror_wiring.py` 执行上游 trainer 的 `_compute_old_log_prob`、`_compute_mirror_teacher_cache` 原函数体，以 CPU worker 替代 Ray 传输。两个不同长度的序列共有六个有效 response token，测试检查请求顺序为 anchor、teacher，温度参数相同，两个请求均关闭 loss 计算，缓存恢复到完整 predictor 位置，且没有生成原生 `teacher_ids` 字段。

## 平方回归与停止梯度 score surrogate 的关系

以下推导固定一个 prefix，令 $q=\pi_k$、$p=\pi_\theta$，所有期望均对冻结的 $q$ 求取。定义 $r=\log(T/q)$、$\ell_\theta=\log(p/q)$、$K_T=\mathrm{KL}(q\Vert T)=-\mathbb E_q r$、$K_\theta=\mathrm{KL}(q\Vert p)=-\mathbb E_q\ell_\theta$。再对冻结 prefix 测度取期望即可得到 token-level 总损失；这里不对 rollout 测度求导。

PMD-Mean 的平方损失及梯度是

$$
L_{\rm Mean}=\frac12\mathbb E_q[(\ell_\theta-\eta(r+K_T))^2],\qquad
\nabla_\theta L_{\rm Mean}=\mathbb E_q[(\ell_\theta-\eta(r+K_T))\nabla_\theta\log p].
$$

因此 $\mathbb E_q[\operatorname{sg}(\ell_\theta-\eta(r+K_T))\log p]$ 的自动微分梯度等于上述梯度。平方损失内的 $\ell_\theta$ 保持可微；score surrogate 内的整个乘法系数停止梯度。将 $K_T$ 换成冻结的 Tail-aware teacher center 后，这个等价关系仍成立，因为 teacher center 不依赖当前 student 参数。

BPO 使用 $D_\theta=\ell_\theta+K_\theta-\eta(r+K_T)$。由精确中心的定义，$\mathbb E_qD_\theta=0$。其平方损失的完整微分为

$$
\begin{aligned}
L_{\rm BPO}&=\frac1{2\eta}\mathbb E_q[D_\theta^2],\\
\nabla_\theta K_\theta&=-\mathbb E_q[\nabla_\theta\log p],\\
\nabla_\theta L_{\rm BPO}
&=\frac1\eta\mathbb E_q[D_\theta\nabla_\theta\log p]
 -\frac1\eta\mathbb E_q[D_\theta]\mathbb E_q[\nabla_\theta\log p]\\
&=\frac1\eta\mathbb E_q[D_\theta\nabla_\theta\log p].
\end{aligned}
$$

这里第二项消失的依据是残差均值为零；inner 更新后 $p\ne q$ 时，$\mathbb E_q\nabla_\theta\log p$ 一般不为零。原始平方损失中的 $K_\theta$ 保持可微，而推导后的 score surrogate 使用 $\operatorname{sg}(D_\theta/\eta)\log p$。

Tail-aware 聚合使 $\widehat K_T=K_T-b_T$、$\widehat K_\theta=K_\theta-b_\theta$，其中 $b_T,b_\theta$ 分别为 anchor 尾部质量乘以相应尾部条件分布 KL。定义 $\widehat D_\theta=\ell_\theta+\widehat K_\theta-\eta(r+\widehat K_T)$，则

$$
\mathbb E_q\widehat D_\theta=-b_\theta+\eta b_T.
$$

对替换中心后的平方损失直接求完整梯度，会得到

$$
\nabla_\theta\frac1{2\eta}\mathbb E_q[\widehat D_\theta^2]
=\frac1\eta\mathbb E_q[\widehat D_\theta\nabla_\theta\log p]
 +\frac1\eta\mathbb E_q[\widehat D_\theta]\nabla_\theta\widehat K_\theta.
$$

现有实现选择第一项，即用 Tail-aware 中心近似原始 BPO 的解析梯度；它不是上述替换平方损失的完整梯度。其相对于精确 BPO 的梯度误差为

$$
\widehat\nabla_\theta L_{\rm BPO}-\nabla_\theta L_{\rm BPO}
=\left(b_T-\frac{b_\theta}{\eta}\right)\mathbb E_q[\nabla_\theta\log p].
$$

在 $p=q$ 的 outer 起点，该误差因 score 均值为零而消失；离开 anchor 后必须纳入偏差分析。把估计中心 detach 后再对平方损失求导，也会得到第一项，但这属于每步重算目标的半梯度更新，不能据此声称存在同一个被精确优化的平方目标。以上都是总体期望恒等式；同一个 sampled action 同时参与随机中心估计时，还须单独分析二者的相关性。

### Outer 权重版本检查

运行时在每个 MirrorOPD rollout 后读取 vLLM server 返回的 `global_steps`，要求每条轨迹的版本等于当前训练步减一；版本缺失、混合或陈旧时，在构建 anchor 缓存前抛出错误。恢复到第 2 步时，下一批应报告版本 2。该版本由上游 server adapter 在同步路径设置，检查同步顺序；它不证明 vLLM 与 FSDP 数值逐位一致。CPU 检查覆盖初始、更新后和恢复后的正确版本，以及缺失、陈旧、混合和长度错误。带此检查的真实 GPU BPO 运行完成两轮训练并正常退出，日志无 traceback；第 1、2 个训练步分别报告 server 权重版本 0、1。修正配置下也未复现首次 BPO 的 DataLoader 退出异常。带版本检查的恢复运行也正常退出，第 3 步 rollout 报告版本 2，恢复模型、optimizer、rng 和 lr_scheduler 后完成更新和保存。
