# 原始训练框架与 OPD 实现审计

## 审计范围

正式训练应修改现有 verl/OpenKimi 数据流；独立 categorical 与随机 causal-LM 实现只作为数学 oracle。源码快照位于 `../../pmd-theory/MirrorOPD/source_audit/`，以下结论来自实际函数体。

| 项目 | 快照 commit | 核心路径 |
|---|---|---|
| MDPO | c9bd3ba080e34f94e104ffe7633167e246dd63c6 | `mdpo_on/mdpo.py` |
| OpenKimi | 737515818bf950e0c3f3ee2483ae0c53be435385 | `openkimi/backends/verl/` |
| One-Shot-OPD | 6b6b1782cc3f04749dd077de19353f839f6bc048 | `verl/verl/workers/fsdp_teacher_worker.py` |

## MDPO 的冻结策略与 inner 更新

`mdpo_on/mdpo.py` 的 `multistep-SGD` 最大化 `mean(ratio * atarg) - meankl / learning_rate_ph`，其中 ratio 是当前策略与 old policy 的 sampled-action 概率比，KL 使用 current‖old 方向。`sgd_steps` 在同一 feed 中重复优化，随后 `assign_old_eq_new` 把 model 变量复制给 oldpi。mirror 步长和 Adam 参数学习率由不同 placeholder 控制。

它是 TensorFlow/stable-baselines/MuJoCo 实现，可用于核对算法语义，不能直接承担 LLM rollout、teacher 推理和分布式训练。正式 LLM 实现应保留其冻结 anchor、多 inner step 和区分两种步长的语义。

## OpenKimi PMD 的 verl 接入

`core_algos.py::compute_policy_loss_opmd` 汇总整条 response 的 log-prob ratio，然后计算 sequence-level 平方残差；`rloo` 使用 group mean baseline，`ploo` 使用 leave-one-out partition baseline。它不是本文逐 prefix 的 token-level Mean/BPO。

`pmd_ray_trainer.py::fit` 生成 rollout 后，一次性重算 old log-prob，并缓存到 batch。actor 更新走继承的 `_update_actor`。`main_pmd.py` 在 Ray worker 进程导入 loss registry；只在 driver 注册会遗漏 worker。OpenKimi 的 verl 子模块固定为 `d9939add7a2a01923a9088891f913a5d20c4e622`，不能随意与其他 fork 的 actor API 混用。

## One-Shot-OPD 的 reward 路径

teacher worker 计算 sampled-token reward `teacher_log_probs - student_log_probs`，通过 `token_reward_direct` 作为 advantage 使用。`LOG_PROB_TOP_K` 会改变训练 reward；`METRIC_TOP_K` 只添加观测，不改变 sampled-token reward。

`compute_top_k_reward` 使用完整词表归一化的 log-prob 计算 log-ratio，然后对 student/teacher probability 权重在候选集内归一化。它没有把 log-ratio 同时替换为两边条件分布的 log-ratio，因此不能把这个函数称为标准 normalized conditional KL。`union-intersection` 权重还刻意不归一化。

`compute_policy_loss_vanilla_topk` 对每个候选 token 应用 PPO ratio/clipping，再沿候选轴求和。Mean/BPO 的冻结 anchor 测度公式不含这种 current/anchor ratio；不能仅替换 advantage 后沿用该 PPO loss。MDPO 需要 ratio，但 clipping 会引入另一种近似，也必须显式声明。

## TA-OPD 的直接损失路径

`fsdp/losses.py::compute_taopd_reverse_kl_topk` 计算 student 完整词表 logits 的 logsumexp，再 gather teacher top-k ids 上的 logits，避免额外保存完整 log-softmax。随后追加聚合 tail token，计算 reverse KL。它直接对 student logits 求导，固定访问 prefix 下尾部质量也有梯度。normalized 变体则分别减去 head logsumexp；unnormalized 变体只保留 head。

其 `log1mexp` 使用 `log(-expm1(x))` 与 `log1p(-exp(x))` 两个稳定分支，但先把输入上界裁到 `-1e-6`。这意味着极小尾部被设定为约 `1e-6` 的下限；函数具有稳定的数值行为，却不是所有概率质量下都精确的尾部计算。移植时需要单独验证小尾部、全支持集和归一化残差，不能把官方代码当成无误差 oracle。

`distillation_ppo_loss` 分成 logits processor 与最终 reduction 两阶段；当不使用 task reward 时，policy loss 被关闭，只保留 distillation loss。`sample_corrected_ta_opd` 对条件尾部 log-ratio 停止梯度，通过 student/behavior 概率比补上 sampled tail；复用 rollout 后必须提供 old log-prob，代码明确不静默裁剪该 ratio。

## 本项目应复用和改动的位置

1. 保留已有 verl rollout manager、actor optimizer、FSDP、response mask、checkpoint 和 vLLM 权重同步；不自建第二套训练循环。
2. 仿照 One-Shot 的 teacher worker 生成 frozen teacher action log-prob；增加 anchor top-k ids/head log-prob/tail mass，以及 teacher 在同一 anchor support 上的 head/tail 信息。
3. 仿照 TA-OPD logits processor，在每个 inner microbatch 从 student logits 计算 anchor‖student 的 Tail-aware center。支持集由 outer anchor 固定，方向与 TA-OPD 的 student‖teacher 不同。
4. 在 OpenKimi registry 注册独立 token-level Mean/BPO/MDPO loss，复用公共 reduction。center 和 residual 在解析 PG 权重中停止梯度；Mean/BPO 不引入 PPO ratio，MDPO 使用显式的停止梯度 current/anchor ratio。
5. 固定 outer batch 的 anchor 缓存贯穿全部 inner epochs。开始新 outer 前完成权重同步，再重新 rollout。严格同步第一版不混入异步陈旧策略。

## 固定 verl 子模块的调用链核验

已初始化 OpenKimi 固定的 verl 子模块。`workers/actor/dp_actor.py::update_policy` 通过显式 `select_keys` 筛选 batch，目前只保留 sampled log-prob、advantages、mask 等标准字段，不保留 head ids/head log-prob/tail mass。loss 调用也没有传递 OpenKimi `opmd` 签名中的 `extra_loss_kwargs`。因此在 legacy actor 路径下，仅增加 trainer 字段或注册新 loss 都不足以让 Tail-aware 数据到达 inner 更新。

该 actor 将 batch 按 `ppo_mini_batch_size` 拆分，再在 `ppo_epochs` 内反复更新。配置的 epoch 不等于单个 optimizer step；microbatch gradient accumulation、mini-batch 数量与 epoch 一起决定实际 inner 更新预算。冻结 `old_log_probs` 在这些循环内保持不变，但 student center 必须每个当前 student forward 重算。

父类 `RayPPOTrainer::_update_actor` 的新 worker 路径把 DataProto 转成无 padding TensorDict，设置 epochs、seed、shuffle，再交给 engine。`engine_workers.py` 在初始化时绑定 `ppo_loss`，提供 `set_loss_fn`；已有 TA-OPD 的 engine 路径在这里接入 distillation logits processor。这是比改 legacy actor 的 sampled-only forward 更直接的复用点，但仍需完整核对 mask、字段 layout 与 teacher 服务。

父类 `RayPPOTrainer::fit` 在 actor 更新后显式调用 `checkpoint_manager.update_weights()`，OpenKimi 自己重写的 `fit` 中没有对应调用。对 OpenKimi HEAD 原始文件的 `git show` 核对也确认该差异。异步 agent-loop 的 `generate_sequences` 入口没有自行触发 actor 权重更新。该静态差异必须通过权重版本或 canary log-prob 的运行测试核实；在验证前，不能声称它满足本文每轮 outer hard sync 的语义。

后续实现优先复用具有 teacher 服务和 distillation logits processor 的现有 verl engine，移植 OpenKimi 的注册方式及 PMD 语义；不用旧的 sequence-level PMD loss 充当 token-level Mean。正式 fork 选择仍待 teacher 配置和 worker 生命周期核验，本节不是生产管线已完成的声明。

## Teacher 服务的信息约束

TA-OPD 的 `experimental/teacher_loop/teacher_manager.py` 通过 vLLM `prompt_logprobs=topk` 取 teacher 自己的 top-k 和 sampled token 概率。这不是任意 anchor top-k token 的打分接口：两个模型 top-k 不重合时，teacher 返回值中没有完整的 anchor 支持集概率。本文两个 KL 都以 anchor 为左分布，因此要使用 anchor support，就必须增加指定 token ids 的 teacher gather，或复用 One-Shot 的 FSDP teacher forward。不能通过扩大 teacher top-k 后默认所有 anchor ids 都存在。

该 teacher manager 明确拒绝非 1 的 distillation temperature，因为当前 vLLM prompt-logprob 接口不支持它。student rollout temperature、student score temperature 和 teacher score temperature必须定义一致；第一版使用 1，后续若使用 0.7，需要专门的温度调整评分路径，不能只修改生成参数。

One-Shot 的 `compute_top_k_teacher_log_probs` 接受 student candidate ids，使用 teacher 完整 logits 的 logsumexp 后 gather，能满足指定 anchor support 的 teacher 打分要求。因而 teacher 数据收集应参考这个路径，actor 侧 Tail-aware 重算参考 TA-OPD 的 logits processor。vLLM 仍用于 student rollout；复用这些组件不要求 teacher 推理也强制使用 vLLM。

## 官方函数的数值核验

`test_upstream_opd_semantics.py` 用 AST 提取上述官方纯张量函数的原始函数体，跳过 Ray/FSDP 服务导入后直接执行。此方法只验证函数数学行为，不证明整个 worker 管线正确。

对支持集上的完整概率 $p=(0.6,0.3)$、$q=(0.3,0.2)$，One-Shot 的 `only_stu`、`student_p` reward 求和为 −0.597253156，而负的条件分布 KL 为 −0.009466492。两者满足

$$
\sum_{v\in S}r(v)=-\mathrm{KL}(\bar p\Vert\bar q)-\log(P_S/Q_S).
$$

这是带归一化权重的 raw log-ratio reward，不是纯条件 KL。该恒等式并不意味着整条 PPO 梯度等于对上述标量求导：advantage 被冻结，候选 token 还经过 ratio 和 clipping。

TA-OPD 的 `log1mexp` 在真实尾部为 $10^{-3},10^{-6},10^{-8},10^{-12}$ 时，返回约 $10^{-3},10^{-6},10^{-6},10^{-6}$。稳定分支在裁剪阈值外正确；阈值内人为抬高尾部质量。对于本项目高度集中的 prefix，移植必须显式记录这个下限，或采用能保留真实尾部的计算方式。现有 full-vocabulary 标量实验使用直接 float64 尾部累加，因此没有该下限。

还枚举了四动作 behavior 分布，直接调用官方 `sample_corrected_ta_opd`：当 behavior 与当前 student 不同时，加入 student/behavior ratio 后，其期望 value 和梯度均匹配完整 reverse KL。核验使用精确聚合尾部，因此验证的是 correction 函数本身，不包括前置尾部下限的误差。官方函数把输入转成 float32，梯度比较采用相应数值容差。

验证命令 `uv run --with torch --with numpy python experiments/test_upstream_opd_semantics.py` 已通过 reward 恒等式、尾部阈值以及 reused-behavior correction 的 value/gradient 检查。

## 接入验证门槛

正式训练补丁必须同时通过：指定 anchor ids 的 teacher gather 对照 full-vocabulary oracle；no-padding/response-mask 字段对齐；三个 token loss 的原始梯度核验；每个 inner 更新重算 student center；outer 末端 actor-to-vLLM 权重版本一致；下一轮 rollout 来自新权重；checkpoint 恢复保持 global step、optimizer 和同步状态一致。CPU oracle 验证只覆盖数学与小模型 forward，不替代这些分布式调用链测试。
