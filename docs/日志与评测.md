# 日志与评测

当前事件及配置 schema 为 2。本地事件、逐题生成记录和冻结源码用于审计，W&B 展示同一批统计。字段来源分别是 [events](../src/mirroropd/runtime/events.py)、[metrics](../src/mirroropd/runtime/metrics.py)、[tracking](../src/mirroropd/runtime/tracking.py)及[evaluation](../src/mirroropd/runtime/evaluation.py)。旧 `opd-metrics-v1`、`00_axes/*` 和旧实验中的 `teacher_center` 不作为当前字段契约。

## 事件身份与测量时点

每个 producer 独占一个 JSONL 流。事件包含 `schema_version`、`run_id`、`source`、`producer_id`、单 producer 的 `sequence`、`event_id`、UTC 时间、单调时钟、`event`、`context` 与 `payload`。重启使用新 producer 身份，不能用覆盖文件或重复序号恢复。reader 只消费换行结束的完整记录，截断已读取流会失败。

`optimization.step` 由 rank0 写全局归约后的记录，包含 `outer`、`inner`、`update`、`updates_completed`、`measurement=pre_update`、`algorithm`、`loss_kind` 和 `metrics`。前三个坐标从零开始，$\mathrm{update}=\mathrm{outer}\,J+\mathrm{inner}$。`updates_completed=update+1` 表示这次更新计数；策略诊断来自更新前。

outer 完成边界记录 `training.outer_completed`；评测完成记录 `evaluation.completed`，按 `model_version` 关联同步后的权重。phase 事件分 started/completed/failed；错误类型、持续秒数和资源值保留在所属事件中。

## 内存观测范围

`phase.started` 与 `phase.completed` 的 `memory` 包含当前 producer 的 RSS、PSS、private 和 locked 字节；Linux `/proc` 不可用时相应字段缺失。`locked_bytes` 是进程锁页计数，不能替代完整 CUDA pinned allocator 统计。CUDA 已初始化的 producer 另记录当前设备的 allocated、reserved 和 process peak；driver 的主存数据不能代表模型 worker。

普通观测不初始化 CUDA、不同步、不重置峰值，`memory_scope=process_peak`。启用 `memory.profile_phases` 后，原生 worker 的整个 train/infer 操作在开始处同步并重置峰值，在完成处同步，记录 `memory_scope=phase_peak`。嵌套 projection 事件不会再次重置；其读到的 peak 仍属于外层 worker 操作。`allocated_delta_bytes` 是结束减开始的常驻分配差，不能当作阶段临时峰值。allocated/reserved 属于 PyTorch allocator，不覆盖 vLLM 独立进程或设备整卡占用。

详细 profiling 另记录 `projection.anchor`、`projection.teacher`、`projection.actor` span；`cache.scored` 给出本次 micro-batch 的有效数和输出 host storage 字节，包括 jagged offsets，按底层 storage 去重。它描述这份输出，不能把不同 micro-batch 的数值直接相加作为同时驻留峰值。时间与容量比较须保持 profiling、分块、诊断和 offload 配置一致。

## 蒸馏与优化指标

| `distill/` 后的名称                       | 含义与限制                                                 |
| ----------------------------------------- | ---------------------------------------------------------- |
| `reward`                                  | 记录动作上的归一化幂均值信号 $A(\log(T/q))$                |
| `frozen_reward_center`                    | 冻结的 $-\mathbb E_qA$ 或分区近似，一般不是普通 KL         |
| `on_policy_baseline`                      | fresh on-policy 使用的同一冻结 baseline                    |
| `student_anchor_kl`                       | $\operatorname{KL}(q\Vert p)$ 或分区近似，方向为锚点到学生 |
| `action_nll`                              | 对记录动作的 $-\log p(a)$，不是参考答案 NLL                |
| `score_coefficient`                       | 乘在 log-prob 前、整个停止梯度的下降系数                   |
| `log_anchor_ratio`                        | $\log p(a)-\log q(a)$                                      |
| `importance_ratio`                        | $p(a)/q(a)$，当前 sampled MDPO 记录                        |
| `conditional_objective`                   | 完整动作积分的 MDPO/BPO 条件目标，由 algorithm 区分        |
| `student_entropy`                         | 完整合法词表上的当前学生熵                                 |
| `anchor_head_mass` / `anchor_tail_mass`   | 冻结锚点在其 Top-J 与补集上的概率质量                      |
| `student_head_mass` / `student_tail_mass` | 当前学生在同一冻结支持集与补集上的质量                     |
| `student_anchor_support_jaccard`          | 当前学生与锚点各自 Top-J 的 Jaccard                        |
| `student_teacher_support_jaccard`         | 当前学生与教师各自 Top-J 的 Jaccard                        |
| `anchor_teacher_support_jaccard`          | 锚点与教师各自 Top-J 的 Jaccard                            |

诊断范围由 `objective.diagnostics=none/basic/full` 和积分方式决定，不能假定每个运行拥有全部字段。`none` 关闭可选诊断，但 BPO 更新仍计算其必需中心。完整诊断需要冻结教师 Top-J；J=0 时支持 Jaccard 按实现约定为 0。

等长 Top-J 集合 $S_1,S_2$ 的 Jaccard 为 $|S_1\cap S_2|/|S_1\cup S_2|$，不是交集数除以 J。head mass 则是概率加权量。三者不能互换，也不会自动改变优化支持集。

每项诊断记录 `/mean`、`/std`、`/rms`、`/min`、`/max`；原始充分统计量在 micro-batch 和 DP 层合并后才求比值。设有效 token 数为 N：

$$
\overline x=\frac{\sum_ix_i}{N},\qquad
\sigma^2=\max\left(0,\frac{\sum_ix_i^2}{N}-\overline x^2\right),\qquad
\mathrm{RMS}=\sqrt{\frac{\sum_ix_i^2}{N}}.
$$

std 为总体标准差（ddof=0），描述该批相关 token 的离散程度，不是独立实验的标准误。有效数为 `distill/valid_tokens`。固定后端 DP 平均 SUM 字段，因此总数与 ESS 需乘回 DP 数，均值中的公共因子抵消。不能平均各 micro-batch 的 std、分位数或 ESS。

sampled MDPO 另记录

$$
\mathrm{importance\_ess}=\frac{(\sum_iw_i)^2}{\sum_iw_i^2},\qquad
\mathrm{importance\_ess\_fraction}=\frac{(\sum_iw_i)^2}{N\sum_iw_i^2}.
$$

该量衡量经验重要性权重集中度；轨迹内 token 相关，不能当作独立前缀样本数，也不测量 reward 或完整参数梯度的信噪比。

优化指标为 `optimization/gradient_norm`、`clip_scale`、`was_clipped`。范数来自本次 clipping 前梯度，scale 为阈值与范数比截到 1 的结果；它不限制参数更新后的 KL。学习率由 driver 转换为 `optimization/learning_rate`。

## W&B 横轴与单位

| 字段族                                                        | 横轴              |
| ------------------------------------------------------------- | ----------------- |
| `distill/*`、`optimization/*`                                 | `axis/update`     |
| `evaluation/*`                                                | `axis/evaluation` |
| `timing/*`、`resources/*`、`task/*`、`policy/*`、`training/*` | `axis/outer`      |

SDK history step 保持单调，但不是优化次数。driver 过滤上游重复蒸馏摘要，worker 的逐更新记录是优化统计来源。耗时转换为 `timing/..._seconds`；prompt/response 长度转换为资源 token 计数；preemption 的 -1 表示不可用，不转换成负次数。设备整卡使用量与 worker allocated/reserved 各自保留测量范围，不能相加或互称峰值。

启用 W&B 不改变本地审计要求；离线结果也不能依赖只在云端存在的截图。`--wandb offline` 保留相同指标与横轴，SDK 文件写在该运行的 `wandb/` 下，`wandb.json` 记录离线模式、run ID 和空 URL。`disabled` 仍保留本地事件。控制进程 stdout/stderr 在 `controller.log`，后端 stdout/stderr 在 `backend.log`。账号配置、人工回传和显式 `wandb sync` 见[运行指南](运行与复现.md)。

## 逐题评测与比较协议

Protocol 记录每题生成数 N、temperature、top-p/top-k、prompt/response/context 预算、seed、scorer 身份、binary/scalar 分数域及 schema。`protocol_id` 绑定这些内容。当前采样协议要求正温度，不能把历史 greedy R1 成绩直接当作当前 sampled R16。

对数据源中的 Q 道题，每题 N 次生成，定义

$$
\mathrm{mean@N}=\frac1Q\sum_{i=1}^Q\frac1N\sum_{j=1}^Nr_{ij}.
$$

binary scorer 另记录 $\mathrm{pass@N}=Q^{-1}\sum_i\max_jr_{ij}$，表示实际 N 次中至少一次正确；它不是 majority、best-of-N 选择器或其他采样数的外推估计。scalar scorer 只报告 mean，不套用二元 pass。

每条验证记录绑定 `question_uid`、`sample_index`、`model_version`、`protocol_id`、实际 request seed、score、response token 数、finish reason 与 EOS 状态，并保留原始生成内容。seed 由基础种子、phase、权重版本、题目 UID 和 sample index 派生。固定 seed 仍不能保证不同引擎或调度逐 bit 一致。

评测需覆盖预期所有题目，且每题恰有索引 0 至 N−1；重复、缺失、过期权重、非有限或越域分数均失败。长度终止需达到独立 response 预算；统计输出包含按来源的回答均长、预算耗尽和 EOS 比例。当前编译器写出 `validation/<model_version>.jsonl`；旧文档的“关闭 validation dump”不适用于当前审计。

比较模型时固定题目、模板、判分、解码、长度和训练预算。按题或轨迹计算不确定性，不把多个相关 token 或反复测试次数当作独立样本。最高 checkpoint 是事后选择，缺少逐题记录时不能补造配对检验。

## 完成审计的实际范围

[audit_run](../src/mirroropd/runtime/audit.py)核对后端退出码、冻结源码身份、Job/config 身份、run 身份、预期更新坐标、算法及 loss_kind、有限优化统计、完整 outer 边界与 rollout 权重版本，并重算每轮逐题结果以对照摘要。fresh-window 检查使用已记录 `student_anchor_kl/rms`；关闭该诊断时，当前代码不会从其他证据独立重建这一数值。

只有这些检查通过才生成 `passed=true`。它证明记录满足实现的完成条件，不证明数学命题、算法优越性或运行中没有未记录故障。`prepared` 和退出码 0 单独均不代表完成训练。状态与失败处理见[运行与复现](运行与复现.md)。
